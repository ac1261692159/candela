# PRD：数据质量页的信息架构与自解释（phase: clklog-data-quality-ops-ia-v1）

> 上游：`docs/product/prd-clklog-data-quality-ops-v1.md`（对拍可信化/闭环/灵敏度，AC-1~AC-12）。
> 本 phase 只改「放在哪、怎么讲清楚」，不动对拍能力本身。

## 阶段目标与范围

用户反馈两件事，本 phase 一并落地：

1. **数据质量从「数据管理」组迁到「运维」组**（信息架构纠正）。
   - 路由：`/sa/meta/quality` → `/sa/ops/quality`；旧路径保留跳转（书签/外部链接不 404）。
   - 菜单：「运维」组末尾新增「数据质量」；从「数据管理」组移除。
   - 权限：**页面入口** `meta.view` → `ops.runtime.access`（与「数据运维」同权，仅平台超管）；
     接口路径与接口权限**都不变**（后者属 rbac-v3 既定边界，见设计 §3）。
2. **页面增加自解释说明区**：说明「这个页面在做什么、术语是什么、结果怎么读、谁该做什么」，
   默认展开可收起，13 语言齐全。

### 为什么放到运维层（结论与理由）

| 理由 | 证据 |
|---|---|
| 讲的是**数据链路可靠性**，不是埋点定义 | 对拍对象是 `sa_events` vs `log_analysis`（ingestor 丢数/停转/重复），与元事件/属性/虚拟事件无关 |
| **受众与权限本就错位** | 页内「对拍设置」写入已是「仅平台超管」（`ops.runtime.access` + `isAdmin`），而入口挂在分析师可见的「数据管理」组 |
| 与「数据运维」是**同一闭环的上下游** | 清理/设 TTL 的前置条件是「存在通过且新鲜的快照」（R2-3）；两页共用同一快照与 `stale_level`；数据运维页里已有「前往数据质量页」跳转 |
| 与「运维」组其余项同域 | 慢 SQL / 服务器状态 / 监控告警 / 数据运维 都是平台可靠性职责 |

**代价（显式记录）**：迁移后分析师不再能看到该页（原来凭 `meta.view` 可见）。
理由：结论已由「数据运维」页的健康卡片承载（同源同新鲜度），分析师需要的是业务数据而非链路对账细节；
若将来要放开，应做成「只读视图 + 白名单」，属独立 phase，不在本次范围。

## 验收标准

| 编号 | 判据 | 核对方式 |
|---|---|---|
| IA-AC1 | 侧栏「运维」组出现「数据质量」，且「数据管理」组不再有它 | 浏览器实测 + `main-layout-menu.spec` 断言 |
| IA-AC2 | `/sa/ops/quality` 打开展示与旧页一致的内容（含配置行、事件级差异、发现日志） | 浏览器实测 |
| IA-AC3 | `/sa/meta/quality` 自动跳转到 `/sa/ops/quality`（无 404、无白屏） | 浏览器实测 + 路由 spec |
| IA-AC4 | 页面权限为 `ops.runtime.access`：非超管不可见入口、直达 URL 被拦；接口权限不变（`meta.view`，由既有 spec 锁定） | 路由配置 + 浏览器实测（超管账号）+ `meta-picker-permission.spec` 保持通过 |
| IA-AC5 | 说明区可展开/收起，含 4 段（做什么 / 术语 / 怎么读 / 谁该做什么），13 语言无源语言残留 | 浏览器实测 + `i18n_check.py` + 单测 |
| IA-AC6 | i18n 命名空间迁移干净：`ops.quality.*` 有全部 92+ 键、`meta.quality.*` 无残留；键集 13 语言一致 | `i18n_check.py` |
| IA-AC7 | 前端全量单测与 `tsc`、`arch_ratchet` 通过；发版后线上实测 | 本地门禁 + 线上核验 |

## 非目标

- 不改对拍算法、阈值默认值、前置对拍规则、清理/登记逻辑。
- **不改后端接口路径**（仍是 `/sa/api/meta/quality/*`）：脚本（`scripts/reconcile.sh`）、AI 工具与
  历史引用都指向它；改路径属独立契约变更。
- 不删除 `meta` 命名空间的其余子树（只迁 `quality` 子树）。
- 不做角色细化（如「分析师只读」）、不做页面视觉重设计。
- 不改「数据运维」页的既有结构（只更新跳转链接）。

## 依赖与授权

无外部依赖；不触红线（纯前端 IA + 文案，后端零改动）。
