## 1. 阶段目标与范围

v1 交付了平台时区与逐查询时区。本期把「时区随人走」闭环：

| 模块 | 本次做什么 |
|------|------------|
| 用户级时区偏好 | `SaUser.timezone`（可空 IANA 名）；个人设置加「显示时区」；`PUT /auth/preferences` 支持 `timezone`；login/me 下发 |
| 项目级时区 | `SaProject.timezone`（可空）；管理 API（`PUT sa/api/iam/ops/projects/:name/timezone`，超管）；查询与落库口径随之 |
| 通知按收件人时区 | `AlertContact.timezone`（可空）；告警触发/恢复时间按联系人时区渲染（同「按收件人语言」模式）；联系人编辑面可设 |

时区解析链（恒定优先级）：

```
展示（查询）时区 = time_range.timezone（卡片/面板显式）
               ?? 用户偏好 timezone
               ?? 项目时区
               ?? 平台时区（analytics.timezone，默认 Asia/Shanghai）
落库日历（stat_date） = 项目时区 ?? 平台时区
告警窗口（指标/留存求值窗） = 项目时区 ?? 平台时区
通知时间渲染 = 联系人时区 ?? 项目时区 ?? 平台时区
```

全部字段可空：空 = 跟随上级，行为与 v1 完全一致（零变化兼容）。

## 2. 用户流程

1. **个人偏好**：个人设置新增「显示时区」（IANA 选择器，带 GMT 偏移，默认「跟随项目/平台」）。设置后：时间面板默认时区、管理面时间渲染、查询 `time_range` 缺省口径全部按它。
2. **面板覆盖**：任何分析页时间面板仍可临时切时区（v1），随卡片持久化——显式选择永远压过偏好。
3. **项目时区（超管）**：管理 API 为某项目设定时区后：该项目的落库 `stat_date` 切日、预计算（分群/标签）计算日、告警求值窗口、成员未设偏好时的默认展示，全部按项目日历。已知限制见 §5-6。
4. **通知**：联系人资料（existing 语言同位）增加时区；触发/恢复通知时间按其渲染。未设 = 项目/平台口径，与现行一致。

## 3. 验收标准

- [ ] **SC-1 用户偏好**：保存 `Pacific/Honolulu` 后 `me` 下发一致；不带 timezone 的事件/漏斗/留存/SQL 查询按用户时区解析「今天」与粒度桶；清掉偏好恢复项目/平台口径。
- [ ] **SC-2 项目时区**：设 `America/New_York` 后，该项目探针事件的 `sa_events.stat_date` 按纽约日历切日（UTC 16-20 点段的上海次日事件落到纽约当天）；该项目（无偏好用户）查询默认日历为纽约；**其他项目不受影响**。
- [ ] **SC-3 通知按收件人时区**：同一触发，联系人 A 设 UTC、B 不设（平台上海）→ 两份通知的时间文本相差 8 小时；语言渲染不受时区字段影响（既有 i18n 行为保持）。
- [ ] **SC-4 零变化**：全部字段为空时，查询 SQL 形态、落库形态、通知文本与 v1 发版后逐字节一致（恒等路径 golden 全绿）。
- [ ] **SC-5 偏好校验**：非法时区值（偏好/项目/联系人三处）均 400/拒绝 + 错误码契约；前端 Profile 保存成功路径。
- [ ] **SC-6 门禁**：单测、`arch_ratchet`、`i18n_check`、冒烟（`smoke-timezone-v1.py` 全过、AS 套件全过 + 本 phase 新用例）全绿。

## 4. 口径修正声明

1. 项目设置异时区后，**该项目新增落库的 `stat_date`** 按项目日历（与 v1 的平台日历不同属一条事件源可能跨日界切换归属）；**历史行不追溯**。这就是「项目时区=部署/创建期决定」的通行口径（参考神策）。
2. 分群/标签**计算日**改随项目时区（v1 为平台时区）——项目未设时无变化；设了 = 修正到业务直觉口径。

## 5. 非目标

1. 项目时区的**界面设置页**（本期仅管理 API；UI 并入后续 RBAC v2 项目设置页 phase 一起做）。
2. 世界地图/多时区对比视图、「按时段 0-23 时」筛选、事件级 zone_offset 结算（epoch 模型仍不需要）。
3. 质量对拍（log_analysis vs sa_events）改按项目日历（其对拍口径仍 CH 服务端日历，已知限制：项目异时区时页面当日计数可能边界错位；单独 phase 处理）。
4. 通知里除「触发/恢复时间」以外的历时类文本（重复间隔/静默时长为相对量，玩转时区无意义）。
5. 存量卡片/DSL 的批量迁移（空字段即新链兜底，无需迁移）。
