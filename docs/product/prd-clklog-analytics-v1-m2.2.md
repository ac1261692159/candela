# PRD：ClkLog 分析平台 v1 — M2.2 埋点管理进阶

## 1. 阶段目标与范围（门禁要素①）

在 M2.1 基础上继续补齐埋点管理的治理与定义能力，使数据分析师和埋点研发能：

1. **更灵活地定义虚拟事件**：支持多个来源事件（逻辑 OR）+ 全局事件属性筛选。
2. **统一治理事件属性**：在独立面板查看跨事件的全部属性，补充备注，查看关联事件数与数据类型分布。
3. **补充事件备注**：所有事件（上报/虚拟/预置）均可填写可编辑的备注，用于埋点说明、 owner 交接、使用规范。
4. **直接编辑事件**：事件列表/详情中可直接修改事件显示名、状态、负责人、备注等基本信息。

## 2. 验收标准（门禁要素②）

| 编号 | 验收项 | 判定标准 |
|------|--------|---------|
| M2.2-A1 | 虚拟事件多事件 OR | 创建/编辑虚拟事件时可选择 1~N 个来源事件；规则文案为「以下任一事件被触发，即该虚拟事件被触发」 |
| M2.2-A2 | 虚拟事件全局筛选 | 虚拟事件定义支持添加全局事件属性筛选条件；条件作用于所有来源事件 |
| M2.2-A3 | 虚拟事件在分析中可用 | 事件分析选择虚拟事件后，SQL 生成器自动展开为 `(event IN (...)) AND (global_filters)` |
| M2.2-A4 | 事件备注 | 元事件表单/抽屉中新增「备注」字段；支持 0~500 字；保存后列表/详情可见 |
| M2.2-A5 | 事件属性面板 | 新增 `/sa/meta/event-attributes` 页面，展示项目下全部事件属性；列：属性标识、显示名、数据类型、关联事件数、备注、状态、更新时间 |
| M2.2-A6 | 属性备注可编辑 | 列表只展示备注文字。改备注在详情抽屉，点「保存」落库（见 `prd-clklog-analytics-meta-detail-v1.md` MD-1~MD-3）。保存后该属性在所有事件中的备注一致（全局） |
| M2.2-A7 | 属性数据类型筛选 | 事件属性面板支持按数据类型筛选：数值、文本、时间、布尔、列表、对象、对象组 |
| M2.2-A8 | 关联事件数 | 事件属性面板实时/近实时展示每个属性关联的事件数量；点击数字或「详情」打开关联事件列表 |
| M2.2-A9 | 事件可编辑 | 事件列表/详情支持修改显示名、状态、负责人、备注；保存后列表即时刷新 |

## 3. 非目标（门禁要素③）

- 不做属性的跨项目复用与标准化映射。
- 不做属性值级治理（如枚举值清洗、空值填充）。
- 不做虚拟事件的嵌套（虚拟事件不能再作为另一个虚拟事件的来源事件）。
- 不做用户属性面板（M4 之后随画像统一规划）。
- 不改 ClkLog 社区版代码与表结构。

## 5. 用户界面

### 5.1 创建/编辑虚拟事件

- **规则定义** 区域：
  - 事件选择：已选事件以 tag 展示，每个 tag 可删除；下方「添加事件」按钮打开事件选择器。
  - 事件之间用「或」视觉连接。
  - 全局筛选：标题「全局筛选」；「添加筛选条件」按钮；筛选条件与事件分析筛选 UX 一致。
- **基本信息** 区域：事件名（`ve_` 前缀）、显示名、备注、状态。

### 5.2 事件列表

- 操作列增加「编辑」图标。
- 事件名列 hover 时展示备注摘要（最多一行）。
- 关键词搜索提示：「搜索事件名、显示名、备注」。
- 「状态」「事件类型」「可用状态」「数据状态」「连接状态」列标题右侧显示筛选图标；点击弹出该列的去重值下拉，选择后即时过滤列表。
- 「可用状态」「数据状态」「连接状态」列标题右侧增加问号图标；hover 时 Tooltip 展示：
  - 可用状态：`可用=有数据且可见；无数据=近7天无数据；已隐藏=被隐藏/删除；已废弃=待确认或已废弃`
  - 数据状态：`正常=昨天有数据；昨日无数据=近7天有数据但昨天无数据；近期无数据=近7天无数据`
  - 连接状态：`自动接入=上报事件；虚拟来源=来源xxx；预置=系统预置事件`

### 5.3 事件属性面板

- 顶部：数据类型多选筛选、关键词搜索、状态筛选（可选）。
- 表格列：
  - 属性标识（prop_key）
  - 显示名
  - 数据类型（标签）
  - 关联事件数（可点击）
  - 状态
  - 备注（只读文字；空为 —）
  - 更新时间
  - 操作（详情）
- 点击行、关联事件数或「详情」打开属性详情抽屉。

### 5.4 属性详情抽屉

- 基本信息：属性标识（只读）、显示名、全局备注、全局数据类型。改完点「保存」才写入；关闭抽屉不保存。
- 关联事件列表：事件名、该事件下的显示名、数据类型、状态。

## 6. 依赖与风险

| 依赖 | 状态 | 说明 |
|------|------|------|
| M2.1 虚拟属性与属性解析器 | 已完成 | 全局筛选与虚拟事件展开可复用 `FilterEditor` 与 `AttributeResolverService` |
| M2 事件分析 SQL 生成器 | 已完成 | 需要在 `event-sql-generator.service.ts` 中支持虚拟事件展开 |
| 数据类型扩展 | 新增 | 需要同步更新 Prisma schema、前端选项、 ingestor 发现逻辑 |

| 风险 | 影响 | 对策 |
|------|------|------|
| 同一 `prop_key` 在不同事件中数据类型不一致 | 全局属性面板类型显示歧义 | 默认展示出现次数最多的类型；详情抽屉展示分布；允许用户手动指定全局类型 |
| 虚拟事件全局筛选嵌套过深 | SQL 复杂、性能下降 | 限制全局筛选最多 5 组条件；复杂场景引导用户走虚拟属性 + 物化 |
| 事件备注搜索导致列表接口变慢 | 列表查询性能下降 | 为 `meta_event.remark` 添加全文索引或在搜索时仅对前 100 条命中 |

## 7. 后续衔接

M2.2 完成后，M3 漏斗 / M4 留存可直接复用：
- 虚拟事件作为漏斗步骤/起始事件。
- 事件属性面板作为属性治理入口。
- 事件备注作为埋点文档的一部分。

用户分群与维度表继续放到 M4 之后单独规划。
