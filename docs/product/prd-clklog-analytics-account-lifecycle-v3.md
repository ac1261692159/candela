# PRD：账号生命周期 v3（成员有效期 / 休眠账号标记 / 会话管理）

> phase: clklog-analytics-account-lifecycle-v3
> 版本：v1.0（2026-09-18）｜ 上游：`research-clklog-analytics-member-lifecycle.md` §5 第三段、v1/v2 PRD 非目标释放项
> 下游：`docs/architecture/clklog-analytics-design-account-lifecycle-v3.md`
> 本文档是「账号生命周期第三段」的**产品层**权威。

---

## 1. 背景与问题

外部协作账号（客户/供应商）进入项目后永不失效、没有到期收口；管理员看不出来谁已经 90 天没登录；用户无法查看和踢掉自己的在线会话，管理员也无法紧急下线某账号的某台设备。对标（research §2.1 GitLab：access expiration / dormant deactivation / active sessions）均为平台基础能力。

## 2. 阶段目标与范围（门禁要素①）

1. **成员有效期**：项目成员（`SaProjectMember`）可设到期时间；到期后该**直接成员资格失效**（失去直接角色，组内角色不受影响），不再计入权限；成员页显示到期标记，可续约、可提前停用。
2. **邀请带有效期（可选）**：创建项目邀请时可附带"入会后成员有效期"。
3. **休眠账号标记**：用户管理页对 `last_login_at` ≥90 天或从未登录且创建 ≥90 天的账号显示「休眠」标记（私有部署**不自动禁用**，由超管人工决定）。
4. **会话管理**：用户个人页可查看自己的在线会话并逐条/全部登出；用户管理页管理员可查看任意用户的会话并吊销（不可吊销自己当前会话）。

## 3. 验收标准（门禁要素②）

- [ ] **AL3-1**：成员设置有效期后，到期时刻起该成员的**直接角色**不再生效（其余来源角色不受影响）；有效期内的行为不变。
- [ ] **AL3-2**：创建/编辑成员与项目邀请均可设/改/清除有效期；成员列表显示「N 天后到期」或「已到期」；已到期成员可一键续约（重设有效期）或删除。
- [ ] **AL3-3**：owner 角色不允许设有效期（owner 只有一名，到期会产生无主项目）。
- [ ] **AL3-4**：休眠标记符合 §5.3 口径；禁用休眠账号沿用既有禁用流程（会话即时吊销）。
- [ ] **AL3-5**：个人页会话列表出现当前会话（标记"本设备"）；登出某会话后该 token 立即 401；「退出全部其他设备」保留当前会话。
- [ ] **AL3-6**：管理员查看任意用户会话、逐条吊销；不能吊销自己当前会话；吊销动作落审计。
- [ ] **AL3-7**：有效期与吊销相关动作全部落 `auth_` 审计；`i18n_check`/`i18n_scan`/`arch_ratchet` 通过；空环境测试全绿。

## 4. 非目标（门禁要素③）

- 不自动禁用/回收休眠账号（仅标记；私有部署由超管人工处置，避免误判）。
- 不做账号级有效期（本次只做**项目成员资格**有效期）；不做 pending approval、TOTP、登录验证码。
- 不做成员组的有效期（组是管理集合，直接随成员删除）。
- 不做基于 IP/UA 的会话指纹识别（本期会话行只含创建/过期时间与本设备标记）。

---

## 5. 产品规则

### 5.1 成员有效期语义

- 字段：`SaProjectMember.expires_at`（可空，空 = 永久）。
- 生效点：所有权限解析读取成员关系的入口；**到期行 = 直接角色失效**，组内角色与 analysis_admin 授权不受影响（权限求并集的既有规则自然生效）。
- owner（`project_owner`）不可设有效期；将 owner 转其他角色后（走 assignOwner 流程）才可设。
- 到期行不自动删除，成员页可续约。

### 5.2 邀请有效期

邀请表单新增可选「成员有效期」：被邀请人入会时写入成员行 `expires_at`；不填 = 永久。邀请链接自身的 7 天有效期不变。

### 5.3 休眠口径

`last_login_at < now-90d`，或（`last_login_at IS NULL` 且 `created_at < now-90d`）。用户管理列表打「休眠」Tag；其余行为不变。

### 5.4 会话管理

- `SaUserToken` 即会话实体：列表字段 = 创建时间、过期时间、是否当前会话。
- 个人：Profile 新卡「登录设备」；本设备置顶不可吊销；其余可逐条登出或全部登出（保留本设备）。
- 管理员：用户管理行操作加「会话」抽屉，逐条吊销或全部登出（等价于禁用+启用的副作用但只有吊销）；不可吊销自己当前会话；全部吊销与自己改密同语义。

### 5.5 审计（沿用 auth_ 通道）

| action | 时机 |
|--------|------|
| `auth_member_expiry` | 设置/修改/清除成员有效期（detail: member_id, project, expires_at） |
| `auth_session_revoke` | 吊销会话（detail: user_id, self/admin, 数量或 token 前缀哈希） |
| `auth_invite_create` | detail 增加 member_expires_at（v2 动作的字段扩展） |

## 增补 v3.1（2026-09-18）：账号域 UX 缝合（不做页面合并）

**背景**：评估「用户管理与成员管理是否合并」的结论为**不合并**（操作者/实体/审计半径不同，两权限码有意分层），但四处"假分开"需要缝合：

1. **demo 填充搬家**：成员页「填充演示成员」（ops.user.manage，本质是建号）移到「设置 → 用户管理」页，建号同时把演示账号挂到当前项目（行为不变）。
2. **建号顺带入会**：用户管理创建账号弹窗新增选填「加入项目 + 角色」（analyst/member/external）；勾选后创建账号成功立即向该项目添加成员（两步合并）；添加失败的账号保留并提示补入（不全量回滚）。
3. **项目足迹**：用户管理「会话」抽屉改双 Tab——会话 / 项目足迹（该用户各项目角色、有效期、所属成员组，只读）。新端点 `GET /iam/users/:id/footprint`（ops.user.manage）。
4. **项目级审计**：审计接口支持 `project` 过滤（服务端按 detail.project 筛近 200 条 auth_ 行）；成员页新增「项目操作审计」区，权限放宽为 `ops.user.manage` 或 `iam.member.view`（项目管理员自证操作轨迹）。

**验收（追加）**：
- [ ] UX-1：demo 按钮不再出现在成员页；用户管理可一键填充演示成员。
- [ ] UX-2：建号勾选入会后 `iam/members` 立即可见该成员；添加失败时提示部分成功且账号保留。
- [ ] UX-3：足迹 Tab 列出成员关系与组（含已到期标记）。
- [ ] UX-4：成员页审计区只显示本项目的 auth_ 行；`iam.member.view` 可读。

## 增补 v3.2（2026-09-18）：分析管理员入会修正 + 邀请式建号 + 告警邮件共用平台通道

1. **Bug 修正（UX-2 缺陷）**：建号并入会的角色下拉漏了 `analysis_admin`（成员管理的既有可授角色）；修正为与成员管理一致的四角色（analysis_admin/analyst/member/external）。
2. **邀请式建号（第三种建号方式）**：用户管理创建弹窗新增「发送邀请邮件（注册链接）」：免填用户名与密码、必填邮箱与项目角色，发出 7 天注册链接（走 v2 邀请链路）；受邀人点开自行注册即建号并入会。与「发送设密邮件」的区别：设密邮件面向"管理员已建好账号"的场景，邀请面向"管理员不想代建任何账号信息"的场景。
3. **告警邮件共用平台通道**：告警 email 通道的 SMTP 解析顺序修订为 通道库内配置 > `ALERT_SMTP_*` > **平台邮件通道（`SaAuthMailConfig`/`AUTH_SMTP_*`）**——零重复配置，平台邮件一配全站（找回/设密/邀请/告警）可用。

**验收（追加）**：
- [ ] UX-5：建号并入会可选 analysis_admin 且入会生效。
- [ ] UX-6：邀请式建号发出 7 天链接；受邀人注册落地即入会；弹窗在该模式隐藏用户名/密码输入。
- [x] UX-7：仅配置平台邮件时，告警 email 通道可发送告警邮件。（2026-10-09 生产实测：真实告警邮件与测试邮件均投递成功，见 `docs/project/acceptance-clklog-analytics-platform-mail-fallback-2026-10-09.md`）

## 增补 v3.2 追加（同日）：`meta.view` 角色口径修订

> ⚠️ **本次修订已被 `docs/product/prd-clklog-analytics-rbac-v3.md` 取代（同日验收后）**：授予整个 `meta.view` 的副作用是分析师同时拿到埋点管理 / 数据管理 / Debug / 数据质量与对拍入口，与 RBAC v2 PRD §6.4「分析师无埋点/元数据」冲突。改法换为「新增只读选择器码 + `meta.view` 收回」。本段保留为历史记录，不再作为口径依据。

- 现象：邀请注册的分析师账号在埋点元数据接口 403，事件分析等页面不可用。
- 根因：RBAC v2 目录 meta.view 只授 owner/分析管理员；但元数据选择器是分析页面的基础依赖，口径过窄。
- 修订：meta.view 授分析师（只读；`meta.edit` 仍归管理员档）。member/external 不变。

## 增补 v3.2 修订（2026-10-09）：UX-7 收尾——平台邮件复用要「选得到、建得出」

- 现象：生产已按 UX-7 在「设置 → 用户管理 → 邮件通道」配好 SMTP，但「运维 → 监控告警 → 通道配置」的
  「邮件（SMTP）」仍显示「未启用」；「联系人」新建时通道下拉里的「邮件」是禁用状态，强行调接口被 400
  `alerting.channel.unavailable` 拒绝。
- 根因：v3.2 只改了**发送侧**（SMTP 三级回落的第三级），**可用性判定**（`capabilities()`）与通道列表
  （`list()`）仍只看告警侧自身配置，没有把平台邮件通道算进来——发送链路是通的，用户却被界面与后端校验挡在门外。
- 修订：把平台邮件通道纳入告警 email 通道的**可用性判定与展示**，判定条件与发送侧回落完全一致
  （`enabled && host && from`），避免「显示可用却发不出去」。

**验收（追加）**：
- [x] UX-7R-1：仅配置平台邮件通道（告警侧 `smtp` 既无库内启用行也无 `ALERT_SMTP_*`）时，`channels` 返回的
      `email.available = true` 且 `platform_fallback = true`，`reason` 为 null。
- [x] UX-7R-2：同上条件下 `POST /ops/alerts/contacts`（`kind=email`）成功建联系人（修订前为 400）。
- [x] UX-7R-3：「通道配置 → 邮件（SMTP）」列表项返回 `platform_fallback = true`，界面显示「平台邮件通道」标记
      而非「未启用」，并在展开区给出「使用平台邮件通道发送」的说明。
- [x] UX-7R-4：平台邮件未启用或缺 host/from 时，email 通道回落为不可用，原因文案与今日一致（不得出现可用但无原因）。
- [x] UX-7R-5：告警侧自发配置优先级不变——库内启用行或 `ALERT_SMTP_*` 存在时可用性只看告警侧，`platform_fallback = false`。
- [x] UX-7R-6：`i18n_check` / `i18n_scan --check` / `arch_ratchet` 全绿，新增文案 13 门语言键齐。

**非目标**：
- 不改发送侧回落顺序，不给告警侧加「显式选择使用平台邮件通道」的开关（回落是隐式的）。
- 不做短信通道的平台级复用（平台侧只有 SMTP，无短信凭证）。
- 不改平台邮件通道自身的配置界面、密码存储与语言/时区渲染。
- 不动权限与审计口径。
