# PRD：自定义 SQL 折线图的双 Y 轴（v1）

- phase: `clklog-analytics-sql-dual-axis-v1`
- 帽子：产品（`docs/product/`）
- 对应实现方案：`docs/architecture/clklog-analytics-design-sql-dual-axis-v1.md`
- 上游：`docs/product/prd-clklog-analytics-event-chart-binding-v1.md`（事件侧同类能力，已上线）
- 状态：待评审

---

## 1. 背景

事件分析的折线图已经支持把指标分配到左右两条 Y 轴，并让每条轴按所属指标的单位格式化（`clklog-analytics-event-chart-binding-v1`，已上线）。

自定义 SQL 没有这个能力，但**契约层其实早就打通了**：`ChartConfigV1.options.metric_axis` 在前后端校验器的白名单里、且不按域收窄，SQL 卡现在就能把它存下来——只是渲染时被忽略。所以 SQL 用户遇到量级差异时，除了改 SQL 没有别的办法。

典型情形与事件侧完全一样：

| 指标 | 量级 | 单轴后果 |
|---|---|---|
| 收入金额 | 10⁴ | 正常 |
| 付费人数 | 10² | 被压成贴底直线 |
| 客单价 | 10² | 被压成贴底直线 |

## 2. 目标

1. 自定义 SQL 的**折线图与趋势图**支持把指标分配到左轴 / 右轴。
2. 两条轴**各按所属指标的单位**格式化刻度。
3. 与事件侧行为一致：全部指标都在左轴时不产生第二条轴（既有图表不变）。

## 3. 需求条目

### R1 轴归属可选

「字段设置」里每个指标的单位下拉下方，增加一个轴归属下拉（左轴 / 右轴），缺省左轴。

**验收**：SQL 结果区能对某个指标选「右轴」；选完应用后图表出现第二条轴。

### R2 两条轴各按自己的单位格式化

左轴用左轴第一个指标的单位，右轴用右轴第一个指标的单位；tooltip 仍按每条系列自己的单位。

**验收**：给右轴指标设「百分比」不影响左轴刻度格式；右轴刻度带 %。

### R3 单轴时行为不变

全部指标都在左轴（或没配置过）时，输出仍是**单条轴对象**，图形与改造前一致。

**验收**：未配置 `metric_axis` 的既有 SQL 卡，图表与改造前逐像素一致（回归基线）。

### R4 右轴刻度不被裁切

出现第二条轴时右边距要放宽，否则右轴刻度标签会被容器切掉。

**验收**：双轴时右轴刻度完整可见。

### R5 只在支持双轴的图型上暴露该控件

本期只做**折线图与趋势图**。柱状 / 条形 / 饼图 / 数值卡上不显示轴归属下拉——避免出现「能设但不生效」的控件。

**验收**：切到柱状图时字段面板里没有轴归属控件。

## 4. 交互

「字段设置 → 指标」区，每个指标原先是：

```
收入金额 单位   [数值 ▾]
```

现在变成：

```
收入金额 单位   [数值 ▾]
               [左轴 ▾]
```

与事件侧的字段面板**形态一致**（同一套控件、同一套文案复用）。

## 5. 非目标

1. **不做柱状 / 条形 / 饼图 / 数值卡的轴归属**。本期只覆盖折线图与趋势图；其他图型连控件都不显示。
2. **不做量级差异自动建议**。事件侧那条建议条依赖 `features/event-chart/axis-suggest.ts`，SQL 侧要用得先把它迁到中性位置并拆 `features/visualization/`（该目录生产文件数已越 80% 线）。单独排期。
3. **不改事件侧任何行为**。
4. **不改查询**。轴归属是纯展示层，不影响 SQL、不触发重查、不写库（要用户保存卡片才落库）。
5. **不引入第三、第四条轴**。

## 6. 术语

| 术语 | 含义 |
|---|---|
| 轴归属 | 某指标画在左轴还是右轴（`options.metric_axis`） |
| 折线族 | 折线图与趋势图——本期支持的两种图型 |
