# PRD：数据质量 × 数据运维 闭环（对拍可信化 + 保留策略统一）

- `phase: clklog-data-quality-ops-v1`
- 关联：调研与实测证据 `research-clklog-data-quality-ops-v1.md`（本 PRD 的事实基础）、实现契约 `docs/architecture/clklog-analytics-design-data-quality-ops-v1.md`
- 上游：`prd-clklog-analytics-v1-data-governance.md`（对拍与清洗）、`prd-clklog-analytics-data-management-v1.md`（存储盘点 / 清理 / TTL）
- 状态：**待实施**（实施前须先落本 PRD 与配套设计，按 AGENTS.md 门禁）

## 1. 背景（一句话版）

对拍机制能跑（低量日 119=119、差异日正确 ALERT），但**作为监控当前无效**：从未定时、结论过期 17 天仍显示「正常」、阈值实际是 10%（设计写 0.1%）导致每天 1.1~1.4% 的稳定偏差永不告警；同时社区版 `log_analysis` 与 19 张聚合表**没有任何保留策略**，而清理执行与 TTL 在生产**从未执行过**。数据质量与数据运维之间目前只有「运维页复用对拍快照」这一处耦合，清理与对拍完全没连线。

## 2. 目标与范围

### R1（P0，1~2 天）：让现有结论可信

| 编号 | 需求 | 说明 |
|---|---|---|
| R1-1 | 对拍**自动定时** | 服务端低峰期每日一次（默认 03:30 平台时区）、默认对拍**昨日单日**、写快照 + 报告落盘；只在 server 进程跑 |
| R1-2 | 结论**过期可见** | 快照 >24h 标黄、>72h 标红；**数据质量页与数据运维页「健康」同步**；过期时页面不再显示「数据一致性正常」而显示「结论已过期，需重新对拍」 |
| R1-3 | 对拍失败**走告警** | 连续失败或偏差超阈 → 复用既有飞书通道（`alert_*` 域的通知栈），含规则名、范围、偏差、报告路径 |
| R1-4 | 阈值**口径统一** | 设计 / 实现 / 页面三处同源（单一常量 + 页面显示百分比）；本期**只统一不收紧**（收紧放 R3） |
| R1-5 | 快照**唯一写入方** | 收敛到一处（清掉 `DataMgmtService.saveReconcileSnapshot` 死代码） |

### R2（P1，约 1 周）：把质量与运维闭环

| 编号 | 需求 | 说明 |
|---|---|---|
| R2-1 | **保留策略总览** | 一张表列出每张表的：预期保留（策略登记）× 实际保留（TTL/分区）× 对拍可信区间；`sa 540 天` 与 `raw 无 TTL` 的错配必须被高亮 |
| R2-2 | **对拍可信区间** | 对拍范围自动收敛到「两侧保留期的小者 ∩ 上限」；超出部分在报告里标注「已超保留期，不比对」而不是计为差异 |
| R2-3 | **清理前置对拍** | 执行 DROP PARTITION / 设置 TTL 前，必须存在覆盖该范围的**通过**快照（且快照在 N 天内，默认 7 天），否则拒绝执行并给出原因 |
| R2-4 | **清理区间登记** | 清理成功后登记「已清理区间」；对拍遇到已登记区间时标注「已清理」而非 ALERT |
| R2-5 | **社区版保留策略**（需用户授权） | 为 `clklog.log_analysis` 与 19 张聚合表设 TTL（建议 90/180 天，逐个确认）；变更前在独立测试环境演练 |
| R2-6 | 脏日期分区清理 | 2019/2023/2027 的测试日期分区（两表）清理或加入对拍忽略清单 |

### R3（P2，2~3 周）：让对拍真正有灵敏度

| 编号 | 需求 | 说明 |
|---|---|---|
| R3-1 | **口径白皮书** | 解释清 1.1~1.4% 的日常差异与少数事件的 +57%~+562%（空 event 过滤、两侧去重语义、社区侧丢数/合并）；结论落文档，可复算 |
| R3-2 | **双向对拍** | 行数之外增加抽样行内容一致率与上游计数对账，能区分「我们重复」与「基准侧少记」 |
| R3-3 | **阈值收紧** | 口径对齐后默认阈值降到 0.1~0.5%，支持按事件设阈值与忽略清单；人工注入 1% 缺口能被发现 |
| R3-4 | 事件级差异进快照 | 页面不点「开始对拍」也能看到最近一次的事件级 Top 差异与发现日志 |
| R3-5 | 低峰期大范围专项 | 分批 + 限内存 + 断点续跑，支持对账 30 天且不 OOM |

## 3. 界面规格

### 3.1 数据质量页

- 顶部状态区：`正常` / **`结论过期（黄）`** / **`结论过期（红）`** / `对拍失败`，并显示「上次对拍 …（N 小时前）」；过期时不再显示「数据一致性正常」。
- 新增「对拍设置」入口（超管）：开关定时对拍、执行时刻、阈值（百分比，默认沿用现值）、忽略事件清单、快照有效期（24h/72h）。
- 每日总量对拍表：新增「是否已清理」列（来自清理登记）与「超保留期不比对」标注。
- 事件级差异：从快照直读（含 Top N 与「仅一侧存在」分组），不再依赖重新对拍。
- 元数据发现变化：直读 `metadiscoverylog`（含分页与时间筛选），不再受快照限制。

### 3.2 数据运维页

- 「健康」卡片与质量页同源同状态（含过期标红）。
- 新增「保留策略」区：每表的预期保留（策略登记）× 实际 TTL × 状态（`已设置` / **`未设置（风险）`** / `偏离策略`）；一行提示「对拍可信区间：近 N 天」。
- 清理预演结果里显示：该范围最近一次对拍结论（通过/失败/无记录），执行按钮在前置检查未通过时禁用并说明原因。
- 动作审计新增两类：`reconcile_run`（自动/手动，含范围、偏差、耗时、报告路径）、`cleanup_ledger`（清理区间登记）。

## 4. 验收标准

| # | 断言 |
|---|---|
| AC-1 | 连续 2 天：`ops_reconcile_snapshot` 出现当日低峰自动写入的记录（`ran_at` 在配置时刻 ±10 分钟内），报告文件存在 |
| AC-2 | 把某条快照 `ran_at` 改到 30 小时前：质量页与数据运维页**同时**显示「结论过期（黄）」且不再显示「数据一致性正常」；改到 80 小时前显示「（红）」 |
| AC-3 | 制造一次对拍失败（阈值设为 0）→ 5 分钟内收到飞书告警，内容含范围/偏差/报告路径 |
| AC-4 | 设计文档、代码常量、页面显示三处的阈值语义与默认值一致（单测断言常量与页面 props 同源） |
| AC-5 | `grep saveReconcileSnapshot` 只剩一处写入方（或该函数已删除），且快照写入路径唯一 |
| AC-6 | 保留策略区能标出 `clklog.log_analysis` 为「未设置（风险）」，`clklog_sa.sa_events` 显示 540 天 TTL，且给出对拍可信区间数值 |
| AC-7 | 对拍范围跨越两侧保留期小者之外的日期时，报告把这些日期标为「超保留期不比对」，不计入 `alert_days` |
| AC-8 | 在未通过对拍（或无快照）的表上尝试执行清理 → 被拒绝，返回原因；补一次通过的对拍后可执行（测试环境验证） |
| AC-9 | 执行一次清理（测试环境 DROP PARTITION）后：清理登记表出现该区间；随后对拍覆盖该区间时标为「已清理」而非 ALERT |
| AC-10 | 社区版表 TTL 生效后，连续 2 天 `system.parts` 不再新增过期分区（或磁盘增长趋平），且审计留痕 |
| AC-11 | 事件级差异与发现日志在**不点「开始对拍」**的情况下可见（来自快照/库表） |
| AC-12 | 对拍默认单日任务的 CH 容器内存峰值不超过设定上限（记录实测峰值），全程无 OOM |

## 5. 非目标

- 不把社区版 `log_analysis` 当唯一真值；对拍定位为「发现方向性异常」。
- 不做全量行级对拍（12 GiB 单机 + 两次 OOM 历史）。
- 不改对拍 SQL 的只读性质（全部 SELECT）；不写社区版库。
- 不在本期做敏感数据清洗（删除/掩码）的界面化——它属另一条线（`prd-clklog-analytics-v1-data-governance.md` §5），本期只保证「清理前后可对拍」。
- 不做自动清理（清理仍须人工确认 + 二次输入表名）。

## 6. 依赖与授权

| 项 | 需要谁 | 说明 |
|---|---|---|
| 社区版表 TTL（R2-5） | **用户明确授权** | 涉及社区版表结构变更（红线 1 的例外须显式批准），先在独立测试环境（`scripts/standalone-test-env/`）演练 |
| 飞书告警通道（R1-3） | 已具备 | 复用监控告警域既有通道与联系人 |
| 定时任务运行位置（R1-1） | 架构决定 | 服务端进程内定时（与卡片缓存 / 保留清理同一模式），仅 `background_workers` 进程执行 |

## 7. 分期与交付顺序

1. **R1**（可独立发版，零风险）：定时 + 过期可见 + 阈值口径统一 + 死代码收敛。
2. **R2**（含一次需授权的社区版变更）：保留策略总览 → 前置对拍 → 清理登记 → 测试环境演练 → 生产 TTL。
3. **R3**：口径白皮书 → 双向对拍 → 阈值收紧 → 快照扩展 → 低峰期专项。
