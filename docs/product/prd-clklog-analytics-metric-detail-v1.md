## 1. 阶段目标与范围（门禁要素①）

「数据管理 → 指标」当前只有**列表 + 删除**：列表能看名字与备注，但看不到指标到底怎么算的，也不能改。指标已经是对外资产（分析里可套用、告警可绑定），只有删没有看/改会让用户只能「删了重建」，而重建会改变 metric_id，**把已有告警绑定悄悄弄断**。

本阶段补齐两件事：

1. **查看**：打开指标详情，看到完整口径（怎么算的）+ 元信息（谁建的、什么时候改的、能否用于告警）。
2. **编辑**：就地改元信息与口径，**保持 metric_id 不变**，因此不影响分析引用与告警绑定。

范围：

- 可编辑：显示名、备注、格式（数字/百分比）；事件指标的「事件 / 计算方法 / 属性」；留存指标的「初始事件 / 回访事件 / 周期 n / 口径 / 队列口径 / 粒度」。
- 不可编辑：指标名（`name`，是资产唯一键）、类型（`kind`，事件/留存口径完全不同）。
- 编辑**不改动**定义里的筛选条件（`filters`）：原值原样保留，页面明示；要调筛选请重新创建指标。

## 2. 验收标准（门禁要素②）

- [x] **M-1**：指标列表每行有「查看」「编辑」「删除」三个入口，显示名可点击直接打开查看。
- [x] **M-2**：查看抽屉展示：显示名、指标名、类型、格式、创建人、创建时间、更新时间、备注，以及**可读的口径摘要**（事件指标：事件 + 计算方法（中文）+ 属性；留存指标：初始事件 → 回访事件 + 周期 + 口径 + 队列 + 粒度），并说明「时间范围不写入指标，套用时以查询为准」。
- [x] **M-3**：编辑模式可改上述字段并保存；保存成功后列表刷新，`updated_at` 变化。
- [x] **M-4**：指标名与类型在编辑模式只读展示，并给出原因（改名/改类型会打断分析与告警引用）。
- [x] **M-5**：保存走 `PUT /sa/api/meta/metrics/:metricId`，服务端仍做定义规范化；校验失败（如事件未选、周期越界）就地显示原因，不静默丢改动。
- [x] **M-6**：编辑保存后，定义里的 `filters` 与 `alias` 等未在表单暴露的字段保持原值不变（前端回传完整定义 + 后端规范化前合并已存定义，两层都有自动化断言）。
- [x] **M-7**：详情页提示「指标被告警引用时，改口径会改变告警判定」，让用户知道影响面。
- [x] **M-8**：前端单测覆盖「摘要可读性」「保存载荷保留未暴露字段」「编辑态与只读态切换」，并纳入 CI。

## 3. 非目标（门禁要素③）

- 不做指标的筛选条件编辑（`filters` 可视化编辑器）——本期保持原值，后续 phase 再评估。
- 不做指标重命名（`name`）与类型转换（事件 ⇄ 留存）。
- 不做指标历史版本 / 变更审计（当前后端未记录指标变更，本期不新增审计表）。
- 不做「指标当前取值」直接展示（求值入口在「运维 → 监控告警 → 新建指标告警 → 测试取值」；项目级求值接口涉及跨模块依赖，另立 phase）。
- 不做指标的图表/趋势页。
