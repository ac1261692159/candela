## A. SQL 分群

> phase: clklog-analytics-sql-cohort-v1

### A.1 阶段目标与范围

在用户分群「新建」增加第三张类型卡 **SQL 分群**。用户写有界只读 SQL，结果必须是**分析主体 ID 一列**；创建后立刻算一次，可开每日定时或只手动刷新。成员仍写入 `sa_cohort_members`，分析筛选/分组与条件分群相同，不另做选择器分类。

时间参数按计算日滚动（对标数数 `${PartDate:…}`），试跑有行数上限。

### A.2 验收标准

- [x] SC-1：新建类型卡出现 SQL 分群；表单为 SQL 编辑器 + 时间参数 + 定时开关 + 显示名/分群名/备注，不是条件句配置器。
- [x] SC-2：试跑与保存计算均走只读账号 + 现有 SQL AST 守卫；禁止 DDL/DML、表函数、跨库、社区版表；强制 `project_name` 与 LIMIT/超时。
- [x] SC-3：结果必须恰好一列主体 ID（列名 `uid` 或第一列当作 `uid`）；多列/无行结构报错。成功后列表人数与分析「用户分群」可用。
- [x] SC-4：定时开则每日按计算日替换时间参数后重算；关则仅创建/编辑/手动刷新。ID/结果分群行为不变。
- [x] SC-5：单测覆盖：非法 SQL 拒绝、结果非单列拒绝、圈人写入成员表后分析 SQL 仍只读 `sa_cohort_members`。棘轮通过。

### A.3 非目标

- 不做 SQL 标签（标签另 phase）。
- 不做分群套分群（SQL 不得读 `sa_cohort_members` / 标签成员表）。
- 不做自定义 SQL 分析的「保存为结果分群」。
- 不放宽 SQL 报告的 AST 黑名单或超时。

## B. 自定义 SQL / 看板上的分群

> phase: clklog-analytics-cohort-sql-dashboard-v1

### B.1 阶段目标与范围

把已算好的用户分群接到 **自定义 SQL 分析** 和 **看板刷新**，查询仍只读成员表。

1. SQL **Builder**：分组/筛选增加「用户分群」分类，语义与事件分析相同（属于/不属于；分组两档）。
2. SQL **手写模式**：数据字典可插入分群成员片段；不把筛选隐形合并进用户 SQL。
3. **看板**：事件/漏斗/留存卡若 DSL 已含分群，刷新保持有效。新增看板级分群筛选，刷新时 AND 到兼容卡片；手写 SQL 卡用表级过滤注入，不改写用户 SELECT 列表。

### B.2 验收标准

- [x] CD-1：Builder 筛选/分组可选已 `ready` 的分群；生成 SQL 为成员 `IN` 子查询，不含条件规则谓词。
- [x] CD-2：手写模式字典有「用户分群」；点击只插入片段，不改已有 WHERE。
- [x] CD-3：看板详情可设 0～1 个分群全局筛选（属于/不属于）；刷新事件/漏斗/留存/Builder SQL 卡时生效；标签卡忽略。
- [x] CD-4：手写 SQL 卡刷新时，对 `sa_events`（及需要时 `sa_user_profiles`）注入与主体表达式一致的成员条件，不包 `SELECT *` 子查询。
- [x] CD-5：分群未 ready 或已删：Builder/分析卡当空集并提示；看板级筛选校验失败则该次刷新报错而非静默全表。棘轮通过。

### B.3 非目标

- 不做看板级多选分群、分群分组（全局筛只要属于/不属于）。
- 不做结果分群从 SQL 分析保存。
- 不做用户标签出现在 SQL/看板（标签另 phase）。
- 不在此期做分析主体切换。

## C. 用户标签

> phase: clklog-analytics-user-tag-v1

### C.1 阶段目标与范围

做出可复用的 **用户标签** 资产：按规则给每个分析主体打一个离散值并预计算，再在事件/漏斗/留存（以及若已交付则 SQL Builder）的筛选/分组里选用。

和分群的差别：分群只回答「在不在」；标签分组按**取值**拆开（可多档），未打标单独一档。

本期只做 **规则标签**（复用分群三种条件句，多条规则按顺序匹配，命中则赋值）。导航放在分析下「用户标签」，或与分群同级入口。选择器增加分类 **用户标签**。

### C.2 验收标准

- [x] UT-1：可创建/编辑/列表/删除规则标签；显示名必填；标签名规则同分群名。保存后立刻计算；失败不可出现在分析选择器。
- [x] UT-2：至少两条规则 + 可选默认值。每条规则条件与条件分群相同（做过/没做过、依次/没依次、用户属性，条件之间且）。先匹配先生效；都未命中则用默认值，无默认值则不写入成员（分组为「未打标」）。
- [x] UT-3：可开每日定时或手动刷新。点人数可预览成员（uid + 标签值），有界。
- [x] UT-4：筛选：标签取值 `等于` / `属于` / `不属于` 给定值列表。分组：按标签值拆列，含「未打标」。查询只读预计算，不即席打标。
- [x] UT-5：选择器分类「用户标签」与「用户分群」并列。单测覆盖规则校验与分析 SQL 引用标签成员表。棘轮通过。

### C.3 非目标

- 不做首末次特征标签、指标分层标签、SQL 标签、标签分层/多值、RFM。
- 不做运营推送、实时标签、血缘。
- 不做用标签再圈分群（标签套分群）。
- 不在此期做分析主体管理（标签主体固定为现网「用户」口径）。

## D. 分析主体管理

> phase: clklog-analytics-analysis-subject-v1

### D.1 阶段目标与范围

分析去重键从写死的「用户」变为可管理的 **分析主体**。预置「用户」= 现网 `if(user_key != '', user_key, distinct_id)`，不可删。可新建主体：来源绑一个事件属性或用户属性（如账户 ID）。

事件/漏斗/留存查询、条件/SQL/ID/结果分群、规则标签的人数与成员，都按当前主体取值去重。分析表单与分群/标签创建页可切换主体。分群/标签资产绑定创建时的主体；分析里只能选**同一主体**的分群/标签。

### D.2 验收标准

- [x] AS-1：管理页列出预置「用户」与自建主体；可新建（来源属性 + 名称）、排序、删除自建（被分群/标签/已存卡片引用则先 409）。
- [x] AS-2：事件/漏斗/留存默认主体为「用户」；切换后人数/转化/留存按该主体 ID 去重。旧卡片无 `subject_id` 视为「用户」。
- [x] AS-3：分群/标签创建时选主体；条件「没做过 / 没依次」仅预置「用户」或用户属性来源的主体可用（事件属性主体禁用，与数数一致）。
- [x] AS-4：分析筛选/分组里的分群与标签，按当前查询主体过滤列表；主体不一致不可选。
- [x] AS-5：主体表达式空值不计入人数。查询仍有 `project_name` + 时间 + LIMIT/超时。棘轮通过。

### D.3 非目标

- 不做设备/会话等系统预置主体（可后续加预置，不在本期发明新 ID 列）。
- 不做多主体同一查询（一次查询一个主体）。
- 不做按主体拆分的实时运营通道。
- 不改社区版表，不把主体值物化进 `log_analysis`。
