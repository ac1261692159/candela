## 1. 阶段目标与范围

把「维表字段」从"只是显示名"升级为**可用的分析维度**：能按维表字段**分组、筛选、聚合**，与数数/神策的「维度表属性」对齐。

| 能力 | v1 | v2 |
|------|:--:|:--:|
| 结果值映射展示（ID → 业务名） | ✅ | 保留 |
| 绑定后为每个非主键字段生成**维度表属性**（`{绑定属性}@{字段}`） | — | ✅ |
| 维度表属性可**筛选 / 分组 / 聚合**（事件 / 漏斗 / 留存） | — | ✅ |
| 维度表属性进入属性选择器（来源标记`数据表`） | — | ✅ |
| 绑定目标含 `#event_name`、`#event_time`（带粒度）并生成属性 | — | ✅ |
| 未命中 / 空值 / 类型对齐的显式语义 | — | ✅ |

## 2. 用户与场景

1. **商品分析**：按 `item_info@quality` 分组看订单量/人数；按 `item_info@resource` 筛选。
2. **事件级维表**：把 `#event_name` 绑到"事件字典表"，用 `#event_name@owner` 按负责人分组，看各团队负责事件的数据量。
3. **运营日历**：把 `#event_time`（日粒度）绑到"活动日历表"，用 `#event_time@campaign` 按活动分组对比效果。

## 3. 功能规格

### 3.1 绑定与属性生成

- 一个绑定 → **该表每个非主键字段生成一个维度表属性**（主键字段不生成，与数数一致）。
- 属性名（DSL 引用名）：`{绑定属性}@{字段名}`，如 `item_info@quality`、`#event_time@campaign`；**显示名可改**。
- 一张表 ≤ 5 个绑定（沿用 v1）；项目内维度表属性 ≤ 500。
- 类型必须匹配：文本主键 ↔ 文本属性/事件名称；数值主键 ↔ 数值属性；布尔主键 ↔ 布尔属性；时间主键 ↔ `#event_time`（普通时间属性 v1 起不支持）。

### 3.2 属性可见性与限制

| 项 | 规则 |
|---|---|
| 属性选择器 | **筛选**并入「事件属性」并标记`数据表`。**分组**单独入口「添加维度分组」，选项形如 `goods_id@商品名称`；结果表头用字段显示名（「商品名称」） |
| 可用位置 | 事件/漏斗/留存的筛选、分组、聚合 |
| 不可用 | 不可物化；不可作分析主体或群体键；不可作虚拟属性表达式的输入；`Scope` 仍是 `event`（不新增枚举） |

### 3.3 查询语义（依实测结论）

| 项 | 语义 |
|---|---|
| 类型对齐 | 两侧同类型比较：文本 trim、数值按数值、布尔按布尔、时间按**粒度格式化文本** |
| 时间与粒度 | `Asia/Shanghai`（与 `stat_date` 口径一致），粒度格式：年/月/日/时/分/秒 |
| 未命中 | 结果为**空值**（子查询无行 → NULL；JSON 缺键 → 字符串 `''`、数值/布尔 `0`，已实测）。`=`、`in` 不命中；「为空/不为空」筛选与空值一致 |
| 展示 | 结果表/图表显示维度值本身；卡片、看板、CSV 导出沿用 v1 的"展示名 + 原始值"策略 |

### 3.4 生效、失效与缓存

- 绑定/解绑/改粒度 → 立即生效，并清该项目查询缓存与相关卡片缓存。
- 数据表删除或绑定解绑 → 属性 `status='invalid'`；引用它的查询**报可读错误**（"属性 xxx 依赖的数据表已失效"），**不静默回退**到原始 JSON 属性。
- 同名重建 → 复用既有 `invalid` 记录并置回 `active`；已有 `active` 同名记录则拒绝。

### 3.5 权限

沿用 `meta.view` / `meta.edit`；维度表属性跟随数据表权限，不新增权限码。

## 5. 非目标

| 非目标 | 原因 |
|---|---|
| 用户属性绑定（用户维度表） | 基底是 `sa_user_profiles`；该路径本身在生产报 missing columns（见 `CODE_HANDOVER.md` 2026-09-14），先修基础再谈扩展 |
| 维表字段作分析主体 / 群体键 | 语义与性能边界未验证 |
| 维表间关联、多跳维度 | 复杂度不成比例 |
| 用户自定义 SQL 直接查维表 | 白名单不放宽 |
| `$` 开头的内置属性作维度键 | `$model`/`$os`/`$app_version` 等**不可**作维度属性：维度属性名契约只允许 `#[a-z]…`（系统字段绑定）与 `[a-zA-Z_]…`；放宽 `$` 会动通用 PROP_KEY 正则，需单独评估（2026-09-15 验收发现，用户确认按现状写入非目标） |
| 字典化 / 预聚合等性能优化 | 先可用，再优化；性能门槛见 A8 |
| 结构变更（加减列）与发布、版本还原、Excel、Open API、定时更新 | 沿用 v1 非目标 |
