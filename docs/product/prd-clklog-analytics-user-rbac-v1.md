# PRD：用户 / 用户组 / 权限体系（RBAC）— P1

> phase: clklog-analytics-user-rbac
> 版本：v1.0（2026-08-28）｜ 上游：`docs/architecture/analytics-extension-plan.md`
> 下游：`docs/architecture/clklog-analytics-design-user-rbac.md`
> 本文档是用户/权限体系的**产品层**权威：用户、登录、角色、资产归属。
>
> **后继**：项目空间五角色 / 成员组 / 数据权限 / 角色说明页见 `prd-clklog-analytics-rbac-v2.md`（`phase: clklog-analytics-rbac-v2`）。P1 仍描述已落地的登录与全局三角色；新授权模型以 v2 为准。

## 1. 阶段目标与范围（门禁要素①）

解决「分析平台谁都能访问」的根本问题：平台此前**无用户体系**，请求仅带 `x-project-name`（项目名），任何知道项目名的人都可访问全部数据。

**P1 目标**（最小可用闭环）：
- 建立用户体系（用户名 + 密码 + 三角色 admin/analyst/viewer）。
- 登录认证（用户名密码 → 签发 token）。
- 资产（看板/卡片/报表）归属到用户，鉴权校验「只能看/操作自己的资产」。
- 前端登录页 + 请求带 token。

**P2（后续）**：用户组 + 组内共享 + 资产移交。
**P3（后续）**：禁用/注销资产交接 + 审计 + 项目身份从认证上下文取。

## 2. 验收标准（门禁要素②）

- [ ] **U-1**：`POST /sa/api/auth/login` 用户名密码正确返回 token，错误返回 401。
- [ ] **U-2**：未携带 token 的请求返回 401；无效/过期 token 返回 401。
- [ ] **U-3**：三角色：admin（管理用户 + 全部资产）、analyst（创建/编辑自己资产）、viewer（只读）。
- [ ] **U-4**：看板/卡片/报表列表仅返回**本人资产**（analyst/viewer）或全部（admin）。
- [ ] **U-5**：非 owner 用户修改/删除他人资产返回 403。
- [ ] **U-6**：前端未登录跳转登录页；登录后请求自动带 token。
- [ ] **U-7**：资产列表显示「归属人」。

## 3. 非目标（门禁要素③）

- 不做用户组、不做组内共享（P2）。
- 不做资产移交、禁用/注销交接、审计（P2/P3）。
- 不做找回密码、邮箱验证、SSO。
- 不做 project 维度隔离改造（仍沿用现有 project 维度，项目身份认证 P3 处理）。
- 不改社区版 ClkLog 用户体系（红线：不侵入社区版）。

## 4. 角色权限矩阵（P1）

| 操作 | admin | analyst | viewer |
|------|-------|---------|--------|
| 登录 | ✅ | ✅ | ✅ |
| 查看自己资产 | ✅ | ✅ | ✅ |
| 创建资产（看板/卡片/报表） | ✅ | ✅ | ❌ |
| 编辑/删除自己资产 | ✅ | ✅ | ❌ |
| 查看全部资产 | ✅ | ❌ | ❌ |
| 管理用户（增删改/禁用） | ✅ | ❌ | ❌ |
| 埋点/属性/数据质量等查看 | ✅ | ✅ | ✅（只读） |

> 埋点管理、事件分析、漏斗、数据质量等「查询类」功能：三角色均可读；「写入类」（新增/编辑埋点、物化、保存卡片）需 analyst+。

---

## 5. 资产归属（P1 范围）

- 新建看板/卡片/报表时，`owner_id` = 当前用户 id。
- 列表/详情接口按 `owner_id == 当前用户` 过滤（admin 豁免）。
- 资产归属字段复用现有 `owner`，语义从「项目名」改为「用户 id」。

---

## 6. 交互与错误提示

| 场景 | 行为 |
|------|------|
| 未登录访问任何页面 | 跳转 `/login` |
| 登录失败 | 「用户名或密码错误」 |
| 访问他人资产 | 403「无权访问该资源」 |
| viewer 尝试创建 | 前端隐藏创建按钮 + 后端 403 |
| token 过期 | 401 → 跳转登录页 |

---

## 7. 初始用户引导

- 首次部署自动创建**默认 admin**（`admin` / 初始密码由部署注入），用于登录后创建其他用户。
- 默认 admin 密码首次登录后**强制修改**（P1 可简化：提示修改）。

---

## 8. 风险与依赖

- 认证引入后，**所有现有接口需接入鉴权**，否则会被 401 拦截导致现有功能不可用（回归风险）。
- token 有效期与刷新机制需明确（P1 用长有效期 token + 可撤销）。
- 依赖：`bcrypt`（密码哈希）、token 存储表。
