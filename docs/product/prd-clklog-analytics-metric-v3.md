# PRD：指标 v3 —— 留存队列范围、指标即卡片数据源 + 三项体验优化

- `phase: clklog-analytics-metric-v3`
- 关联：`docs/architecture/clklog-analytics-design-metric-v3.md`（实现契约）、`prd-clklog-analytics-metric-v2.md`（上一期：九区口径 + 查询时间 + 取值选择）
- 承接 v2 §9 的 P2：留存指标的查询时间（队列范围）、看板卡片直接以指标为数据源

## 1. 背景与问题

v2 上线后用户实测反馈三处体验问题（本期一并修）：

1. **查询时间面板越界**：面板固定 848px 宽，锚点靠近视口右侧时（例如指标抽屉里的控件）整块面板超出浏览器右边界，日历被裁切；面板自身的两列日历在窄容器里也会横向溢出。
2. **数值变换只会乘**：事件分析的「数值变换」只有「乘以系数」，单位换算里常见的 `÷1000`（毫秒→秒）、`+8`（时区补正）、`-1`（去掉测试流量）都表达不了。
3. **指标列表操作列拥挤**：列表右侧「查看 / 编辑 / 删除」三连按钮把表格挤到横向滚动，且删除这种破坏性操作紧贴查看按钮，容易误点。

v2 未做的 P2 两项：

4. **留存指标不能设查询时间**：留存指标的队列范围由周期 `n` 推导（`max(30, n+30)` 天），用户无法按自己的口径调整（例如只看最近 60 天的队列）。
5. **看板卡片不能直接用指标**：指标已能表达「事件 + 完整口径 + 查询时间 + 取值」，但看板卡片仍要重新配一遍 DSL；同一口径在两处维护，容易漂移。

## 2. 目标与范围

| 优先级 | 内容 |
|---|---|
| P0 | 查询时间面板**始终在视口内**：宽度自适应（`min(848, 100vw-40)`）、窄容器下日历改单列、弹层自动避让并限宽 |
| P0 | 数值变换支持**加减乘除**：`× / ÷ + -` + 保留小数位；旧定义（只写 `factor`）行为不变 |
| P0 | 指标列表去掉操作列：点显示名看详情；**编辑左侧放删除**，删除按钮**收进详情抽屉**（带二次确认） |
| P1 | 留存指标可设**队列范围**（查询时间）：只允许相对范围，最小 `n+1` 天、最大 180 天；不设置时沿用现行推导 |
| P1 | 看板卡片新增**指标卡**：以已保存指标为数据源，卡片缓存的刷新走指标求值；支持折线/柱/表格/数值四种视图 |
| P1 | 指标详情抽屉提供**「创建看板卡片」**入口（与删除并排），建好后可在看板工作室里放置 |

## 3. 界面规格

### 3.1 查询时间面板（修复）

- 面板宽度：`min(848px, calc(100vw - 40px))`；`max-width` 同上；不设 `min-width`。
- 窄容器（< 680px）：日历从两列降为一列，预设列改为整行横向排布。
- 弹层：`placement="bottomLeft"`、`arrow={false}`、`autoAdjustOverflow`（antd 默认开启），并设 `overlayStyle.maxWidth = calc(100vw - 24px)`；抽屉/弹窗内使用时挂到 `document.body` 避免被容器裁切。
- 300px 窄侧栏、720px 抽屉、1440px/1280px 视口三种场景下面板都必须完整可见（含「应用」按钮）。

### 3.2 数值变换（四则运算）

- 控件：`[运算: 乘以 / 除以 / 加上 / 减去] [数值] [保留小数位（0-6，可选）]`。
- 语义：先做四则运算，再保留小数位；除以 0 在保存/校验时被拒（400）。
- 兼容：定义里只有 `factor`（等价于「乘以」）时按新语义解释，界面回显为「乘以 N」。
- 文案：口径摘要显示 `÷1000，保留 2 位` / `×0.001` / `+8` / `-1`。
- 生效位置：分析查询（ClickHouse 端聚合后计算）、指标求值（试算与告警）、二者必须一致。

### 3.3 指标列表与详情

- 列表列：显示名（可点，第二行是「查询时间 · 取值」）/ 指标名 / 类型 / 口径 / 备注；**无操作列**。
- 详情抽屉头部：`编辑` 与 `删除` 并排（删除在右，红色，二次确认后删除并关闭抽屉）；查看态与编辑态都可见，编辑态点删除先提示「未保存的修改会丢失」。
- 删除成功后回到列表并刷新。

### 3.4 留存指标的队列范围

- 指标编辑器的留存分支新增「队列范围」（沿用查询时间控件，只允许相对范围）。
- 默认（不设置）= 现行推导 `max(30, n+30)` 天，上限 180 天；设置后必须 ≥ `n+1` 天（否则队列未成熟，校验直接 400 并给出原因）。
- 口径描述与列表摘要显示队列范围（如「队列 最近 90 天」）。

### 3.5 指标卡

- 入口：指标详情抽屉 → `创建看板卡片` → 填卡片名（默认取指标显示名）→ 生成 `type=metric` 的卡片。
- 数据：卡片缓存按指标求值（含日序列），视图支持 折线 / 柱状 / 表格 / 数值；数值视图显示指标值（应用取值选择与数值变换后的结果）。
- 指标口径变更后，卡片在下一个刷新周期自动反映新口径（缓存不落永久副本）。
- 卡片仍受「看板级筛选（分群）」之外：**本期不支持**在看板筛选里对指标卡做分群过滤，界面给出说明。

## 4. 验收标准

| # | 断言 |
|---|---|
| AC-1 | 1440×900 与 1280×720 视口下，指标抽屉里的查询时间面板完整可见（含「应用」按钮），不产生横向滚动 |
| AC-2 | 面板宽度 ≤ 视口宽度 − 40px；日历列数在窄容器下为 1（断言 DOM class 与计算宽度） |
| AC-3 | 数值变换选「除以 1000」保存后：`GET metrics/:id` 返回 `transform={op:'div',value:1000}`；试算值 = 原值 / 1000（允许保留小数位） |
| AC-4 | 旧定义 `transform={factor:0.5}` 仍按「乘以 0.5」生效，且编辑界面回显为「乘以」；保存后写为 `{op:'mul',value:0.5}` |
| AC-5 | 除以 0 → 400；SQL 生成器对 `div` 输出 `(expr) / N`，`add/sub` 输出 `+ N` / `- N`，且都在 `round(..., decimals)` 之内 |
| AC-6 | 指标列表渲染出的表头不含「操作」列；点显示名打开详情抽屉 |
| AC-7 | 详情抽屉查看态有 `编辑` 与 `删除`；删除需二次确认，确认后卡片从列表消失（API 204/ok + 列表刷新） |
| AC-8 | 留存指标设置队列范围「最近 90 天」后，`GET metrics/:id` 返回 `time_range.relative={kind:'recent_n',n:90}`；求值用 90 天队列 |
| AC-9 | 留存队列范围 < n+1 天 → 400（提示原因）；> 180 天 → 400 |
| AC-10 | `POST cards {type:'metric', dsl_json:{metric_id}}` 成功；缓存刷新返回单指标序列（含「阶段汇总」行），卡片能渲染折线与数值 |
| AC-11 | 指标卡在指标口径变更后，下一个刷新周期结果随之变化（用改 value_pick 的方式验证） |
| AC-12 | 指标卡请求分群筛选时不报错，返回未筛选结果并在卡片上标注「指标卡不支持看板分群筛选」 |

## 5. 非目标

- 不做指标卡的**多指标/维度拆分**（一期一张卡一个指标）；
- 不做指标卡的自定义时间范围（跟随指标查询时间，卡片不覆盖）；
- 不做留存指标的**逐日队列曲线**改造（仍按现有留存结果结构展示）；
- 不做查询时间面板的「自然语言输入」；
- 不改动 v2 已定的取值选择集合与告警联动规则。
