# PRD：指标告警重设计 + 告警通知模板

- `phase: clklog-analytics-alerting-v4`
- 帽子：产品
- 上游：`prd-clklog-analytics-alerting-v1.md`、`-v2.md`、`-v3.md`（v2 的「卡片刻度告警」在本期被**取代**）
- 触发：用户实测反馈——「新建分析指标告警」点击即 500（服务不可用）；且告警对象选错了（不应以分析卡片为对象，应关联**数据管理中的指标**）

> 验收记录：`docs/project/acceptance-clklog-analytics-alerting-v4.md`（含端到端取证与遗留项）

---

## 1. 阶段目标与范围（门禁要素①）

本期两条主线：

| 主线 | 解决的问题 | 交付形态 |
|------|-----------|---------|
| **A. 指标告警重设计** | 「分析指标告警」以**分析卡片缓存**为观测源：卡片缓存过期/缺失即静默失效；且列表接口 500 导致功能从上线起不可用 | 告警对象改为「数据管理 → 指标」里的**已保存指标**（事件/留存），规则保存后在检测周期内真实求值 |
| **B. 告警通知模板** | 告警内容写死在代码里（`【级别】触发 名称 / 当前值 …`），无法按团队话术调整 | 可编辑模板：按「触发/恢复 × 通道」配置，预填充占位符，支持 Go 模板子集条件 |

范围与边界：

- **A 的观测源**只认 `MetaSavedMetric`（数据管理 → 指标）；指标定义（事件指标 / 留存指标）由既有查询引擎求值，保证「工作台上看到的数」与「告警判定的数」同口径。
- **A 的评估节奏**沿用既有状态机：60s 轮询 + 连续 `for_windows` 次越线才触发；指标时间窗口为**天**（`window_days`：今天 / 近 2 天 / 近 7 天 / 近 30 天），因为事件分析引擎的时间范围就是按天（`stat_date`）。
- **A 的旧路径**（`source='card'`、`GET /ops/alerts/cards`、卡片缓存取值）本期**下线**，不留双轨。
- **B 的模板粒度**：项目 × 事件类型（触发/恢复）× 通道（飞书/邮件/短信），是「项目级默认模板」，不按规则单独绑定。

## 2. 验收标准（门禁要素②）

### A. 指标告警

- [x] **A-1**：新建告警的来源是「数据管理 → 指标」的已保存指标列表；接口不再返回卡片；前端不再出现「分析卡片」字样作为告警对象。
- [x] **A-2**：原 `GET /sa/api/ops/alerts/cards` 的 500 缺陷消失——该接口下线，且**同类缺陷**（把 `project` 同时写进 URL 与 axios `params` 导致查询参数成数组）在告警控制器全族修复（`project` 数组入参被规范化取首值）。
- [x] **A-3**：指标可选列表接口返回：指标 id / 名称 / 显示名 / 类型（事件/留存）/ 定义摘要 / 是否可告警 / 不支持原因；另有「测试取值」接口按当前窗口真正求值一次，返回数值与耗时。
- [x] **A-4**：规则可配：指标、窗口天数（1/2/7/30）、比较符（> ≥ < ≤）、阈值、单位、级别（紧急/警告/提示）、持续窗口（连续越线次数）、重复间隔、恢复通知、联系人；保存后 60s 内进入检测。
- [x] **A-5**：指标被删除或求值持续失败时，规则健康度给出明确原因（指标缺失 / 求值失败），在工作台可见，不静默失败。
- [x] **A-6**：求值有界且只读：每次求值带项目过滤 + 时间窗口（`stat_date` 区间）；单轮每条规则最多 1 次 ClickHouse 查询；指标规则数量上限 20；评估不写入任何业务表（仅告警事件/投递记录）。
- [x] **A-7**：端到端取证：新增 **3 条测试指标**（含事件指标与留存指标）→ 建规则 → 实际触发 → 实际恢复；`alertevent` 与 `alertnotification` 可查，报告附证据。
- [x] **A-8**：迁移干净：历史 `source='card'` 规则在迁移中被停用（当前生产 0 条，迁移仍须幂等且可重复执行）。

### B. 告警通知模板

- [x] **B-1**：通知内容由模板渲染；触发/恢复 × 飞书/邮件/短信六个组合均可编辑，未自定义时使用**预填充占位符**的默认模板。
- [x] **B-2**：模板编辑器提供占位符清单（名称 + 说明 + 示例值），点击插入到光标处；未定义变量渲染为空串（不报错）。
- [x] **B-3**：支持 Go 模板子集：`{{.变量}}`、`{{if 条件}}…{{else}}…{{end}}`，条件支持 `eq / ne / or / and / not` 与字符串/数字字面量、括号。
- [x] **B-4**：保存时校验语法；非法模板（未闭合 `{{if}}`、未知动作、空表达式）返回 400 且不落库，UI 就地提示错误原因。
- [x] **B-5**：预览接口用示例数据渲染，仅返回文本，不发送任何真实通知。
- [x] **B-6**：「恢复默认」删除自定义覆盖，回到默认模板（预填充占位符）。
- [x] **B-7**：模板变更写入告警变更审计（action=`alert_template_update` / `alert_template_reset`，含操作人）。
- [x] **B-8**：邮件用模板渲染主题与正文；短信沿用长度约束（渲染后压缩空白并截断，页面说明）。
- [x] **B-9**：端到端取证：一次真实触发与一次真实恢复的通知内容 = 渲染后的模板（占位符已被替换），飞书群可见。

## 3. 非目标（门禁要素③）

- 不实现完整 Go template：不支持 `range / with / define / template / 管道 / 自定义函数`，不支持变量赋值。
- 不按规则绑定模板（不做「每条规则一套模板」）；不做模板版本历史与回滚。
- 不做富文本/HTML 邮件、飞书卡片 JSON（interactive card）模板；通知仍是纯文本。
- 不做秒级/分钟级指标窗口（事件分析的时间范围按天，本期不新增分钟级 SQL 通道）。
- 不做复合条件（多指标组合）告警、不做告警静默（mute）模板、不做抑制/聚合/降噪策略。
- 不做 cron 表达式调度（评估周期固定 60s）。
- 不恢复卡片来源告警，也不做卡片与指标的双轨兼容。

## 4. 用户可见变化

| 位置 | 变化 |
|------|------|
| 告警工作台 · 规则表 | 「卡片」列改为「指标」列（显示指标显示名 + 窗口天数）；空规则提示改为「从数据管理的指标创建」 |
| 告警工作台 · 建规则 | 「新建指标告警」抽屉：可选指标列表（搜索 + 类型标签 + 定义摘要 + 测试取值）→ 阈值/窗口/联系人 |
| 告警工作台 · 新标签页 | 「通知模板」：触发/恢复 × 飞书/邮件/短信，模板编辑 + 占位符插入 + 预览 + 恢复默认 |
| 通知内容 | 由模板渲染；默认模板与线上现状兼容（含级别、状态、当前值、条件、时间） |
| 数据管理 · 指标 | 指标列表继续是告警的可选对象；页面提示「可在监控告警中作为告警对象」 |

## 5. 依赖与风险

| 项 | 说明 |
|----|------|
| 依赖 | 「数据管理 → 指标」的已保存指标定义（事件/留存）；生产当前 **0 条**，需由本期新增测试指标验证 |
| 风险 | 求值复用了工作台查询链路 → 必须确认评估不带数据权限裁剪（规则由平台超管创建），且不污染查询缓存语义（使用 `refresh` 直查并写回） |
| 风险 | 按天窗口的指标在「今天」尚未结束时是累计值，天然单调上升；文档与 UI 需明确窗口口径，避免用户误配阈值 |
