# PRD：账号生命周期 v1（资料 / 密码策略 / 登录锁定 / 用户管理 / 审计）

> phase: clklog-analytics-account-lifecycle-v1
> 版本：v1.0（2026-09-17）｜ 上游：`docs/product/research-clklog-analytics-member-lifecycle.md`（GitLab / Grafana / Metabase 对标 + 缺陷清单）
> 下游：`docs/architecture/clklog-analytics-design-account-lifecycle-v1.md`
> 本文档是「账号生命周期第一段」的**产品层**权威：不依赖邮件通道即可交付的账号基础能力。

---

## 1. 背景与问题

现状创建成员只有「用户名 + 密码（+可选显示名）」三个字段：没有邮箱、没有找回密码、没有编辑、没有删除，登录可以无限爆破，所有账号操作零审计。对标结论（research §4/§5）：**邮箱列是全图的钥匙，但其本身不依赖邮件通道，可以先落**。本 phase 交付不依赖邮件通道的第一段，邮件相关能力（忘记密码链接、建号设密邮件、项目邀请、邮箱验证）留作下一 phase。

## 2. 阶段目标与范围（门禁要素①）

1. **账号资料**：`SaUser` 增加 `email`（可空、唯一、格式校验）、`last_login_at`、`created_by`；用户自助可编辑显示名与邮箱。
2. **用户管理页**（「设置 → 用户管理」，权限 `ops.user.manage`）：列表、创建（含 email）、编辑（显示名 / 邮箱 / 平台角色）、启用/禁用（接通既有 API）、解锁、重置密码、删除、审计查询。
3. **密码策略**：≥8 位 + 弱口令黑名单 + 不得包含用户名；管理员代设密码（创建 / 重置）标记 `must_change_password`，首次登录强制改密。
4. **登录锁定**：同一账号连续 5 次密码错误锁定 15 分钟；登录成功清零；超管可手动解锁。
5. **重置密码（无邮件降级方案）**：管理员触发，系统生成一次性临时密码仅展示一次，用户全部会话吊销，临时密码登录后强制改密。
6. **审计**：登录成功/失败/锁定、建号、编辑、改密、重置、禁用/启用、解锁、删除，统一落 `ops_action_log`（`auth_` 前缀），用户管理页可查。

## 3. 验收标准（门禁要素②）

- [ ] **AL-1**：创建用户可填邮箱；邮箱格式非法 400，邮箱重复 409；不填可创建。
- [ ] **AL-2**：密码短于 8 位、命中弱口令黑名单、或包含用户名（大小写不敏感）→ 400 并给出对应文案；创建 / 改密 / 强制改密三处全部生效。
- [ ] **AL-3**：同一账号连续 5 次密码错误后，第 6 次请求（即使密码正确）返回「账号已锁定」，15 分钟后自动恢复；期间正确密码也不能登录；超管解锁后立即恢复；任一时刻登录成功计数清零。
- [ ] **AL-4**：管理员重置密码 → 接口仅返回一次临时密码；该用户既有 token 全部失效；用临时密码登录成功但只能看到强制改密页；改密成功后解除并可正常访问。
- [ ] **AL-5**：管理员创建的用户登录后同样进入强制改密流（`must_change_password=true`）。
- [ ] **AL-6**：用户管理页可编辑显示名 / 邮箱 / 平台角色（super_admin ⇄ none）；操作对象是自己时禁用 / 删除 / 重置 / 降权返回 409。
- [ ] **AL-7**：删除无资产用户成功，其项目成员、成员组、token 记录一并清理；拥有看板 / 卡片 / 指标 / 分群 / 标签 / 文件夹任一资产的用户删除返回 409 并提示先禁用或移交。
- [ ] **AL-8**：§6 审计清单全部动作落 `ops_action_log`（action 以 `auth_` 前缀），用户管理页「审计」区可查询最近记录；运维「数据管理」审计列表不出现 `auth_` 行。
- [ ] **AL-9**：个人设置页可编辑显示名与邮箱；登录成功后 `last_login_at` 更新。
- [ ] **AL-10**：存量用户不受影响（email 为空可正常登录与使用）；`python3 scripts/i18n_check.py`、`python3 scripts/i18n_scan.py --check`、`python3 scripts/arch_ratchet.py` 全部通过；新增文案 13 门语言齐全。

## 4. 非目标（门禁要素③）

- 不做邮件通道：忘记密码邮件链接、建号设密邮件、按邮箱邀请入项目、邮箱验证（下一 phase，见 research §5 第二段）。
- 不做手机号 / 短信验证（research §5：维持非目标）。
- 不做 SSO / LDAP / OIDC、自助注册、登录验证码。
- 不做成员有效期、休眠回收、pending approval 状态。
- 不做会话管理页（仍可经由改密/禁用/重置连带吊销）。
- 不做资产移交：删除被资产阻塞（409），不移交所有权；资产移交沿用既有 P2 决策。
- 不追溯存量用户密码：旧密码（<8 位）仅在下次改密 / 被重置时按新策略校验。
- 不侵入社区版 ClkLog 用户体系（红线）。

## 5. 产品规则

### 5.1 账号字段（新增）

| 字段 | 规则 |
|------|------|
| `email` | 可空；平台内唯一（忽略大小写）；格式按通用邮箱正则校验；用户与管理员都可改 |
| `last_login_at` | 登录成功更新，只读展示 |
| `created_by` | 创建人用户名；脚本 / 迁移创建的记 `system` |
| `must_change_password` | 管理员代设密码时置 true；用户本人改密成功后置 false |

### 5.2 密码策略（三处统一：创建 / 改密 / 强制改密）

- 长度 ≥ 8 位；
- 不得命中内置弱口令黑名单（如 `password`、`12345678`、`qwerty123` 等常见口令，大小写不敏感）；
- 不得包含本人用户名（大小写不敏感）。

### 5.3 登录锁定

- 计数口径：同一账号**密码错误**计 1 次（用户不存在不计数，防止探测）；连续 5 次 → `locked_until = now + 15min`，计数清零。
- 锁定期间：任何登录请求（含密码正确）返回 401「账号已锁定，请稍后再试」。
- 解除：到期自动解除；或超管在用户管理「解锁」（清零 + 清 `locked_until`）。
- 登录成功：计数清零、清 `locked_until`、更新 `last_login_at`。

### 5.4 用户管理操作矩阵（`ops.user.manage`，即平台超管）

| 操作 | 规则 | 自我保护 |
|------|------|----------|
| 创建 | username 唯一；email 可空唯一；代设密码 → 强制首登改密 | — |
| 编辑 | 显示名 / 邮箱 / 平台角色（super_admin ⇄ none） | 不可改自己平台角色 |
| 启用 / 禁用 | 禁用立即吊销全部会话（既有行为） | 不可禁用自己 |
| 解锁 | 清失败计数与锁定截止时间 | — |
| 重置密码 | 生成 12 位临时密码，**只在弹窗展示一次**；吊销全部会话；置强制改密 | 不可重置自己（走自助改密） |
| 删除 | 无资产方可删除；有资产 409 提示先禁用 | 不可删除自己 |

### 5.5 强制改密流

`must_change_password=true` 的用户登录后：全屏仅显示「首次登录需修改密码」表单 + 退出登录按钮；新密码过 §5.2 策略校验后解除标记并进入系统。期间任何页面 / API 不放开（改密与登出接口除外）。

### 5.6 个人设置

「个人设置」新增基本资料编辑（显示名、邮箱）；改密文案与校验升级为新策略；其余不变。

### 5.7 审计

复用 `ops_action_log`（告警 / 运维已在写），新增 `auth_` 前缀动作，用户管理页提供只读查询（最近 100 条，按时间倒序）。运维「数据管理」审计列表过滤排除 `auth_` 前缀，互不污染。

## 6. 审计事件清单（验收对照）

| action | 时机 | detail 关键字段 |
|--------|------|-----------------|
| `auth_login_success` | 登录成功 | username |
| `auth_login_failed` | 密码错误（含触发锁定的最后一次） | username, fail_count |
| `auth_login_locked` | 锁定期登录被拒 | username, locked_until |
| `auth_user_create` | 管理员创建用户 | username, operator |
| `auth_user_update` | 编辑资料 / 平台角色 | user_id, changed_fields |
| `auth_password_change` | 用户自助改密 | user_id |
| `auth_password_reset` | 管理员重置 | user_id, operator |
| `auth_user_status` | 启用 / 禁用 | user_id, status |
| `auth_user_unlock` | 手动解锁 | user_id, operator |
| `auth_user_delete` | 删除用户 | user_id, username, operator |

## 7. 风险与依赖

- **数据库迁移**：`SaUser` 加列（email 唯一索引 + 计数/锁定列），上线随 `prisma migrate deploy` 生效；存量行 email 为 NULL，唯一索引不受影响（MySQL 允许多个 NULL）。
- **前端门禁**：强制改密是全屏拦截，需保证改密 / 登出链路在该状态下可用（回归点）。
- **审计复用**：`ops_action_log` 读取方（运维数据管理）需同步加 `auth_` 前缀排除，否则账号操作混进数据管理审计。
- **文档回写**：`clklog-analytics-design-user-rbac.md` 密码算法描述（bcrypt）与实现（scrypt）不一致，随本 phase 回写。
- 依赖：无外部服务（不发邮件、不发短信）。
