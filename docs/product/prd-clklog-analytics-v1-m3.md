> 对标：神策分析（Sensors Analytics）事件分析与漏斗分析

---

## 1. 阶段目标与范围（门禁要素①）

M3 在 M2/M2.1/M2.2 已实现的埋点管理与基础事件分析之上，补齐「事件分析增强」和「漏斗分析」两个核心模块，使分析平台达到可日常运营的对标神策体验。

| 模块 | 范围 |
|------|------|
| 事件分析增强 | 支持多指标、每个指标独立事件+筛选、全局筛选、多维分组、多图表（折线/柱状/饼图/数值卡/表格）、时间粒度 |
| 漏斗分析 | 支持 2~8 步有序漏斗、每步独立事件+筛选、全局筛选、窗口期、转化/流失视图、漏斗图+明细表格 |

## 2. 验收标准（门禁要素②）

- [ ] M3-E1：事件分析支持至少 3 个指标同时查询，每个指标可配置不同事件和筛选条件。
- [ ] M3-E2：事件分析支持全局筛选（事件属性+用户属性）和分组（事件属性/用户属性/时间粒度）。
- [ ] M3-E3：事件分析可切换折线图、柱状图、饼图、数值卡、表格，图表与表格数据一致。
- [ ] M3-E4：事件分析 P95 查询耗时 < 3s（DAU 5 万规模）。
- [ ] M3-F1：漏斗分析支持 2~8 步，每步可配置事件和筛选条件。
- [ ] M3-F2：漏斗分析支持全局筛选、窗口期（1 分钟~3650 天）、按人数有序口径。
- [ ] M3-F3：漏斗分析返回每步人数、逐级转化率、总转化率、流失人数，并展示漏斗图和明细表格。
- [ ] M3-F4：漏斗分析 P95 查询耗时 < 5s（DAU 5 万规模）。
- [ ] M3-R1：所有 ClickHouse 查询强制注入 `project_name` 过滤与 `LIMIT`（红线）。
- [ ] M3-R2：不改 ClkLog 社区版表结构与代码（红线）。

## 3. 非目标（门禁要素③）

- 不做时间对比（上期/去年同期）。
- 不做留存分析（移到 M4 之后）。
- 不做看板/卡片保存、自定义 SQL、用户分群。
- 不做按次数漏斗、属性关联、转化时长、用户下钻。
- 不做复杂漏斗路径分析（无序、并行）。

## 4. 事件分析增强

### 4.1 指标配置

| # | 需求 | 说明 | 优先级 |
|---|------|------|--------|
| E1-1 | 多指标 | 至少支持 3 个指标同时展示；可增删排序 | P0 |
| E1-2 | 每指标独立事件 | 每个指标选择不同事件（含虚拟事件） | P0 |
| E1-3 | 每指标独立筛选 | 每个指标可配置事件属性/用户属性筛选 | P0 |
| E1-4 | 指标类型 | 触发次数、触发用户数、属性聚合（sum/avg/max/min/去重/p50/p90/p99）、人均次数 | P0 |
| E1-5 | 指标别名 | 用户可修改指标在图表/表格中的显示名 | P1 |

### 4.2 全局筛选

| # | 需求 | 说明 | 优先级 |
|---|------|------|--------|
| E2-1 | 全局筛选作用于所有指标 | 事件属性+用户属性；与指标级筛选是「且」关系 | P0 |
| E2-2 | 筛选操作符 | `=`、`!=`、`in`、`not_in`、`contains`、`not_contains`、`regex`、`not_regex`、`>`、`>=`、`<`、`<=`、`is_set`、`not_set` | P0 |
| E2-3 | 筛选组合 | 支持且/或嵌套，最多 3 层 | P0 |

### 4.3 分组

| # | 需求 | 说明 | 优先级 |
|---|------|------|--------|
| E3-1 | 分组维度 | 事件属性、用户属性、时间粒度（小时/天/周/月） | P0 |
| E3-2 | 多分组 | 支持 1~2 个分组维度（如按天 + 按城市） | P1 |
| E3-3 | TopN + 其他 | 分组值默认取 Top 20，其余归入「其他」 | P0 |

### 4.4 图表与表格

| # | 需求 | 说明 | 优先级 |
|---|------|------|--------|
| E4-1 | 图表类型 | 折线图、柱状图、饼图、数值卡 | P0 |
| E4-2 | 表格 | 按分组维度展开，展示每个指标数值 | P0 |
| E4-3 | 图表切换 | 用户可在折线/柱状/饼图/数值卡/表格间切换 | P0 |
| E4-4 | 空状态 | 无数据时给出明确提示 | P0 |

## 6. 用户界面

### 6.1 事件分析页面

左侧配置面板从上到下：

1. **分析指标** 区域：指标卡片列表，每张卡片包含事件选择器、指标类型选择器、属性选择器（agg 时）、筛选条件编辑器、删除/拖拽排序按钮。页面不另设「选择事件」分区；多事件靠多条指标实现。
2. **全局筛选** 区域：与指标筛选 UX 一致的 `FilterEditor`。
3. **分组项** 区域：可添加 1~2 个分组，选择维度类型（事件属性/用户属性/时间）和具体属性/粒度。
4. **时间范围** 区域：日期选择 + 时间粒度。
5. **计算按钮**。

右侧结果区域：

- 顶部图表类型切换按钮（折线/柱状/饼图/数值卡/表格）。
- 中部图表区。
- 底部表格区（表格视图时全屏展示）。

### 6.2 漏斗分析页面

左侧配置面板从上到下：

1. **漏斗步骤** 区域：步骤编号、事件选择器、步骤别名输入、筛选条件编辑器、删除/拖拽排序按钮；底部「添加步骤」。
2. **全局筛选** 区域。
3. **窗口期** 区域：数字输入 + 单位（分钟/小时/天），默认 7 天。
4. **分组项** 区域（可选）。
5. **时间范围** 区域。
6. **计算按钮**。

右侧结果区域：

- 顶部「转化 / 流失」切换。
- 漏斗横向柱状图。
- 明细表格。

## 7. 漏斗语义基准

对齐神策「按人数漏斗」默认口径：

- 对每个用户，取其在时间范围内的首次命中第 1 步的事件时间 `t1`。
- 在 `t1` 到 `t1 + 窗口期` 内，检查是否依次命中第 2、3…N 步（中间可穿插其他事件）。
- 若命中，该用户计入转化；各步只计一次。
- 全局筛选作用于第 1 步人群；每步筛选作用于该步事件。
- ClickHouse 使用 `windowFunnel` 实现。

## 9. 依赖与风险

| 依赖 | 状态 | 说明 |
|------|------|------|
| M2 事件分析 SQL 生成器 | 已完成 | 需扩展为多指标 |
| M2.1/M2.2 虚拟事件/属性解析 | 已完成 | 事件/漏斗中复用 |
| windowFunnel 语义对拍 | 新增 | 以 §7 为基准，必要时与神策结果差异显式声明 |

| 风险 | 影响 | 对策 |
|------|------|------|
| 多指标 + 多分组导致 SQL 复杂度指数增长 | 性能不达标 | 限制同时 3 指标、2 分组；复杂场景走物化列或预聚合 |
| windowFunnel 与神策边界 case 不一致 | 数据口径争议 | 验收用例覆盖首次/重复/穿插/跨天场景 |
