# PRD：AI Workspace 按项目隔离（app 目录）

- `phase: clklog-ai-workspace-project-isolation-v1`
- 帽子：产品
- 上游：`docs/architecture/clklog-ai-workspace-design.md`、`prd-clklog-ai-workspace-v1.md`
- 触发：用户要求「AI workspace 需要根据项目进行隔离；隔离设计仅增加一个 `app` 目录，这个目录是项目独立的；切换不同的项目，启动 harness 后读取到的 `app` 目录不一样」

---

## 1. 阶段目标与范围（门禁要素①）

让 AI Workspace 的**工作目录**具备项目隔离：每个项目有且只有一个独立的 `app` 目录，harness 启动后模型在 `/workspace/app` 看到的就是**当前项目**的那一份；切到别的项目再启动，读到的 `app` 是另一个项目的，两者互不可见。

范围与边界：

- **只新增一个目录** `app`（host 侧 `…/workspaces/<项目>/app`，容器内挂到 `/workspace/app`），不新增第二层用户维度、不新增卷、不新增服务。
- 隔离轴 = **项目**：同一项目下的成员共享这一个 `app`（与平台「项目内资产共享」的既有模型一致）。
- 运行时会话产物（既有 `workspaces/<项目>/<用户>/<kind>/<id>`）与 `dsh-home` **保持不变**，本次不动它们的分层。
- 平台级模板（`initialization/`）保持全局共享，不进 `app`。

## 2. 验收标准（门禁要素②）

- [x] **P-1**：为项目 A 启动 harness，模型侧存在 `/workspace/app`，且它就是 host 上 `…/workspaces/<hash(A)>/app`。
- [x] **P-2**：在 A 的 `app` 写入文件后，切到项目 B 启动 harness，`/workspace/app` 中**看不到**该文件；切回 A 又能看到（用户描述的核心验收场景）。
- [x] **P-3**：`app` 目录首次使用时自动创建（无需人工 mkdir），属主为 harness 运行用户、权限 0750，容器内以同一 uid 可读写。
- [x] **P-4**：`app` 目录内自动带一份标识文件（如 `project.json` 写项目名 + `README.md` 写用途），人和模型都能确认当前项目。
- [x] **P-5**：隔离不可被绕过：`app` 路径由服务端按项目推导，broker 校验其形状（必须是 `workspaces/<该项目的 hash>/app`），符号链接一律拒绝；容器仍为 `--read-only` + `--network=none`。
- [x] **P-6**：容量有界：`app` 计入工作区用量统计或单独设上限，超限时按既有策略拒绝（不允许无限增长）。
- [x] **P-7**：多项目并发时互不影响：A 与 B 的 runtime 可同时存在（受既有全局 `max_runtimes` 约束），各自挂各自的 `app`。
- [x] **P-8**：验收取证：A/B 切换的双向可见性测试 + 符号链接逃逸测试 + 权限检查，写入验收记录。

## 3. 非目标（门禁要素③）

- 不做「每个用户在每个项目各一个 `app`」——本 phase 明确 `app` 是**项目级**共享目录（若日后要求用户级，只需改路径规则，见设计 §7）。
- 不做每项目独立的 runtime 配额/公平调度（`max_runtimes` 仍是全局）。
- 不做每项目独立的模板/策略（`initialization/` 保持全局）。
- 不做跨项目读取或迁移（不允许把 A 的 `app` 内容搬到 B）。
- 不做 `app` 的前端管理界面（本期是运行时目录；浏览/清理走运维操作）。
- 不做项目删除时的自动清理（本期人工/运维脚本处理，避免误删）。

---

## 4. 用户可见行为

| 场景 | 变化 |
|---|---|
| 在项目 A 打开 AI Workspace | 模型工作目录里出现 `app/`，内容属于 A；写入的文件留在 A |
| 切到项目 B 打开 AI Workspace | `app/` 是 B 的（A 的文件不可见），提示/标识文件写明当前项目名 |
| 切回 A | 之前写入的文件仍在（持久化，非会话级） |
| 同一项目内不同成员 | 共享同一个 `app`（项目内协作） |

## 5. 依赖与风险

| 项 | 说明 |
|---|---|
| 依赖 | 既有 `workspaces/<hash(project)>/...` 分层与项目校验链路（gateway/proxy/broker 均已带 project），本设计只在其上「补一个同级目录」 |
| 风险 | 项目级共享意味着同项目成员彼此可见 `app` 内容——需产品确认是否符合预期（默认按用户要求取「项目独立」） |
| 风险 | `app` 在会话工作区之外，broker 现有「只允许挂载 workspaceRoot 内路径」的校验需要一条**显式白名单规则**（设计 §4.3），不能放宽成任意路径 |
