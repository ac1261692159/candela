- `phase: clklog-analytics-ops-console-v1`
- 日期：2026-09-07
- 帽子：产品（`docs/product/`）
- 状态：**已实现并上线**（2026-09-15 回写；生产实测见 `docs/project/acceptance-clklog-analytics-alerting-v1.md`）
- 关联：架构方案 `docs/architecture/clklog-analytics-design-ops-console-v1.md`

## 1. 背景

2026-09-07 线上「场景与内部场景」看板打不开，整个排查过程暴露一个事实：**平台能分析业务数据，但看不见自己**。

| 想回答的问题 | 现在的做法 | 代价 |
|---|---|---|
| 为什么 500 | SSH 登服务器 grep 日志 | 需知道日志路径，且要懂日志格式 |
| 慢查询影响多大 | `grep -c` + 按分钟手工聚合 | 无历史趋势，无法对比 |
| 哪些卡片慢 | 正则提取 + `uniq -c` | 完全手工 |
| 系统还健康吗 | 登服务器跑 `df` / `free` / `supervisorctl status` | 每次都要连服务器 |
| 出问题有人知道吗 | **没有告警，靠用户报** | 故障发现滞后 |

用户诉求：

> 需要重新开一个运维面板，然后开一个：慢SQL的菜单、服务器状态菜单、监控告警菜单。
> 运维面板在平台内一级菜单，**只有 admin 超管才能使用，其他用户均不可见**。
> 服务器状态菜单尤其要对磁盘进行使用量的预估，需要依赖趋势图。

**目标一句话**：把「登服务器 + grep」的运维动作，收敛成平台内超管可见的三个页面。

---

## 2. 用户与权限

| 项 | 规则 |
|---|---|
| 可见人群 | **仅 admin 超管**（`platform_role = super_admin`） |
| 其他用户 | 侧边栏**不出现**「运维」菜单；直接访问 URL 返回无权限页 |
| 判定依据 | 平台级身份，与项目角色（项目 owner / 分析管理员 / 分析师 / 普通成员 / 外部人员）**无关** |
| 边界说明 | 超管若不是某个项目成员，运维面板仍可访问——它管理的是平台本身，不是项目数据 |

---

## 3. 信息架构

侧边栏新增一级菜单「运维」，位置：在「项目权限」之后、「设置」之前。三个子菜单：

| 菜单 | 路径 | 一句话 |
|---|---|---|
| 慢 SQL | `/ops/slow-queries` | 查谁慢、慢在哪、为什么失败 |
| 服务器状态 | `/ops/server-status` | 主机与依赖现在怎么样、磁盘什么时候会用完 |
| 监控告警 | `/ops/alerts` | 哪些指标越线了、什么时候开始的 |

## 4. 页面详述

### 4.1 慢 SQL

**用途**：无需登服务器，查看超过阈值的查询。

**筛选条件**

| 控件 | 默认值 | 选项 |
|---|---|---|
| 时间范围 | 近 24 小时 | 近 1 小时 / 近 6 小时 / 近 24 小时 / 近 3 天 |
| 最小耗时 | 5000 ms | 可输入（毫秒） |
| 执行状态 | 全部 | 全部 / 成功 / 失败 |
| 执行账号 | 全部 | 按实际出现的账号动态列出 |

**列表列**（默认按耗时倒序，分页 20 条/页）

| 列 | 说明 |
|---|---|
| 时间 | 查询结束时间 |
| 耗时 | 毫秒，主排序字段；超过 30 秒（查询超时上限）以警示色标注 |
| 状态 | 成功 / 失败 |
| 读取行数 | |
| 读取字节 | 人性化单位（KB/MB/GiB） |
| 内存占用 | 人性化单位 |
| 账号 | |
| SQL | **默认单行截断**，点击展开完整内容，可一键复制 |
| 异常 | 失败时展示错误原因 |

**必须呈现的提示**

- 页面顶部常驻说明：**数据来自 ClickHouse 查询日志，仅保留最近约 3 天**（生产实测保留约 2.5 天）。选择「近 3 天」以外的范围时给出相应提示，避免用户误以为"没有慢查询"而非"日志已过期"。
- 空态文案：「当前时间范围内没有超过 X ms 的查询」。

**不做**：不提供"终止查询"等写操作，本页**纯只读**；不提供导出（首期）。

### 4.2 服务器状态

**用途**：一页看完主机、依赖、数据链路，并回答「磁盘什么时候会用完」。

分区块自上而下：

**① 概览（卡片行）**

| 卡片 | 内容 |
|---|---|
| 应用 | 版本号、已运行时长 |
| 主机内存 | 已用 / 总量、使用率 |
| CPU 负载 | 1 / 5 / 15 分钟负载 |
| 磁盘 | 已用 / 总量、使用率（取 `/data` 数据盘） |

**② 磁盘使用量预估（本页面重点）**

- 用**趋势图**渲染：X = 采样时间，Y = 已用空间。
- 阈值线 = 磁盘总量（并标注 90% 提醒线）。
- 图上显著位置给出结论文案：**「按近期增速，预计 YYYY-MM-DD 用尽，剩余 N 天」**；若近期无增长，显示「当前无明显增长趋势，暂不预测」。
- **数据积累期空态**（重要）：趋势预估依赖历史采样，面板上线初期样本不足时，显示「正在积累采样数据：当前 X/3 个采样点，满 3 点后可预测」，**不得**在样本不足时给出预测线。

**③ 依赖与数据链路**

| 项 | 内容 |
|---|---|
| ClickHouse | 连通状态、版本 |
| 数据量 | `sa_events` 行数、占用空间 |
| 数据链路 | 最近一次成功写入时间、距今多久；超过阈值时以警示色标注「链路可能停滞」 |

**刷新**：提供手动刷新按钮；默认不自动刷新（避免运维页自身成为负载）。

**不做**：不展示 Kafka 消费延迟（首期）；不提供任何重启/清理等运维动作入口。

### 4.3 监控告警

**用途**：让失效模式自己暴露，而不是等用户报。

**规则列表**

| 列 | 说明 |
|---|---|
| 规则名 | |
| 监控对象 | 如"慢查询次数"、"磁盘可用空间" |
| 当前值 / 阈值 | |
| 状态 | 正常 / 触发中 |
| 启用 | 开关（停用后不再检测） |
| 操作 | 调整阈值 |

**内置规则**（随版本提供，**不可新增、不可删除**，只能启停与调阈值）：

| 规则 | 默认阈值 |
|---|---|
| 慢查询次数突增 | 近 5 分钟耗时 > 5s 的查询 ≥ N 次 |
| 查询失败率 | 近 15 分钟失败占比 > X% |
| 卡片缓存连续刷新失败 | 某卡片连续失败 ≥ 3 次 |
| ClickHouse 不可达 | 连续探活失败 ≥ 2 次 |
| 磁盘可用空间 | < 10% |
| 数据链路停滞 | 最近写入距今 > 30 分钟 |

**告警事件列表**

| 列 | 说明 |
|---|---|
| 触发时间 | |
| 规则 | |
| 触发时值 | |
| 状态 | 触发中 / 已恢复 |
| 持续时长 | |

筛选：按状态（触发中 / 已恢复 / 全部）。

**通知方式（首期）**：**仅页面内可见**。不发送邮件、企微、短信。页面顶部对「触发中」的告警给出数量角标或提示条，超管登录即可看到。

**不做**：不提供通知渠道配置；不做告警自动处置（只告警不动作）；不支持自定义规则。

## 5. 阶段目标

| 编号 | 目标 |
|---|---|
| G1 | 慢 SQL 可查：不看日志也能看到谁慢、慢多久、SQL 原文与失败原因 |
| G2 | 服务器状态可见：主机、依赖、数据链路一页看完，并给出磁盘用尽预估 |
| G3 | 告警可看：内置规则覆盖本次事故暴露的失效模式，触发后超管登录即见 |
| G4 | 全程只读：运维面板不提供任何写操作与运维动作入口 |
| G5 | 权限收敛：仅超管可见可用 |

## 6. 范围

### 6.1 范围内

1. 侧边栏「运维」一级菜单 + 三个子页面。
2. 慢 SQL 查询页（筛选、列表、SQL 展开/复制）。
3. 服务器状态页（概览、磁盘趋势预估、依赖与数据链路、手动刷新）。
4. 磁盘用量采样落表（供趋势图消费）。
5. 监控告警页（内置规则启停与阈值调整、告警事件列表）。
6. 超管权限接入（菜单与接口两层）。

### 6.2 范围外

1. **不**发送任何外部通知（邮件/企微/短信）——涉及密钥与外发依赖，单独立项。
2. **不**支持自定义告警规则（首期仅内置 6 条）。
3. **不**做任何自动处置（不自动重启、不自动清理）。
4. **不**提供慢 SQL 的"终止查询"；**不**在首期提供日志清理等写操作（2026-09-15 修订：日志目录治理与分区清理后由 `phase: clklog-analytics-data-management-v1` 以「预演 → 二次确认 → 审计」形式引入，见 §9 修订记录）。
5. **不**展示 Kafka 消费延迟。
6. **不**做多节点 / 分布式视图（当前单节点部署）。
7. **不**引入 Prometheus / Grafana 等外部监控栈。
8. **不**优化慢 SQL 本身（用户已明确"记录下来即可"）。
9. **不**改造 `/sa/api/health` 的鉴权（如需外部探活，单独立项）。

## 7. 验收标准

| 编号 | 标准 |
|---|---|
| AC1 | 超管账号侧边栏出现「运维」菜单及三个子项；非超管账号**不出现** |
| AC2 | 非超管直接访问 `/ops/*` 任一 URL 返回无权限页，不返回任何运维数据 |
| AC3 | 慢 SQL 页可按时间范围与最小耗时筛选，列表展示耗时/状态/读取行数/SQL（可展开复制）/异常 |
| AC4 | 慢 SQL 页顶部常驻提示查询日志保留期（约 3 天），避免用户误判"无慢查询" |
| AC5 | 服务器状态页展示应用版本与运行时长、内存、CPU 负载、磁盘使用率 |
| AC6 | 磁盘区域展示趋势图与「预计 YYYY-MM-DD 用尽，剩余 N 天」（依赖趋势图 phase） |
| AC7 | 采样点 < 3 时**不显示预测线**，显示「正在积累采样数据：X/3」 |
| AC8 | 服务器状态页展示 ClickHouse 连通与版本、数据量、数据链路最近写入时间 |
| AC9 | 监控告警页列出 6 条内置规则，可启停、可调阈值；触发中的告警在页面顶部有提示 |
| AC10 | 告警事件列表可按状态筛选，展示触发时间、触发值、持续时长 |
| AC11 | 慢 SQL 页**无任何写操作入口**（无终止查询、无删除）。**2026-09-15 修订**：服务器状态页的「日志目录治理」与新增「数据运维」页确含写动作（清理日志、DROP PARTITION、TTL），属 `clklog-analytics-data-management-v1` 范围，须满足「预演 + 二次确认 + 审计」三条硬约束后方可上线，见 §9 |
| AC12 | 页面数据均为只读获取，不因打开运维页而产生额外业务查询负载 |
| AC13 | 磁盘用量下降或无增长时**不画预测虚线**，文案「暂不预测」；Y 轴从 0 到磁盘总量，不出现负 GB |
| AC14 | 180/90 天视图拟合前按天抽样；外推最多 30 天 |

## 8. 依赖与实施顺序

1. **先** `clklog-analytics-trend-chart-v1`（趋势图）——用户明确优先，磁盘预估依赖它。
2. **后** 本 phase 运维面板：
   - 磁盘预估直接复用趋势图能力；
   - 慢 SQL 注意查询日志仅保留约 3 天（AC4）；
   - 数据链路判据**不得**使用 `sa_events.max(stat_date)`（生产实测为未来值 `2027-01-02`，不可用），改用 ClickHouse 侧最后写入时间或 ingestor 心跳——由架构方案确定。

## 9. 关键产品决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| D1 | 平台内一级菜单，不建独立运维站点 | 复用登录与权限；独立站点要重建认证体系 |
| D2 | 仅超管可见，且菜单与接口两层拦截 | 用户明确要求；运维是平台级能力，双重保险防误配 |
| D3 | 慢 SQL 明确告知"日志只保留约 3 天" | 不告知会让用户把"日志过期"误读为"没有慢查询" |
| D4 | 磁盘预测在采样不足时**不画预测线** | 样本不足的预测是误导，宁可显示"积累中" |
| D5 | 告警首期仅页面内可见 | 外部通知涉密钥与外发依赖，单独立项；先把"看得见"做实 |
| D6 | 内置规则不可增删，仅可启停与调阈值 | 首期收敛范围；自定义规则编辑器是独立复杂度 |
| D7 | 运维面板纯只读，不做任何运维动作（**2026-09-15 修订**：动作类能力在 `clklog-analytics-data-management-v1` 中以独立 phase 引入，原理由由「预演 + 二次确认 + 审计」三条硬约束承接，见 §9） | 面板出问题不应成为故障源；动作类能力需单独的审计与二次确认设计 |
| D8（2026-09-15） | 动作类能力**另开 phase**，不在本 PRD 内扩写 | 保持本 phase 的验收边界可核对；写动作需要单独的风险与审计设计 |
