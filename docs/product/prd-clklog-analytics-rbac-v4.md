# PRD：项目权限全员只读可见（phase: clklog-analytics-rbac-v4）

> phase: clklog-analytics-rbac-v4
> 上游：`docs/product/prd-clklog-analytics-rbac-v2.md`（五角色与权限目录）、`docs/product/prd-clklog-analytics-rbac-v3.md`（选择器/治理分离与指标归属）
> 下游：`docs/architecture/clklog-analytics-design-rbac-v4.md`
> 触发：v3 验收中提出「分析师看不到自己的权限列表」，产品决定改为**全员可见**。

---

## 1. 背景与产品决定

v2 把「项目权限管理」定为管理员专属，普通成员看不到自己为什么能用某些功能；v3 验收时用户提出：

> 「所有用户都应该能看到 项目权限、数据权限。」

据确认的三个口径：

| 决策点 | 结论 |
|---|---|
| 可见角色 | **含外部人员**——五个项目角色全部只读可见 |
| 数据权限深度 | **含策略明细**——事件/属性白名单、行过滤条件只读可见 |
| 邀请与审计 | **保持管理员可见**——待处理邀请（含未入会者邮箱）与权限审计流水不放开 |

---

## 2. 阶段目标与范围

1. **项目权限全员只读可见**：成员列表、成员组、角色说明（功能 / 操作权限 / 功能明细三列目录）四个页面，owner / 分析管理员 / 分析师 / 普通成员 / 外部人员都能打开。
2. **数据权限全员只读可见，含明细**：策略列表（名称 + 引用数）+ 只读明细（可见事件、可见事件属性、可见用户属性、行过滤条件）。明细视图对非管理员**新增**（现状只有编辑者可写原始 JSON，没有查看入口）。
3. **写权限一律不变**：成员与组的增删改、角色定义编辑、策略增删改仍分别由「项目权限管理 · 编辑」「项目权限管理 · 编辑（分析管理员授权）」「数据权限 · 管理」决定。
4. **收紧两处附带暴露面**：待处理邀请列表与权限审计流水改为「能管理项目权限的人」可见，不再随本次放开外溢。

---

## 3. 验收标准

- [ ] **RB4-1 入口**：五个角色登录后侧栏都出现「项目权限」分组，四个子项（成员 / 成员组 / 角色管理 / 数据权限）均可进入；外部人员也能进入，且不影响其「只看被分享看板」的既有约束。
- [ ] **RB4-2 只读**：分析师 / 普通成员 / 外部人员在这四个页面上看不到任何写操作按钮（添加成员、改角色、移出成员、续期、新建/编辑/删除成员组、编辑角色定义、新建/删除策略）；直连写接口仍 403。
- [ ] **RB4-3 角色说明可读**：非管理员能打开角色管理页，读到五个预置角色的「功能 / 操作权限 / 功能明细」完整目录——即"能看到自己的权限列表"。
- [ ] **RB4-4 数据权限明细**：非管理员能在数据权限页查看任一策略的明细（可见事件、可见事件属性、可见用户属性、行过滤条件）；`mode=all` 显示为「不限制」，白名单显示具体键，行过滤显示 `属性 运算符 值` 条件并在多条件时标明「且」关系。
- [ ] **RB4-5 邀请不放开**：非管理员看不到待处理邀请区（含被邀请人邮箱），也无法通过接口读到邀请列表（403）；邀请与撤销仍只有管理员可用。
- [ ] **RB4-6 审计不放开**：非管理员看不到权限审计流水，接口 403；owner / 分析管理员的可读性不回归。
- [ ] **RB4-7 管理员不受影响**：owner / 分析管理员的四个页面与全部写操作与改动前一致；超管在设置里的账号管理不受影响。
- [ ] **RB4-8 文案与门禁**：新增文案在 13 门语言齐备；`arch_ratchet` / `i18n_check` / `i18n_scan --check` / 后端 jest / 前端 vitest / 两端 `tsc` 全绿。

---

## 4. 非目标

1. **不给非管理员任何写权限**：本期只放开「查看」，不引入「成员自助改自己角色」「组员自助管理」等能力。
2. **不放开邀请队列与权限审计流水**（RB4-5 / RB4-6），二者含第三方邮箱与治理流水。
3. **不改数据权限的求值逻辑**：谁能看哪些数据、谁被哪条策略收窄，一律不变；本期只让策略本身可见。
4. **不改 v3 的选择器与指标口径**，不改看板可见性规则（外部人员仍只见分享给它的看板）。
5. **不做权限变更通知/订阅**（「谁改了谁的权限」的主动告知）。
6. **不引入新的权限码**：复用 `iam.member.view` 作为「项目权限只读」的载体。

---

## 5. 界面影响

| 页面 | 分析师 / 普通成员 / 外部人员 | owner / 分析管理员 |
|---|---|---|
| 项目权限 → 成员 | 只读成员表（用户、角色、数据权限、到期） | 不变（增删改、邀请、审计、续期齐全） |
| 项目权限 → 成员组 | 只读列表 | 不变 |
| 项目权限 → 角色管理 | 只读五角色目录与权限明细 | 不变（owner 可编辑分析管理员授权） |
| 项目权限 → 数据权限 | 只读列表 + **新增**明细查看 | 不变（新建/删除） |

侧栏「项目权限」分组从「仅管理员可见」改为「项目成员可见」。

---

## 6. 风险

- **成员名单对外开放**：外部人员也能看到项目成员构成（用户名、显示名、角色、到期）。用户已确认接受；如后续要收，只需把 `iam.member.view` 的外部人员档收回，页面与接口无需改动。
- **角色目录信息量**：所有人能看到每个角色的完整权限明细，包括自己不具备的能力——这是本期的目的（"读懂自己的边界"），但也意味着权限模型对全员透明；如需按角色裁剪展示，属后续需求。
- **误判"看得到=改得动"**：只读页面必须彻底隐藏写按钮，否则用户点了才吃 403。验收 RB4-2 覆盖。
- **审计/邀请的收紧是行为变更**：以前持有 `iam.member.view` 就能读邀请与审计，现在改为需要「项目权限管理 · 编辑」。现网只有 owner / 分析管理员持有该档，二者都同时持有编辑码，故无实际用户受影响。

---

## 7. 发布说明

- 所有项目成员现在都能看到「项目权限」与「数据权限」，只读。
- 待处理邀请与权限审计流水仍只对能管理项目权限的人开放。
- 无数据迁移、无需重新登录。
