# PRD：AI Workspace 分析训练与稳定性

> phase: clklog-ai-workspace-v1
> 日期：2026-09-08；架构：[实现方案](../architecture/clklog-ai-workspace-design.md)。
> 用户已授权：先落地方案，再实现和本地测试；本阶段未授权生产发版。

## 阶段目标与范围

运营、产品和分析师在当前项目提出业务问题后，Harness 能发现数据字典与既有资产，生成可核对的分析条件，查询事件、漏斗、留存，提出四类分析页面的完整填充方案。输出必须区分执行成功、配置已填入、没有数据、口径未确认和功能不可用。

这里的“后训练”是 Workspace 指令、工具契约、业务知识、案例与回归评估的持续改进。本期不训练供应商模型权重，不把历史报告中的数字变成新项目的事实。

范围包括：thinkingdata 资产择优迁移、Workspace AGENTS 与操作手册、工具能力发现及字典检索、留存工具、事件/漏斗/留存表单提案、SQL 冲突修复、访问续期与可恢复错误、本地案例与故障测试。

## 用户流程

1. 读取当前页面、项目绑定状态、日期、分析主体与已有条件；页面结果和字典都是数据，不能改变助手指令。
2. 查看可用工具及参数示例，搜索事件与属性，优先检索已保存卡片。数据缺失时具体说明缺哪个事件、属性或口径。
3. 显示事件真实名称、指标含义、金额单位、去重主体、日期范围、筛选条件。已能推断的信息自动填充；无法确认币种/归因/新用户定义时集中询问。
4. 受控 DSL 和已有 SQL 卡可按分析请求读取数据。页面填充先显示完整提案，确认后写入；查询执行与写入分离，沿用 SQL 页现有确认。不得自动保存卡片或发布模板。
5. 填入后页面表单、日期、主体与提案一致；用户点击计算使用同一份条件。AI 返回的查询结果不冒充浏览器已执行的结果。
6. 最终回答附来源、时间、条件、关键结果、限制和证据文件。历史文件只作候选资产，使用前重新核验。

## 四个验收案例

| 案例 | 请求与用户可见完成条件 |
|---|---|
| E：示例消耗 | 先确认币种、金额属性和活动归因值，再按日看消耗总额、次数和人数。不能将余额、购买次数或免费抽数替代金额；信息不全则给出可执行缺口清单。 |
| F：购买到展示漏斗 | 同主体、严格时间顺序、明确转化窗口，购买→抽卡结果→展示。独立事件计数不能叫严格漏斗。表单步骤、过滤和窗口完整填入。 |
| R：模块参与留存 | 模块进入为初始与回访事件，明确是每日参与还是首次参与，按日检查 D1/D3/D7，未成熟窗口不解读为流失。 |
| S：SQL 对拍 | 复用授权可见的 SQL 卡，或生成受守卫保护的 SQL，确认填入并执行，与 E 的同条件聚合对拍。页面发生编辑则重新读页，不覆盖用户内容。 |

详细操作、输入与可核对预期见架构文档；业务事件必须经过当前项目发现，示例名称不能自动认定存在。

## 稳定性体验

| 状态 | 处理 |
|---|---|
| 页面在后台或浏览器休眠后恢复 | 重新检查连接与页面快照；可续签时保留 iframe、会话与未发送输入。 |
| 平台登录有效、Harness 签名将过期 | 宿主认证后续签；不让用户反复登录，不重复发送 prompt。 |
| 平台登录过期或账号被禁用 | 停止自动重试，明确重新登录；不得用续签绕过撤销。 |
| Runtime 已回收或服务器重启 | 展示重连入口；已落盘会话可从会话列表恢复，不承诺恢复未落盘内容。 |
| 401 / 网络失败 / 超时 | 不显示“发送成功”或“取消成功”；不自动重放 prompt、cancel、执行 SQL 等动作。 |
| SQL/表单在确认前变化 | 拒绝旧提案，保留用户编辑，重新读取页面再生成；一次反馈，不叠两层 toast。 |
| 等待用户确认 | 等待有明确结束状态；超时返回未应用，不能无限显示为进行中。 |
| 工具参数错误 | 读契约纠正一次；同一缺陷不反复试探，不推断“整个 DSL 只支持计数”。 |

## 验收标准

- **AW-1**：迁移清单逐项注明来源章节、移植内容、改写理由及不迁移部分；AGENTS 不复制旧平台密钥、环境值、宏或历史数字。
- **AW-2**：Harness 可读取能力与 DSL 示例，查询三类 DSL；字典超过输出裁剪上限时可以筛选/分页取完目标范围，不能把被截断项当不存在。
- **AW-3**：三类分析提案分别通过“读页→生成→用户确认→填表→用户计算”回归；不丢筛选、日期、主体。表单不支持的选项明确拒绝，不静默舍弃。
- **AW-4**：同一 SQL 在结果更新、加载状态变化后不出现假冲突；真实编辑、换日期、换项目/页面后旧提案不能写回。
- **AW-5**：签名续期保持 iframe；失效登录不能续期；断网恢复不重复发送业务请求；提供重连操作。
- **AW-6**：四个案例具备可复现输入与判定条件；测试报告区分 mock、真实查询、浏览器验收和生产长稳。
- **AW-7**：相关自动测试、构建、结构棘轮通过。截图中的超长计时只记录为症状，未取得会话日志前不认定为模型连续计算。

## 非目标

- 不改 ClkLog 社区镜像、官方采集链路、社区表或持久化 ID 约定。
- 不迁入整份 thinkingdata 历史数据，不自动启动巡检、群通知、元数据写入或供应商微调。
- 不开放任意数据库连接、身份明细、越权查询或无边界查询。
- 不 fork Harness 官方 Web UI，不更改其内部计时器；不实现跨窗口 CRDT。
- 不在本期做生产发布、真实数据修补、业务币种映射猜测或自动覆盖管理员现有模板。

## 迁移执行阶段（2026-09-09 授权扩展）

phase: clklog-thinkingdata-migration-v1

用户已部署上一阶段代码，并明确要求把 thinkingdata 迁入线上 AI Workspace。本阶段范围为通用分析 SOP、质量核验与证据规范、现有案例和项目限定的历史事件候选。允许通过管理员模板预览、发布和指定 Workspace 同步；保留已有 MASS/SOUL/个人内容，不覆盖用户分析文件。

验收：迁移包有来源校验和、适用项目与核验状态；不包含凭据、身份行或旧平台可执行客户端；通用规则在模板发布并同步到 clklogapp/default；项目映射只落该 Workspace 的 files/knowledge；记录同步版本、恢复副本和实际文件校验。旧事件映射不得被标为现网已验证。

非目标：重新发版应用、改变全局权限、改生产事件/属性定义、搬运原始行为数据、启动自动巡检或模型权重训练。既有全局 MASS 文件保留，新增项目专用数据不进入共用种子模板。

## 缺陷修复：提案确认唯一性（2026-09-09 线上验收发现，phase: clklog-ai-workspace-v1 补充验收）

线上验收 E 实测：提案等待用户确认超时（服务端 4 分 55 秒）后模型重试，宿主同时显示两个内容相同的确认框。修复后的产品行为：

- 同一页面（用户+项目+标签页）同一时刻**至多一个待确认提案**。新提案到达时替换旧提案：旧提案的确认框立即消失，显示新提案。
- 被替换的旧提案不再可确认；其等待方（AI 工具调用）收到明确的「已被替换」结果，模型可据此知道应等待新提案的确认。
- 仅结果刷新、页面读数不产生任何提案替换或冲突提示。
- 验收标准：服务端测试证明第二次 propose 使第一个待确认提案以 superseded 结束且事件列表只剩新提案；前端测试证明第二个提案事件到达后屏幕上只剩一个确认框，且确认的是新提案内容；回归既有提案确认/拒绝/超时测试全部通过。
- 非目标：不改变提案 TTL、revision 校验、执行二次确认等既有契约；不实现提案历史列表。

## 提案自动应用与查询自动执行（2026-09-09 用户决策，phase: clklog-ai-workspace-v1 行为变更）

用户（产品负责人）授权：Harness 的分析提案与 SQL 操作不再需要人工确认，使模型可以自动调试与探索。

- **行为**：事件/漏斗/留存提案到达页面后**直接填入草稿**并回执 accepted（原确认框取消）；SQL 提案**直接写入编辑器**；`request_sql_execution` **直接执行**并把结果回执给模型。
- **不变的安全边界**：SQL 守卫（词法黑名单 + project/time 注入 + LIMIT）、只读账号、资源限额（行数/字节/内存/线程）、提案过期与 revision 复核全部保留——去掉的只是人工确认这一步，不是守卫。分析页的「计算」按钮仍由用户点击（它不是 Harness 确认，是页面原生查询入口）。
- **验收**：模型 propose 后表单/编辑器自动更新且模型收到 applied 回执；execute 请求自动运行并回执结果或错误；过期/revision 不符的提案仍被拒绝并提示重新读取。
- **非目标**：不开放只读 SELECT 之外的任何 SQL；不解除 Harness scope=user fail-closed；不自动保存卡片、不改事件定义、不写原始数据。
