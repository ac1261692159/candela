# PRD：Debug 重查询异步化——快查询秒回，慢查询转后台

> phase: `clklog-analytics-debug-async-query-v1`
> 状态：待评审 → 实施中
> 来源：`docs/project/validation-clklog-analytics-sa-events-projection-v1.md` §6（projection 因磁盘容量不可行，异步为零存储路线）
> 前置：`clklog-analytics-debug-query-v1`（查询 + 留档 + 项目开关，已上线）、`clklog-analytics-sa-events-skip-index-v1`（跳数索引，已上线）

---

## 1. 背景

Debug 页的 7 天窗 + 设备/账号维度查询在当前数据量下需要 **5–10 秒**（跳数索引已把账号维度从 23s 压到 10s，
projection 能把两类查询压到 0.1–0.5s，但**磁盘装不下**：基础表按 18 个月 TTL 的稳态已占满磁盘约 89%）。
在既不扩盘也不缩短保留期的前提下，**唯一零存储的解法是异步**：让用户不必盯着转圈等结果。

## 2. 阶段目标与范围

**做**：

1. `POST /meta/debug/query` 改成**两段式**：先同步跑（短预算），超预算则登记为后台任务并立即返回任务 id；
2. 后台任务在 server 进程（`background_workers` 门禁，与既有后台任务同一判据）串行执行，结果写入**既有留档记录**；
3. 前端：快查询体验不变；慢查询提示「已转后台」并轮询这条留档，完成后**原地渲染结果**；
   历史记录列表增加状态列，运行中/失败可见；
4. 复用既有留档表与接口，不新增存储成本。

**不做（非目标）**：

- 不扩盘、不缩短保留期、不建 projection（属上一 phase 的结论，本 phase 绕开）；
- 不改 `GET /meta/debug/recent`（外部/AI 调用方仍走同步查询，契约不变）；
- 不做跨进程分布式任务队列（单 worker + 数据库状态足够；多实例另立 phase）；
- 不改窗口语义与 SQL 形状（异步执行复用同一 `DebugService.recent`）。

## 3. 需求

- **A1 快查询不退化**：24h 窗 + 事件名类查询仍**单次往返**秒回，不引入轮询延迟；
- **A2 慢查询不占屏**：超过同步预算（默认 5s）的查询立即返回「已转后台」，用户可离开页面；
- **A3 结果可回看且与原语义一致**：后台结果写入同一条留档（含命中数、快照行、耗时），历史列表可见状态；
- **A4 失败可见**：后台失败写入 `status=failed` + 稳定错误码（前端按语言渲染），不再静默；
- **A5 不重复排队**：相同项目 + 相同条件 + 相同窗口的**待办/运行中**任务已存在时复用该任务（防双击/连点）；
- **A6 不泄漏资源**：串行执行（并发 1）、单任务预算 120s、卡死任务 10 分钟后判超时失败；
- **A7 窗口口径确定**：后台任务以**用户提交时刻**为准计算窗口（不因排队漂移）。

## 4. 验收标准

| 编号 | 判据 |
|---|---|
| AS-1 | 快查询（`event=fish_open` 24h）仍是一次请求返回结果，UI 无「已转后台」提示 |
| AS-2 | 慢查询（7 天 + 设备维度）在 ≤6s 内返回「已转后台」提示，页面可继续操作；结果完成后自动渲染 |
| AS-3 | 留档记录状态流转正确：`pending → running → done`；失败为 `failed` 且带错误码 |
| AS-4 | 后台结果与同步结果**逐值一致**（同条件同窗口跑两次对比） |
| AS-5 | 连点两次相同条件只产生 1 条任务 |
| AS-6 | `background_workers=false` 的进程（ingestor / 本地）不执行任务（日志与状态可见） |
| AS-7 | 卡死任务 10 分钟后被判 `failed(timeout)`，不永久占用队列 |
| AS-8 | 门禁全绿；新增文案补齐 13 语言 |

## 5. 风险

| 编号 | 风险 | 处置 |
|---|---|---|
| R-1 | 两段式把「超预算」判据交给 ClickHouse 的 `max_execution_time`（粒度不精确） | 用 CH 超时错误码（159/160）判定；文档写明「预算是近似值」 |
| R-2 | 后台任务与用户查询抢 CH 资源 | 串行 + 单任务 120s 预算；worker 与既有后台任务同门禁，便于整体关停 |
| R-3 | 留档表混入「任务」语义 | 显式加 `status/error_code/started_at/finished_at` 列并为历史数据默认 `done`（不迁移历史语义） |
| R-4 | 前端轮询放大请求 | 轮询间隔 2s、上限 2 分钟；列表仅在有未完成任务时轮询 |
| R-5 | 用户以为「转后台 = 结果丢了」 | 文案明确「完成后可在下方历史记录查看」，并在完成时就地渲染结果 |
