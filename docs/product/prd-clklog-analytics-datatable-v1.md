## 1. 阶段目标与范围

一句话：**让事件里的业务 ID 在分析结果里可读**；跨表维度（用维表字段做分组/筛选）留到 v2。

| 能力 | v1 | v2（Gate 0 之后另立 phase） |
|------|:--:|:--:|
| CSV 上传建表、列表、下载、清空、删除 | ✅ | |
| 增量更新 / 替换更新 | ✅ | |
| 关联属性：绑定「事件属性 / 事件名称 / 事件时间（粒度）」 | ✅ | |
| **结果里把 ID 显示成业务名**（表格/图例/CSV 导出） | ✅ | |
| 筛选下拉显示 `名称（ID）`（提交值仍是 ID） | ✅ | |
| 审计（方式 / 行数 / 操作人 / 时间） | ✅ | |
| 用维表字段**分组 / 筛选 / 聚合**（生成 `{属性}@{字段}` 维度表属性） | ❌ | ✅ |

**为什么这样分期**：v2 需要"查询期跨表取数"，而生产 ClickHouse 是 **23.2.1**，其查询能力（相关子查询 / 字典 / JOIN 改写）**尚未实测**；v1 因此收敛为**不依赖任何 ClickHouse 跨表能力**的做法——后端在拿到结果集后，用一次有界的 `IN` 查询把出现的 ID 换成业务名。用户诉求（"只有 ID，不知道是什么"）由 v1 完整覆盖，且风险最小。

## 2. 解决什么问题

### 2.1 主场景（v1 完整覆盖）

事件里上报 `item_info=10001`，分析结果、表格、导出里全是 `10001`，业务方要的是「精铁」。

**v1 之后**：`10001 → 精铁` 这条映射成为平台资产，一次配置，所有表格、图例、导出统一显示业务名。**历史数据同样可读**——映射发生在**结果装配阶段**，不改埋点、不补历史数据。

### 2.2 问题全景与分期

| 问题 | 今天怎么凑合 | 凑合不了的代价 | v1 | v2 |
|------|--------------|----------------|:--:|:--:|
| **ID 不可读**：结果只有 `10001` | 分析师对照 Excel 人肉翻译 | 每次查询翻译一遍，看板无法自助 | ✅ 显示映射 | |
| **口径分散**：多张卡片各写一份映射 | SQL 图里硬编码 `CASE WHEN` | 维表一改就要改 N 处；且我们的用户 SQL 白名单（只允许 `sa_events`/`sa_user_profiles`）**根本 JOIN 不了业务表** | ✅ 映射集中在一处 | |
| **按维表字段分组/筛选**（品质 / 资源 / 分类） | 改埋点把维度补进事件属性 | 要发版 + 埋点评审，**历史数据补不回来** | ❌ | ✅ |
| **静态维表数据不必重复上报** | 每条事件带一遍维表字段 | 流量与埋点维护成本 | ❌ | ✅ |

### 2.3 明确不解决的问题

1. **事件里没有可用主键就没法用**（商品 ID / 活动 ID / 事件名 / 事件时间至少有一个）。没有主键属于"该补埋点"。
2. **不是宽表 / 数仓导入通道**：单表上限 20 万行。
3. **不放开用户自定义 SQL 查维表**：白名单不变。
4. **v1 不支持"按业务名筛选"**：筛选项显示 `名称（ID）` 便于选择，提交值仍是 ID。
5. **不做独立的「维度字典」产品面**：值映射场景用一张两列数据表覆盖。

## 4. v1 功能规格

### 4.1 列表页

搜索：`搜索数据表名称/关联属性`。列：数据表名称、关联属性、创建方式（v1 固定「手动上传」）、行数、最后更新人、最后更新时间、操作（⚙ 配置关联属性 / ↑ 更新数据 / ⋮ 下载·清空数据表·删除数据表）。

空状态：`还没有数据表` + `创建数据表` + 说明「上传一张业务维表，把结果里的 ID 变成可读的名字」。

### 4.2 创建数据表（三步向导）

1. **上传数据表**：拖拽或点击上传 `UTF-8 编码的 CSV`；解析成功提示 `解析成功，你也可以重新上传`；展示字段命名规则（小写字母开头、仅小写字母/数字/下划线、≤50 字符、**第一列为主键**）；提供模板下载。
2. **确认表结构**：数据表名称（`^[a-z][a-z0-9_]{0,49}$`，项目内唯一）、备注（≤120 字）、字段表（字段名只读 / 数据类型下拉：**数值、文本、时间、布尔** / 显示名可填）；首列标「主键」，**主键类型保存后不可改**。
3. **数据预览**：`成功行数 N 行`、`丢弃行数 M`（M>0 可下载丢弃明细）；预览前 20 行；`保存` → `数据表创建成功`。

### 4.3 更新数据表

| 方式 | 语义 | 关键约束 |
|---|---|---|
| **增量更新**（默认） | 按主键匹配：已存在则更新，不存在则新增；文件里未出现的旧主键保持不动 | 表头与列顺序必须与当前结构完全一致，否则拒绝并提示差异 |
| **替换更新** | 用新数据整体替换 | 同上 |

- 预览显示 `新增 N 行 / 更新 M 行 / 丢弃 K 行`。
- 文件内同主键重复：**后行覆盖前行**，预览提示"有 X 个主键在文件内重复，已取最后一行"（数数取首行，此处刻意不同，见 §10）。
- **更新是"整版本替换"**：写新版本 → 校验 → 原子切换。**中途失败时线上仍是旧数据**，不会出现"表被清空"的窗口。
- v1 不支持字段增删与改类型（要改只能删表重建）。

### 4.4 配置关联属性

弹窗 `配置关联属性（数据表: xxx）`，顶部约束说明：

> 数据表 `test1` 的主键 `item_info` 为【文本】类型，只能关联数据类型为【文本】的属性。

- 一组绑定 = 选一个属性（`事件名称(#event_name)` / `事件时间(#event_time)` / 已登记的事件属性）。
- 选 `事件时间` 时需选**时间粒度**：年 / 月 / 日 / 小时 / 分钟 / 秒。
- 绑定后选择**展示字段**（该表除主键外的字段，可多选，默认第一个非主键字段）与显示名：结果里该属性的值展示为所选字段的值。
- 一张表最多绑定 5 个属性（与数数一致）；类型不匹配的属性在下拉里置灰并给原因。

### 4.5 结果映射展示（v1 的核心价值）

| 位置 | 行为 |
|---|---|
| 事件分析 / 漏斗 / 留存结果表 | 被绑定属性所在的列显示业务名；提供「显示原始值」开关；悬浮显示原值 |
| 图表 | 轴与图例使用业务名 |
| CSV 导出 | 同时输出「展示名」与「原始值」两列 |
| 筛选 / 分组下拉 | 显示 `名称（ID）`，**提交值仍是 ID** |
| 保存的卡片 / 看板 | DSL 未变，映射自动生效；数据表更新后缓存失效、下次刷新即为新名 |

未命中（ID 不在表里）：**显示原值**，不显示空、不伪造；一次查询里映射量超上限时跳过映射并在页面上提示。

### 4.6 清空 / 删除 / 下载与影响面

| 动作 | 行为 |
|---|---|
| 下载 | 导出当前生效版本为 UTF-8 CSV |
| 清空数据表 | 保留表结构与绑定；二次确认写明行数；结果里全部回落到原始值 |
| 删除数据表 | 二次确认 + **影响面清单**（引用的卡片/看板数量）；删除后绑定进入 `invalid`，相关位置显示原值并提示「该属性依赖的数据表已删除」——**不静默回退、不静默消失** |

## 5. 文案与错误提示

| 场景 | 文案 |
|---|---|
| 表名非法 | `数据表名称只能以小写字母开头，包含小写字母、数字、下划线，最长 50 个字符` |
| 表名重复 | `项目内已存在同名数据表` |
| 表头不一致 | `表头与当前表结构不一致：缺少 xxx，多出 yyy` |
| 主键为空 / 类型不符 | `第 12 行的主键为空，已丢弃` / `第 8 行字段 quantity 不是数值，已丢弃`（可下载明细） |
| 超限 | `单表最多 20 万行，本次更新后为 23 万行，请拆分或精简` |
| 类型不匹配 | `属性 item_info 为【数值】类型，无法关联主键为【文本】的数据表` |
| 正在导入 | `该数据表正在更新中，请稍后再试` |
| 映射超上限 | `本次结果中待映射的值过多（超过 5 万），已跳过映射展示` |
| 删除时被引用 | `有 3 张卡片在使用该数据表的映射，删除后这些卡片将显示原始值` |

## 6. 规则与限额

### 6.1 字段类型与主键

- 类型：数值 / 文本 / 时间 / 布尔（内部词表 `number|string|datetime|boolean`）。
- 主键：**永远是第一列**，单主键，不可为空，类型创建后不可改；主键值在文件内重复取最后一行。

### 6.2 可关联范围

| 主键声明类型 | 可关联 |
|---|---|
| 文本 | 事件属性（文本）、事件名称 |
| 数值 | 事件属性（数值） |
| 时间 | 事件时间（需选粒度）；**普通时间属性绑定 v1 不支持**（上报时间字符串格式不受控，无法保证两侧一致） |
| 布尔 | 事件属性（布尔） |

不可关联：已绑定的属性（不嵌套）、虚拟属性、对象/列表类型属性、用户属性（v1 非目标）。

### 6.3 限额

| 项 | 上限 |
|---|---|
| 单次上传文件 | ≤ 10 MB（沿用现有"前端读文本 POST"通道） |
| 单表行数 | ≤ 200,000（按**更新后**去重总行数校验，不是按上传文件行数） |
| 单表列数 | ≤ 50 |
| 项目内数据表数 | ≤ 50 |
| 单表绑定数 | ≤ 5 |
| 单字段值长度 | ≤ 1024 字符 |
| 单次结果映射值数 | ≤ 50,000（分批 1000/次） |

### 6.4 审计

每次创建/更新/清空/删除留一条记录：方式、起止版本、成功与丢弃行数、结果、操作人、时间；表详情可查、可导出。

## 7. 与现有能力的边界

| 现有能力 | 区别 |
|---|---|
| 虚拟属性 | 做**同行内值加工**（表达式）；数据表做**跨表查表**。v1 两者不嵌套 |
| 物化列 | 解决"JSON 属性查询慢"；数据表解决"结果不可读/维度不在事件里" |
| 埋点属性登记 | 登记"上报过的属性"；数据表产出的是**映射/展示**，列表来源标记不同 |
| 自定义 SQL | 白名单不变；用户仍无法直接查维表 |
| 用户分群 / 标签 | 圈用户集合；数据表只做 ID → 业务名，不产生集合 |

## 8. 验收标准

v1（可核对）。状态以本表为准，不把「页面能打开」当成通过。

| 项 | 要求 | 2026-09-15 状态 |
|---|---|---|
| **A1** | 绑定后自选展示字段；结果列显示业务名；「显示原始值」开关 | **本轮交付**：展示列可落库；表头可切原始值。多展示字段仍不做（v1 单列） |
| **A2** | 分析 CSV 同时含展示名与原始值 | **本轮交付**（事件/漏斗/留存结果导出） |
| **A3** | 筛选下拉 `名称（ID）`，提交仍是 ID | **本轮交付**（已绑定属性的等于/列表类算子） |
| **A4** | 未命中显示原 ID，页面不报错 | **已交付**（生产 17134：命中分母含未命中） |
| **A5 / A6** | 增量 / 替换更新预览与生效 | **部分**：有入口；本轮补表头/类型强校验。预览行增减计数仍粗 |
| **A7** | 更新失败线上仍是旧映射 | **本轮交付**（租约 + CAS；发布后审计失败不删生效版本）；单测覆盖 |
| **A8** | 表头不一致拒绝 | **本轮交付**（名、序、类型以已保存结构为准） |
| **A9** | 绑定事件时间粒度 | **未交付**（绑定 UI 有粒度，查询映射未按粒度造数验收） |
| **A10** | 类型不匹配置灰 + 接口可读错误 | **部分**：下拉置灰；接口仍不强制拒绑 |
| **A11** | 删除给影响面，失效不静默 | **未交付**（`referenced_cards` 仍为 0） |
| **A12** | 无 `meta.edit` 看不到写入口，接口 403 | **部分**：后端有装饰器；前端仍露出编辑入口 |
| **A13** | 审计可查；超限拒绝 | **部分**：最近 20 条审计；50 表 / 5 绑定服务端未强制 |

v2（另立 phase，前置 Gate 0）：按维表字段分组/筛选/聚合、`{属性}@{字段}` 维度表属性、三类分析回归。

### 8.1 已接受的实现偏离（相对原稿，不回退）

| 原稿 | 实际 | 原因 |
|---|---|---|
| 只接受 CSV | 前端可把 Excel 转成 CSV 再上传 | 运营表常是 xlsx；服务端契约仍是 CSV 文本 |
| 主键永远第一列且即 join 键 | 主键仍是首列；join 键绑定时可另选 | 商品表首列是自增 `id`，业务键在 `goods_id` |
| 展示字段可多选 | v1 **单展示列**，绑定里显式选择 | 结果列是「一列换业务名」，多字段属于 v2 |
| 映射 `pk IN` 分批 | 读生效版本快照后按 join 键匹配 | 键列不一定是 CH `pk`（首列）；超 5 万取值跳过映射并提示 |
