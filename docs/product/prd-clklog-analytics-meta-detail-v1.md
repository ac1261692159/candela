## 1. 阶段目标与范围

把事件属性、用户属性、虚拟事件的改写从列表行内操作收进详情：列表只展示，详情里编辑，点「保存」才落库；关抽屉不保存。虚拟事件删除只出现在详情里。用户属性补详情入口，并在界面上说明「物化」含义。

| 模块 | 本次做什么 |
|------|------------|
| 事件属性面板 | 去掉列表「编辑」；备注只读展示；详情内改显示名/类型/备注，底部「保存」 |
| 用户属性 | 列表增加「详情」；显示名不再行内失焦保存；详情内编辑后点保存；物化含义可理解 |
| 虚拟事件 | 列表去掉「删除」；「编辑」改为「详情」（仍是原编辑界面）；删除放在详情里 |

## 2. 验收标准

- [ ] MD-1：事件属性列表无「编辑」按钮；备注列为文字（空为 —）；点「详情」或关联事件数打开抽屉。
- [ ] MD-2：事件属性详情可改显示名、全局数据类型、全局备注；不点「保存」关闭抽屉后，再打开仍是原值。
- [ ] MD-3：点「保存」后列表与再次打开的详情均显示新值。
- [ ] MD-4：用户属性列表显示名为只读文字；操作列为「详情」。
- [ ] MD-5：用户属性详情可改显示名；不点保存关闭则不落库；点保存后列表更新。
- [ ] MD-6：「已物化」列或详情内有说明：物化 = 把 JSON 属性抽成 ClickHouse 独立列以加速查询；本期点物化只生成 DDL、不自动改表。
- [ ] MD-7：虚拟事件列表无「删除」；操作为「详情」。新增仍走独立入口。
- [ ] MD-8：虚拟事件详情含原编辑表单与「保存」；已有记录另有「删除」；删除需确认，确认后列表不再出现该条。

## 3. 非目标

- 不改元事件列表/事件详情抽屉的保存方式。
- 不改事件详情里「事件属性」Tab 的行内显示名（仍用现有 PropertyList）。
- 不实现 M8 自动 ALTER TABLE。
- 不改虚拟事件 SQL 展开语义。

## 4. 体验

### 4.1 共同规则

列表不出现常驻输入框来改写字段。详情用抽屉。底部主操作为「保存」；「取消」或点遮罩关闭 = 丢弃未保存修改。删除是破坏性操作，只放在详情并二次确认。

### 4.2 物化（给用户看的含义）

上报属性默认存在事件 `properties` JSON 里，分析时每次解析。物化是给该属性加一列 ClickHouse 物化列（`p_` 前缀），查询走列而不是 JSON。列表「已物化」表示元数据是否已标记；按钮「物化」本期只预览/提交 DDL，不会立刻改社区版表。

### 4.3 事件属性

操作列只留「详情」。备注列展示已保存文字。

### 4.4 用户属性

与事件属性同一套「详情 + 保存」。物化说明见 §4.2，放在列标题问号或详情文案，不新造术语。

### 4.5 虚拟事件

列表「详情」打开与原「编辑」相同的规则+基本信息表单。删除按钮在详情底部（保存旁边），确认后调用现有删除接口。
