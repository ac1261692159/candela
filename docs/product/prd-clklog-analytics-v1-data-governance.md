# PRD：ClkLog 分析平台 — 数据治理（一致性对拍 + 敏感数据清洗）

> phase: clklog-analytics-data-governance
> 版本：v1.0（2026-08-26）｜ 上游：`docs/architecture/analytics-extension-plan.md`、`docs/architecture/clklog-analytics-design.md`
> 下游：`docs/architecture/clklog-analytics-design-data-governance.md`
> 对标：神策分析数据治理、常规合规数据保留/删除实践

---

## 1. 阶段目标与范围（门禁要素①）

本阶段解决分析平台**数据质量与合规**两大问题，分两条主线：

| 主线 | 解决的问题 | 交付形态 |
|------|-----------|---------|
| **数据一致性对拍** | ingestor 静默丢数据/停转/重复无法及时发现，分析结果可信度无兜底 | 只读对拍工具（CLI + 定时任务） |
| **敏感数据清洗** | 合规要求下删除/掩码特定用户或事件数据（仅限旁路库 `clklog_sa`） | 清洗规则引擎（带备份/审计/演练） |

范围界定：

- **对拍**：只读比对 `clklog_sa.sa_events` 与社区版 `clklog.log_analysis`，分粗粒度（计数对拍）与细粒度（CRC 级字段对拍）两级；可定时、可手动。
- **清洗**：仅作用于旁路扩展库 `clklog_sa`（`sa_events` / `sa_user_profiles`），删除或掩码敏感数据；**绝不触碰社区版 `clklog.log_analysis` 及 19 张聚合表**（红线）。

## 2. 验收标准（门禁要素②）

- [ ] **G-R1（对拍）**：`reconcile.sh` 可对指定时间范围执行粗粒度计数对拍，输出 `sa_events` vs `log_analysis` 各事件行数差异表；计数偏差超过阈值（默认 0.1%）时以非零退出码报警。
- [ ] **G-R2（对拍）**：支持细粒度 CRC 抽样对拍，确认字段级一致（抽样率可配置）。
- [ ] **G-R3（对拍）**：对拍工具**只读**，不写任何库表；对社区版 `clklog` 库仅 `SELECT`（且仅读取 `log_analysis` 需要的列）。
- [x] **G-C1（清洗）**：支持按 `distinct_id` / `user_key` / 事件范围删除 `sa_events` 数据；删除前自动生成**全量备份表 + 审计记录**。
- [x] **G-C2（清洗）**：支持敏感字段掩码（如手机号/邮箱/身份证在 `properties` JSON 中替换为占位符），掩码幂等可重放。
- [x] **G-C3（清洗）**：所有清洗 DDL/DML 先在测试库 `clklog_sa_staging` 演练，演练通过才允许作用于生产库。
- [x] **G-C4（红线）**：清洗命令**硬拒绝**任何针对 `clklog`（社区版）库的写入/删除/DDL。
- [x] **G-S1（安全）**：清洗使用独立写账号，仅授予 `clklog_sa` 库必要权限；凭据走环境变量，不入库。

> **验收记录（2026-09-15，生产 17185）**：见 `docs/project/acceptance-clklog-analytics-v1-data-governance.md`。
> 清洗主线已实现并线上验收（4 次真实执行 + 1 次门禁阻断）。
> ⚠️ **边界**：清洗只作用于旁路库 `clklog_sa`；社区版 `clklog.log_analysis` 内的同一份数据清不到（红线 1 禁止改造社区版）——若合规要求「彻底删除」，需产品/法务单独决策。

## 3. 非目标（门禁要素③）

- 不做 ID-Mapping 离线刷数（匿名 `distinct_id` ↔ 登录 `user_key` 归并仍为运行时口径，见 `clklog-analytics-design.md` §5.3）。
- 不做脏数据字段自动修复（如属性类型错乱、时间戳格式修正）——本期只做**删除/掩码**两类合规清洗，字段修复后续 phase。
- 不做全量行级 CRC 对拍（数据量大成本高），只做计数对拍 + 抽样细对拍。
- 不对社区版 `clklog` 库做任何清洗（红线，不可触碰）。
- 不做清洗任务调度 UI 管理界面（本期 CLI + 定时任务即可）。

## 4. 数据一致性对拍

### 4.1 目标

建立分析平台数据质量**主动兜底**能力，及时发现 ingestor 异常导致的丢数据/停转/重复，避免脏数据进入分析结果。

### 4.2 对拍维度

| 编号 | 对拍项 | 口径 | 说明 |
|------|--------|------|------|
| R-1 | 总量对拍 | `sa_events` 行数 vs `log_analysis` 非空 event 行数 | 全库/按 `stat_date` 分桶 |
| R-2 | 按事件对拍 | `sa_events.group by event` vs `log_analysis.group by event` | 单事件数差异定位 |
| R-3 | CRC 唯一性 | `count() vs count(DISTINCT crc)` 在 `sa_events` | 重复行检测（ReplacingMergeTree 未 merge 时可见） |
| R-4 | 抽样细对拍 | 抽样 N 条，比对两表同 CRC 事件的 `distinct_id`/`event`/`log_time` 一致 | 字段级可信 |

> `log_analysis` 无 `crc` 列，R-4 需用 `distinct_id + event + log_time` 拼接作为伪键抽样比对（`log_analysis` 仅读取，不做任何修改）。

### 4.3 触发方式

- **定时**：cron / supervisor，默认每小时粗对拍一次、每日抽样细对拍一次。
- **手动**：`reconcile.sh --from=... --to=...` 指定时间范围即时执行。

### 4.4 输出

- 差异表（TSV/Markdown）：时间范围、各事件行数、偏差百分比。
- 退出码：偏差超阈值 → 非零；正常 → 零。便于 cron 感知告警。
- 报告落本地 `logs/reconcile/reconcile-{ts}.txt`，保留 N 份。

## 5. 敏感数据清洗（删除 / 掩码）

### 5.1 目标

满足合规要求：在需要时删除或掩码特定用户/事件在**旁路库**中的敏感数据。范围仅限 `clklog_sa.sa_events` 与 `clklog_sa.sa_user_profiles`。

### 5.2 清洗类型

| 类型 | 动作 | 目标对象 | 示例 |
|------|------|---------|------|
| **按用户删除** | 删除指定 `distinct_id` / `user_key` 的全部事件与画像 | `sa_events`、`sa_user_profiles` | 用户行使「被遗忘权」/注销 |
| **按事件删除** | 删除指定事件名、或指定筛选条件的行 | `sa_events` | 误埋点事件清理 |
| **按时间删除** | 删除某时间段前的数据 | `sa_events`（配合 TTL） | 合规保留期到期 |
| **字段掩码** | 将 `properties` JSON 内敏感字段值替换为占位符 | `sa_events.properties`、`sa_user_profiles.properties` | 手机号→`138****0000`，邮箱→`a***@x.com`，身份证→`***` |

### 5.3 清洗流程（强制门禁）

所有清洗必须走以下流程，缺一不可：

```
① 测试库演练（clklog_sa_staging） → ② 备份（clklog_sa_bak 快照表） → ③ 审计记录 → ④ 生产执行 → ⑤ 对拍确认
```

| 步骤 | 动作 | 产出 |
|------|------|------|
| ① 演练 | 在 `clklog_sa_staging` 重建受影响表结构，先跑清洗 SQL 验证影响行数与预期一致 | 演练报告 |
| ② 备份 | 生产执行前，将受影响行 `INSERT ... SELECT` 到 `clklog_sa_bak` 对应快照表，含清洗时间戳 | 快照表 |
| ③ 审计 | 记录操作人、时间、清洗规则、影响行数、备份表名到审计表 | 审计记录 |
| ④ 执行 | 生产库执行删除/掩码（按规则生成 DDL/DML） | 变更记录 |
| ⑤ 确认 | 复用对拍工具确认清洗后数据符合预期 | 对拍报告 |

### 5.4 红线约束（不可违反）

- 清洗命令**硬拒绝**任何指向 `clklog`（社区版）库的写/删/DDL——白名单只允许 `clklog_sa*` 库。
- 删除/掩码前必须已有备份与审计记录（红线 6）。
- 清洗用独立写账号，只授予必要库权限（红线 3 凭据参数化）。

### 5.5 掩码规则（示例）

| 敏感字段 | 掩码规则 |
|---------|---------|
| `phone` / `mobile` | 保留前 3 后 4，中间 `****` |
| `email` | 保留域名，本地部分掩码 |
| `id_card` / `identity_no` | 全掩码 `***` |
| `address` | 保留省级，后续掩码 |

> 字段清单以项目合规登记为准（后续可扩展，本次 PRD 先定机制与示例）。

## 6. 用例清单

### 6.1 对拍用例（G-R）

| 编号 | 前置 | 步骤 | 期望 |
|------|------|------|------|
| GR-1 | 有数据 | 跑 `reconcile.sh --to=今日` | 输出差异表，偏差 < 0.1% 退出码 0 |
| GR-2 | 造入 N 条不入 `sa_events` 的假数据 | 同 GR-1 | 偏差超阈值，退出码非零，报告含差异 |
| GR-3 | 造入重复 CRC 行 | 跑 CRC 唯一性检查 | 检出重复，报告标注 |
| GR-4 | — | 跑抽样细对拍 | 抽样行字段一致，输出一致率 |

### 6.2 清洗用例（G-C）

| 编号 | 前置 | 步骤 | 期望 |
|------|------|------|------|
| GC-1 | 测试库演练通过 | 按 `distinct_id` 删除 `sa_events` | 受影响行已备份到 `clklog_sa_bak`，原表该用户事件清零，审计有记录 |
| GC-2 | 演练通过 | 掩码 `sa_user_profiles.properties.phone` | 该字段值变为 `138****0000`，可重放不重复掩码 |
| GC-3 | 演练通过 | 尝试对 `clklog.log_analysis` 执行删除 | 命令被硬拒绝，非零退出，无任何写入 |
| GC-4 | — | 未做演练直接执行生产清洗 | 被门禁阻止，提示先演练 |

## 7. 风险与依赖

- **对拍口径差异**：`log_analysis` 无 `crc`，细对拍需伪键，存在极小概率误匹配；用抽样 + 统计口径兜底。
- **清洗不可逆**：依赖备份表 + 审计，任何删除都有快照可回滚。
- **社区版升级**：`log_analysis` 列名可能变化，对拍 SQL 需做列存在性容错；不改其结构（红线）。
- **依赖**：对拍复用现有 CK 只读连接；清洗需新增 `clklog_sa` 写账号（Puppet 参数化）。
