## 1. 阶段目标与范围

「指标单位不一致」这条判定写在双轴之前，判的是**整张图所有指标是否同一个单位**。双轴引入后这个假设失效了，于是出现两个洞：

1. **跨轴不同单位被误报**：左轴人民币、右轴百分比是双轴最典型的正确用法，现在照样报「指标单位不一致，不能放在同一数值轴」。自动模式下它是 `error`，意味着这种合法配置可能直接不出图。
2. **同轴确实混单位时只是警告，而且画出来的刻度会张冠李戴**：轴刻度单位取「该轴第一个指标」（`line.adapter.ts` / `trend.adapter.ts` 的 `unitOfKey(leftKeys[0])`），于是同一根轴上第二个指标的真实量纲被套上了第一个指标的装饰——把计数标成 `4,730%`。

本期把判定改成**按轴**，并让混单位这件事在图上和面板上都有明确出路。

| 模块 | 本次做什么 |
|------|------------|
| 判定 | 按轴分组判单位：同一根轴内不一致才报；跨轴不一致不报。柱状/条形没有双轴，维持整图判定 |
| 渲染 | 某根轴确实混单位时，该轴刻度退化为纯数字（不做货币/百分比/时长装饰），各系列的单位交给悬停提示按系列给出——宁可无装饰，不可套错量纲 |
| 操作 | 字段设置里给一个「按单位拆轴」：把不同单位的指标自动分到左右两轴（SQL 与事件两侧共用同一面板） |
| Harness | 能力自述补上单位词表（现在只有 `options.units` 这个名字，模型不知道有哪些合法值，猜错直接 400）与「同一根轴必须同单位，否则用分轴拆开」的规则；工具描述与 Workspace 规范同步 |

## 2. 用户流程

1. 分析师在字段设置里给「消耗总量」选了「百分比 (0–100)」，而它与两个「数值」指标同在左轴。
2. 图旁边出现一条说清位置的提示：**同一根轴（左轴）上的指标单位不一致：消耗均值_人均（数值）、消耗总量（百分比）**，并带上「按单位拆轴」按钮。
3. 点「按单位拆轴」：系统比较两种朝向、**只搬动必须搬的指标**（本例只把人称搬到右轴），使两根轴各只剩一种单位，提示消失。
4. 若不点：图照常画（手动配置不阻断），但该轴刻度只显示数字，不再把百分号套到计数上；悬停时每条线各自带自己的单位。

## 3. 验收标准

- [ ] **SC-1（按轴判定）**：`line` / `trend` 中，指标分别落在左右两轴且两轴单位不同时**不报**混单位；同一根轴内出现两种单位时**报**，且提示带轴名与涉及的指标名。
- [ ] **SC-2（柱状不变）**：`bar` 没有双轴，全部指标共用一个刻度，维持整图判定与既有行为。
- [ ] **SC-3（刻度不张冠李戴）**：某根轴混单位时，该轴刻度不出现任何单位装饰（货币符号、百分号、时长、字节）；该轴只有一个单位时，刻度格式与改动前**逐字节一致**。
- [ ] **SC-4（一键拆轴）**：字段设置里的「按单位拆轴」把指标按单位分组落到左右轴；执行后若每根轴都只剩一种单位，提示消失。多于两组单位时，占比最大的一组留左轴，其余进右轴，并如实保留剩余提示。
- [ ] **SC-5（两侧可用）**：自定义 SQL 与事件分析都能用这条路径（同一面板组件，两页行为一致）。
- [ ] **SC-6（Harness 可改）**：能力自述含合法单位词表与「同一根轴必须同单位」规则；模型能在**一次**提案里同时给 `options.units` 与 `options.metric_axis`，把混单位状态改成合法状态并在页面上生效。
- [ ] **SC-7（门禁与回归）**：新增/改动单测通过；前端既有图表用例不回归；`python3 scripts/arch_ratchet.py`、`python3 scripts/i18n_check.py`、`python3 scripts/i18n_scan.py --check` 通过。

## 4. 非目标

- 不做自动改单位：平台不猜用户的数据量纲，只判定与建议。
- 不改单位本身的格式化规则（百分比缩放、货币符号、SI/IEC 进制）与 `MetricUnit` 枚举。
- 不把混单位升级为阻断：手动配置的画照画（与既有「单位改完立刻生效」一致），只把话说清楚并给出路。
- 不做「>2 种单位」的自动三分轴：双轴只有两根轴，超过两组时如实保留提示。
- 不改量级断崖建议（`axis-suggest`）：那是按数值分布建议，与本期按单位建议是两套规则，各自独立。
