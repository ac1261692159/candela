# 调研：成员生命周期与账号体系（GitLab / Grafana / Metabase 对标 + 现状缺陷清单）

> 产品帽。2026-09-17。依据 GitLab 官方文档（Self-Managed 用户管理）、Grafana / Metabase 私有化部署通行做法、OWASP / NIST 账号安全基线，以及本仓库现网实现逐行核实结果。
> 只记他们有什么、我们有什么、差在哪、该选哪条改进路径。不排期、不写接口、不改实现。
> 上游触发：现「创建成员」只能填用户名+密码（+可选显示名），无邮箱/手机、无修改密码、无邀请与找回。
> 关联：`research-clklog-analytics-rbac.md`（项目角色模型，已完成）；`prd-clklog-analytics-user-rbac-v1.md` / `prd-clklog-analytics-rbac-v2.md`（两者的非目标条款里明确缓建了本文大部分能力）。

## 1. 范围界定：账号生命周期

把「成员管理」拆成五段生命周期，逐段对标：

| 段 | 问题 | 典型动作 |
|----|------|----------|
| 建号 | 这个人怎么获得平台账号 | 管理员代建 / 邀请注册 / 自助注册+审批 |
| 资料 | 账号携带哪些身份信息 | 用户名、邮箱、手机、显示名、头像 |
| 入会 | 他怎么进入某个项目 | 项目成员绑定 + 角色 + 有效期 |
| 在用 | 登录、改密、找回、安全防护 | 密码强度、失败锁定、会话管理、审计 |
| 退出 | 停权、删除、数据交接 | 禁用、删除、资产转移 |

RBAC v2 已解决「入会」里的角色与数据权限（`research-clklog-analytics-rbac.md`）。本报告聚焦其未覆盖的部分：**建号、资料、密码与找回、邀请、停用/删除、审计**。

## 2. 主流方案对标

### 2.1 GitLab（Self-Managed，本次主对标）

GitLab 是私有化部署产品里账号体系最完整的参照，核心设计：**管理员不需要知道、也不应该经手用户的密码**。

**建号（Admin → Users → New user）**
- 必填三件套：`username` / `email` / `name`（显示名），邮箱是主身份标识之一，全局唯一。
- 密码两种投放方式：
  - **默认：系统向该邮箱发登录/重置链接，用户首次登录自行设密码**——管理员全程不见明文；
  - 可选：管理员直接代设密码。
- 管理侧可 `skip_confirmation`（跳过邮箱确认直接激活），也可不发确认则用户收验证邮件、确认后才完全激活。

**自助注册 + 审批**
- 自助注册默认开启（"Register now"）；管理员可开 **Require administrator approval**：新注册账号进入 `pending approval` 态，功能上等同被封禁——不能登录、不占席位，管理员批准后激活（或拒绝并删除）。

**账号状态机（Admin → Moderate users）**
- `active` / `pending approval` / `blocked`（禁止登录与访问，**数据保留**，用于停权）/ `deactivated`（≥90 天不活跃自动停用，登录即自动恢复，用于回收休眠席位）/ `banned`（连其贡献内容一起隐藏，用于反垃圾）/ `trusted`。
- 封锁/封禁后立即不可登录；另有 **failed login attempts 锁定**（Locked user accounts，管理员可解锁）。

**项目/群组成员邀请**
- 添加成员支持**按用户名**或**直接输入邮箱地址**：
  - 邮箱已注册 → 直接成为成员，收到通知邮件；
  - 邮箱未注册 → 收到**邀请邮件 + 注册链接**，注册落地即入组。
- 邀请时可指定**角色**与**有效期（access expiration date）**，到期成员资格自动失效（外部协作场景刚需）。

**密码生命周期**
- 用户自助：登录页 "Forgot password" → 邮件重置链接（一次性、有时效）。
- 管理员：**UI 一键向用户发重置密码邮件**，或 console/Rake 代处理。
- 改密需验证当前密码。

**审计**
- Admin Area 有独立 Audit Events：用户创建/封禁、成员增删改、权限变更全部留痕，可过滤可导出。

### 2.2 Grafana / Metabase（私有化分析类产品的轻量参照）

| 能力 | Grafana | Metabase |
|------|---------|----------|
| 建号 | Admin 建号填 name/email/username，**或不设密码发邀请邮件**；SMTP 配好后可发 "invite" | Admin 建号 name/email，可切 "send password setup email"，不设密码则用户自行激活 |
| 组织/成员 | Org + Team，邮箱邀请入 Org | Group → 数据/集合权限 |
| 找回 | "Forgot password" 邮件链接 | 同左 |
| 状态 | 可禁用；登录失败可配锁定 | 可停用（deactivate，数据保留） |

教训共同点：**邮箱是所有账号运维动作的前置条件**；私有部署第一步就是配 SMTP，之后建号/邀请/找回全部走邮件自助，管理员不再当中转站。

### 2.3 神策 / 数数（业务对标对象）

`research-clklog-analytics-rbac.md` 与 gap 文档 §10 已对标其**项目角色与数据权限**，本报告不重复。账号生命周期侧补充其私有部署共性：不开自助注册，账号由超管/管理员在系统管理侧建立，项目成员从已有账号中选取——**与我们现状同构，即这一步我们与神策齐平，不落后也不领先**；本节对标的安全与自助化能力（找回、邀请、锁定、审计）属于 GitLab/Grafana 一档的通用平台基线，神策公开文档粒度不足以核对，不臆造。

### 2.4 安全基线（OWASP ASVS / NIST SP 800-63B 通行结论）

- **密码**：最低 8 位；对常见/已泄露口令做黑名单；不强制复杂度种类、不强制定期换密（NIST 明确反对形式主义策略）。
- **登录防护**：失败错误文案统一（防枚举）；失败计数 + 锁定或指数退避；入口限流。
- **重置令牌**：高强度随机（≥32 字节）、一次性、短时效（30–60 分钟）、使用后即毁、重置成功吊销全部会话。
- **改密**：必须验旧密码；改密后吊销其他会话。
- **会话**：绝对有效期 + 空闲失效；禁用/降权立即生效。

## 3. 我们的现状（现网逐行核实）

> 证据为 `apps/analytics-server` / `apps/analytics-web` 当前代码，行号截至 2026-09-17。

### 3.1 数据模型（`prisma/schema.prisma`）

- `SaUser`(:343-362)：`username @unique` + `password_hash` + `display_name?` + `platform_role(super_admin|none)` + `status(active|disabled)` + `default_project` / `locale` / `timezone`。
- **没有的列**：`email`、`phone`、`avatar`、`created_by`、`last_login_at`、失败计数类字段。无任何预留。
- `SaUserToken`(:448-458)：DB token，`expires_at = 登录+7天`（`auth.service.ts:24`），无刷新。

### 3.2 建号与资料

- 创建用户 `POST /sa/api/auth/users`（`auth.controller.ts:63-67`，权限 `ops.user.manage`），入参**只有** `{ username, password, display_name? }`（`auth.service.ts:200-208`），密码仅校验 ≥6 位；创建后 `platform_role` 固定 `none`(:222)。
- 前端入口在运维侧 `ProjectOwnersPage.tsx:162-194`（用户名/显示名/密码三项）。
- **不存在**：编辑用户资料、管理员改他人密码、删除用户、查询用户详情；`platform_role` 超管授予无 API（只能改库）。
- 用户自助：ProfilePage 可改语言/默认项目/时区/密码（验旧密，`auth.service.ts:180-195`）✓；不能改显示名。

### 3.3 登录安全

- 已符合基线：scrypt + `timingSafeEqual`（`password.util.ts:7-19`）；登录失败 401 文案统一不区分账号/密码错（`auth.service.ts:35-66`）；改密吊销其他会话(:193-195)；禁用即吊销全部 token(:240-242)。
- **缺失**：登录无失败计数、无锁定、无验证码、无任何限流（全仓无 Throttler）——可对任意账号无限爆破。
- token 存浏览器 localStorage（`auth.store.ts`），7 天硬过期、无滑动续期（P1 设计取舍，`design-user-rbac.md:78`）。

### 3.4 状态与退出

- 后端已有 `PUT /auth/users/:id/status` 启用/禁用（`auth.controller.ts:69-82`），**前端零调用**，无入口。
- 无删除用户；无成员有效期；无休眠回收；无资产交接（v1 PRD 明列 P2/P3）。

### 3.5 项目成员加入

- `MembersPage.tsx` 添加成员 = **下拉选已有登录用户** + 角色（:119-131），符合 rbac-v2 PRD「无邀请链接」的既定取舍（PRD §3）。
- 新人要两步走：超管先在「运维→项目设置」页建号，owner 再到项目成员管理添加，两处页面、两种权限码。

### 3.6 审计

- 登录、登出、建号、改密、禁用、成员增删改**全部不落审计**；`OpsActionLog` 目前仅告警与运维数据管理使用。v1 PRD 明列「不做审计（P2/P3）」，属已决策的缓建，非疏漏。

### 3.7 邮件通道基础

- SMTP 配置与发送器**已存在但只服务告警**（`configuration.ts:86-105` 的 `ALERT_SMTP_*` + `alerting/channels/sender-email.ts`）。账号体系复用该模式（独立配置组）无技术障碍，但**现状账号域与邮件域零耦合**——这是找回/邀请做不了的根本原因（没有 email 字段）。

### 3.8 文档漂移

- `clklog-analytics-design-user-rbac.md:21,70` 写密码用 bcrypt，实现已是 scrypt——设计文档未回写，后续做密码策略时对不上号。

## 4. 差距清单（他们 vs 我们）

| # | 能力 | GitLab / Grafana / Metabase | 我们 | 性质 |
|---|------|------------------------------|------|------|
| 1 | 邮箱作为账号资料 | 必填、唯一、可验证 | **无该列** | 结构性缺口（前置） |
| 2 | 手机号 | 一般无（私有化产品普遍以邮箱为准） | 无 | 可降级为不做 |
| 3 | 管理员建号默认发「自行设密」邮件 | GitLab 默认行为 | 管理员代设明文密码、线下传递 | 流程缺口 |
| 4 | 忘记密码（邮件重置链接） | 全有 | **无**；忘密只能进库改 hash | 流程缺口 |
| 5 | 管理员重置他人密码 | UI 一发重置邮件 | 无 | 流程缺口 |
| 6 | 编辑用户资料 / 显示名 | 有 | 无（用户自己也不能改显示名） | 功能缺口 |
| 7 | 禁用/启用入口 | 有 | 后端已有、前端无入口 | 半成（最小成本项） |
| 8 | 删除用户 + 资产交接 | 有（保留/转移贡献） | 无删除 | 流程缺口 |
| 9 | 项目邀请（按邮箱，未注册→注册链接） | GitLab 核心流程 | 只能选已有账号 | 协作缺口 |
| 10 | 成员有效期（到期自动失效） | GitLab 有 | 无 | 协作缺口 |
| 11 | 登录失败锁定 / 限流 | GitLab 有；OWASP 基线 | **无任何防护** | **安全缺口** |
| 12 | 密码强度（≥8 + 弱口令黑名单） | 基线 | 仅 ≥6 | 安全缺口 |
| 13 | 账号状态机 | 6 态 | 2 态（active/disabled） | 够用差距 |
| 14 | 认证与成员变更审计 | GitLab Admin Audit Events | 零落库 | 合规缺口 |
| 15 | 邮箱验证（confirmable） | GitLab 有 | 无（无邮箱） | 随 #1 解锁 |
| 16 | 自助注册 + 审批 | GitLab 可开关 | 无（私有化一般关自助注册，可选不做） | 可选项 |
| 17 | 会话管理页（看/踢会话） | GitLab 有 | 无（只有改密/禁用时连带吊销） | 次要 |
| 18 | SSO / LDAP / OIDC | 各家高档位 | 无；既有 PRD 持续列为非目标 | 维持非目标 |

**已符合基线、无需动的**：登录错误文案防枚举、scrypt+恒定时间比较、改密验旧密、改密/禁用吊销会话、token 7 天绝对过期、RBAC 权限目录与项目角色（rbac-v2）。

## 5. 改进路径建议（选项与取舍，不排期）

按依赖关系分三段，段内条目独立可拆。**前置洞察：#1 邮箱列是全图的钥匙**——没有它，找回/邀请/验证/通知都无法起步；而邮箱列本身不依赖任何外部通道，可先落。

### 第一段：不依赖邮件通道即可交付（纯后端 + 前端表单）

1. `SaUser` 增加 `email`（可空→逐步必填、唯一、格式校验）、`last_login_at`、`created_by`；用户自助与管理员可编辑显示名。
2. 管理员侧用户管理页：列表 + 创建（含 email） + 编辑 + **启用/禁用（接通既有 API）** + 重置密码 + 删除（软删为先，资产归属策略随删除一并定义，呼应 v1 PRD 的 P2「资产移交」）。
3. 密码策略：`≥8 位 + 弱口令黑名单`；管理员代设密码标记「首次登录须改密」。
4. **登录失败锁定**：按账号计数（如 5 次锁 15 分钟）+ 入口限流；无需验证码即可堵住爆破。
5. **审计落库**：登录成功/失败、建号、改密、重置、禁用、成员增删改，统一写 `OpsActionLog`（通道已存在，告警在写），前端只读查询页。
6. 无邮件时的重置方案（GitLab 模式的降级版）：管理员生成**一次性重置口令/链接，页面只展示一次**，人工转交——先解「忘密进库改 hash」的痛点。

### 第二段：邮件通道加持（复用告警 SMTP 的配置模式，独立 `AUTH_SMTP_*` 配置组）

7. 忘记密码：登录页入口 → 一次性短时重置令牌（≥32 字节随机、单用、用后吊销全会话）。
8. 建号改为 GitLab 默认模式：管理员填 username/email/name，**系统自动发设密邮件**；保留「直接代设」开关。
9. 项目邀请：成员管理支持输入邮箱——未注册则发注册链接（落地自动入会），已注册则发邀请待接受；邀请可设**成员有效期**（external 角色尤其需要）。
10. 邮箱验证：建号/改邮后发确认链接，未验证状态限制登录或只读。

### 第三段：加固与生命周期（可长期缓建）

11. 账号状态机补齐 `pending approval`（若未来开自助注册）、休眠回收（对标 GitLab deactivated）。
12. 会话管理页（查看在线会话、逐个踢下线）。
13. 可选 TOTP 二次验证（超管强制、成员可选）。
14. 手机号/短信验证：依赖短信通道（告警已有腾讯云 SMS 配置模式可复用），私有化产品中优先级最低，建议维持非目标，邮箱覆盖即可。

### 明确维持非目标（沿用既有 PRD 决策）

- 不侵入社区版 ClkLog 用户体系（红线，SaUser 加列属分析域正常演进，不触红线）。
- 不交付 SSO/LDAP/OIDC、自助注册对公网开放、C 端式验证码。

### 附带修复

- 回写 `design-user-rbac.md` 的密码算法描述（bcrypt → scrypt），消除文档漂移。
