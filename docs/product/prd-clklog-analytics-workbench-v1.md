## 1. 阶段目标与范围

把事件分析、漏斗分析、留存分析收成同一套「窄配置 / 宽结果」工作台：配置区变窄、筛选不再被裁切、步骤用带序号的卡片表达顺序。同时把留存从占位页做成可查询、可存卡片、可在看板刷新的完整能力，并为三类分析各提供一条能跑通的示例卡片。

| 模块 | 本次做什么 |
|------|------------|
| 工作台布局 | 三页共用左栏约 280px、右栏吃剩余宽度；分栏/堆叠由壳层档位决定（见 `prd-clklog-analytics-shell-responsive-v1.md`），不再用内容区 800px 容器查询单独决策 |
| 步骤卡片 | 分区是加强边框的卡片；序号只标同级列表（漏斗转化步、多条筛选/指标/分组） |
| 筛选交互 | 下拉挂到 `document.body`，条件字段换行而不是横排溢出 |
| 留存分析 | 初始/回访事件、首日或全部口径、日周月、N 日列表、cohort 表 + 留存率曲线、保存卡片、看板刷新 |
| 示例卡片 | 用项目内真实事件各存一张事件/漏斗/留存卡并跑出结果 |

## 3. 非目标

- 不改 Harness Web 源码（含 `startTime` 报错）；不合并多窗口对话。
- 不做分组留存、属性关联漏斗、按次数漏斗、用户下钻。
- 不做时间对比（上期/去年）。
- 不引入第二套组件库或新字体；继续 Ant Design。
- 不把示例卡写成跨项目种子脚本入库；示例卡只在当前项目用真实事件创建。

## 4. 体验

### 4.1 空间

分析任务是「配条件 → 看图/表」。结果必须是主视觉。左栏只承载配置，默认 280px，上限 300px。窗口变窄时的菜单 / Harness / 分栏取舍以 `prd-clklog-analytics-shell-responsive-v1.md` 为准：先收菜单，再收 Harness，最后才放弃左右分栏。

### 4.2 步骤卡片

序号只标**同级列表**：漏斗的转化步、同一筛选组里的多条条件、多个指标、多个分组。分区标题（窗口与口径、全局筛选、分组、时间范围、查询、指标、初始/回访事件）不编号。步骤块用加粗边框与背景区分，不是 Card 套 Card。事件分析不单独放「事件」分区：每个指标自己选事件（对标神策）。漏斗转化步可折叠；步骤名称显示为标题，点击标题才进入改名，不常驻输入框。

### 4.3 筛选

对标神策 / Mixpanel：同一层只有一种关系（全且或全或），不是相邻两条各选一次。0 或 1 条条件时不露出且/或。≥2 条时，且/或作为连接词画在条件之间，点任一连接词切换整层。混合关系用「条件组」嵌套（例如 (渠道=App 且 版本≥3) 或 渠道=Web），最多 3 层。每条条件纵向排范围、属性、运算符、值。下拉挂到 `document.body`。

### 4.4 留存口径（对用户）

| 口径 | 含义 |
|------|------|
| 全部用户 | 时间范围内第一次触发初始事件的人进入该日队列 |
| 首日新用户 | 初始事件发生且 `is_first_day=1` 的人进入该日队列 |
| 回访 | 队列日之后第 N 个粒度单位再次触发回访事件（日=天，周=周，月=月） |

输出：队列日期 × 人数 × 各 N 的留存人数与留存率；曲线用各 N 的留存率。

### 4.5 示例

每个分析页提供「填入示例」：用当前项目可见事件填好表单。部署后在看板写入三张对应类型卡片，作为可刷新案例。
