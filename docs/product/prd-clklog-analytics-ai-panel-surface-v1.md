## 1. 阶段目标与范围

AI 面板里嵌的是官方 Harness 套件。它的设置弹窗**自身没有响应式**（整包只有 3 处媒体查询，设置面板包 0 处），行布局是 `flex:1; min-width:0` —— 容器变窄时它不会拒绝，只会一直缩到 0，中文于是逐字断行成「一列一个字」。实测（§3 数据）它需要 **≥640px** 才排得下。

而我们的停靠上限是 `min(560, 视口×32%)`：1600 视口下最大 512px，**停靠态在任何视口下都不可能让这个弹窗正常显示**；同时「展开到覆盖层」的入口只在不能停靠时才出现，用户在可停靠时没有任何办法把面板变宽。

本期把面板明确拆成两种面，并让切换**按需发生、自动还原**。

| 模块 | 本次做什么 |
|------|------------|
| 面模型 | 承认「对话面」与「第三方弹窗面」；弹窗需要更宽时走覆盖层，而不是继续挤（红线 §2 的字面要求） |
| 手动通道 | 面板头部常驻「扩宽为整屏 / 收回为侧栏」开关，不再依赖「能不能停靠」 |
| 自动通道 | 官方弹窗打开时自动临时扩宽、关闭后自动还原，**会话不重建** |
| 停靠上限 | 放宽到能容纳弹窗（720），让宽视口可以在停靠态直接看弹窗；工作台地板仍由既有 `roomMax` 保护 |
| 边界如实 | 视口本身 < 640 时（连覆盖层都放不下）给一句提示，不假装正常 |

## 2. 用户流程

1. 用户在自定义 SQL 页打开 AI 面板（停靠态，宽 400~512），点官方设置。
2. 面板**自动临时扩宽为覆盖层**（≥640），设置弹窗一行一句排得开；面板头部出现一行说明：这是为了容纳官方设置。
3. 关闭设置 → 面板**自动收回**到原来的停靠宽度与位置，滚动与会话原样保留（AI 运行时不重建）。
4. 不想被自动切换时：头部常驻的「扩宽为整屏」按钮可手动切换；手动切换优先，自动逻辑不覆盖用户的选择。
5. 窗口本身很窄（覆盖层也到不了 760）时：给出「窗口太窄，官方设置弹窗可能显示不全」的提示。

## 3. 实测依据（本期数字的唯一来源）

在顶层助手页打开官方设置，用 `setViewportSize` 逐档扫描。**判据取「最长的那条说明」的行数**——
设置弹窗里有三条说明，长度不同：

| 视口 | 弹窗宽 | 字号说明 | 对话显示说明 | 占线行为说明 | 全部单行？ |
|---|---|---|---|---|---|
| 900 | 800 | 1 行（413px） | 1 行（395px） | 1 行（412px） | ✅ |
| 800 | 752 | 1（365） | 1（347） | 1（364） | ✅ |
| **760** | **712** | **1（325）** | **1（307）** | **1（324）** | **✅ 下限** |
| 720 | 672 | 1（285） | 1（267） | **2** | ❌ |
| 680 | 632 | 1 | **2** | **2** | ❌ |
| 640 | 592 | 1（205） | **2（187）** | **2（204）** | ❌ |
| 600 | 552 | 2 | 2 | 2 | ❌ |
| 560 | 512 | 3 | 3 | **4** | ❌ |

结论：**760 是弹窗完整可读的下限**。

> 这条数字订正过一次：最初只量了第一条（最短的「字号」说明）得出 640，按那个值上线后，
> 停靠 693px 时「对话显示」的说明仍会折成两行。教训是**判定阈值要取最坏的那一条文案**，
> 而不是顺手量到的第一条。

## 4. 验收标准

- [ ] **SC-1（弹窗可读）**：从停靠态打开官方设置后，**全部三条**说明文字各占一行（取最长的那条判）；面板实际宽度 ≥ 760。
- [ ] **SC-2（自动还原）**：关闭设置后面板回到打开前的面与宽度；**会话不重建**（运行时不重连、不出现重连提示）。
- [ ] **SC-3（手动通道）**：面板头部常驻「扩宽/收回」开关；手动切换后，自动逻辑不得把它拉回（用户选择优先）。
- [ ] **SC-4（不打扰）**：面板已经 ≥760（用户手动拖宽或已在覆盖层）时，打开设置**不再切换**。
- [ ] **SC-5（停靠可达）**：宽视口下用户可以把停靠面板拖到 ≥760 而不被百分比上限挡住；工作台宽度不越过既有地板（`SPLIT_MIN` / `STACK_MIN`）。
- [ ] **SC-6（宽度偏好不被误清）**：新的上限之内（640–720）的宽度偏好在下次加载后仍保留。
- [ ] **SC-7（窄视口如实）**：面宽（含覆盖层）< 760 时给提示，不假装弹窗可用。
- [ ] **SC-8（门禁）**：新增/改动单测通过；`tsc` 通过；`python3 scripts/arch_ratchet.py`、`python3 scripts/i18n_check.py`、`python3 scripts/i18n_scan.py --check` 通过；新增文案补齐 13 语言。

## 5. 非目标

- **不向官方 UI 注入窄屏样式**：类名是哈希的（如 `bVCLcG_row`），dsh 一升级就失效，把我们的稳定性绑在别人内部实现上不划算。只有「覆盖层也救不了」的窄视口才退化为提示。
- 不改对话面的可用下限（400 保持不变）：窄不等于不可用，聊天的排版在 400 下是正常的。
- 不在我们面板里复刻官方设置项（字号、显示密度仍走官方，只是让它排得开）。
- 不改覆盖层既有的 92% / 窄视口 100% 规则。
- 不改官方组件、不 fork、不 patch 其 CSS 文件。
