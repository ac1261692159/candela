## 1. 阶段目标与范围（门禁要素①）

让分析平台（`/sa`）**能被不懂中文的人正常使用**：界面文案、系统提示、通知、导出与预置名称按使用者语言呈现；同时**中文用户的现有体验逐字不变**。

范围：

1. **语言集**：先交付简体中文 + 英文；第二梯队繁体中文 / 日文 / 韩文；再往上按客户激活欧洲语种（§3）。
2. **语言选择**：登录前按浏览器语言自动判定并可手动切换；登录后记住到账号，跨设备生效（§4）。
3. **界面文案**：菜单、按钮、表单标签、表头、空态、提示、引导、图表配置项、组件库自带文案（日期选择器 / 分页 / 确认框）全部随语言变化。
4. **系统提示**：接口报错、校验失败、权限不足、服务不可用等提示按当前语言呈现；技术细节不外泄的现有规则保持不变。
5. **系统生成内容**：告警通知按**接收者**语言发送；导出文件表头与工作表名按**操作者**当前语言；AI 助手按提问者语言作答（§5）。
6. **预置名称**：角色名、权限项说明、告警健康度、内置通知模板默认值等平台自带的展示名随语言变化；用户自己起的名字不动（§6）。
7. **加语言的成本**：新增一门语言只增加语言内容，不改交互、不改接口约定、不需要为新语言单独发版逻辑。

## 2. 用户与场景

| 用户 | 场景 | 期望 |
|---|---|---|
| 中文团队里的外籍分析师 | 用同一套平台做事件 / 漏斗 / 留存分析 | 界面、报错、看板全英文；自己建的事件名保持原样 |
| 私有化交付的海外客户 | 部署在客户环境，由客户团队日常使用与运维 | 首次打开就是英文（跟随浏览器），不需要找设置 |
| 跨国团队 | 同一项目内中英成员协作 | 各看各的语言；看板、卡片、事件的**名字**两边一致（那是数据） |
| 平台超管 / 运维 | 运维面板、告警工作台、账号管理 | 运维界面与告警通知按自己的语言 |
| 值班 / 支持人员 | 排查「用户看到的提示不对」 | 能用 URL 参数临时切到目标语言复现，不改动用户偏好 |
| 中文用户（存量，占多数） | 日常使用 | 完全不感知本次改动：文案、格式、顺序与现在逐字一致 |

## 3. 语言集与上线门槛

| 梯队 | 语言 | 交付要求 |
|---|---|---|
| 首发 | 简体中文 `zh-CN` | 源语言，100% 覆盖，行为与现状逐字一致 |
| 首发 | 英文 `en-US` | 界面与系统提示 100% 覆盖；术语统一（见 §6.3） |
| 第二梯队 | 繁体中文 `zh-TW`、日文 `ja-JP`、韩文 `ko-KR` | **已于 2026-09-17 上线**（见验收记录 §3.8） |
| 五常 + 德 | 俄文 `ru-RU`、法文 `fr-FR`、德文 `de-DE` | **已于 2026-09-17 上线**（中文/英文/俄文/法文 = 联合国五常语言齐备；见验收记录 §3.9） |
| 第三梯队 | 西班牙文 `es-ES`、葡语（巴西）`pt-BR`、越南文 `vi-VN`、泰文 `th-TH`、印尼文 `id-ID` | **已于 2026-09-17 上线**（见验收记录 §3.10） |
| 预留 | 阿语等 RTL 语言、欧洲其余语种 | RTL 需先做 CSS 逻辑属性与布局镜像改造；其余按需激活（术语表见 `docs/architecture/i18n-glossary.md`） |

**上线门槛（产品规则，必须可核对）**：一门语言**只有在界面文案与系统提示全覆盖时**才出现在语言选择器里。半成品语言不暴露给用户——宁可少列一个选项，也不让用户看到中英混排的界面。内容型页面（接入指南 / SDK 文档）允许例外，但必须在页面顶部明确标注「该语言文档尚未翻译完成，部分内容为中文」（§7-11）。

## 4. 语言选择与生效（体验契约）

1. **首次访问（未登录）**：按浏览器语言自动判定；浏览器语言不在已上线语言集内 → 显示简体中文。
2. **登录后**：账号偏好优先；账号未设置过偏好时，沿用浏览器语言并把结果记为账号偏好。
3. **切换入口**：登录页（未登录也能切，登录页自身文案随之变化）+ 登录后「个人设置」内。
4. **切换即时生效**：不刷新整页，**不丢失**当前已填写的查询条件、未保存的筛选或编辑内容；日期选择器、分页、表格空态等组件自带文案同步变化。
5. **持久化**：登录用户的语言属于账号偏好，换设备 / 换浏览器后仍然生效；未登录时记住在本设备。
6. **语言名用自身语言书写**（`简体中文` / `English` / `繁體中文` / `日本語` / `한국어`），不用当前界面语言翻译语言名，避免"英语"这类需要二次翻译的选项。
7. **浏览器与无障碍**：页面语言标记与标签页标题随语言更新，屏幕阅读器与浏览器翻译提示据此工作。
8. **临时覆盖**：支持用 URL 参数一次性指定语言（供支持与验收复现），不写入账号偏好、不改变用户在别处的默认。
9. **英文下的版式**：英文比中文长，界面按「够宽则展开、不够则不挤压」处理——不允许标签竖排、不允许按钮文字被截断到看不清（沿用 `docs/architecture/templates/AGENTS_front.md` 的硬红线）。

## 5. 系统生成内容的语言

| 内容 | 语言依据 | 说明 |
|---|---|---|
| 告警通知（飞书 / 邮件 / 短信） | **接收者**的语言 | 通知的读者是收件人，不是触发者；收件人没有账号（纯群机器人）时按项目默认，再退到平台默认简体中文 |
| 用户自定义通知模板 | 原样发送，不翻译 | 是用户写的资产；本次只把**内置默认模板**做成多语言 |
| 导出的表格 / 图表 | **操作者当前界面语言** | 表头与工作表名随语言；导出内容里的用户数据不译；文件名保持与语言无关的稳定形态 |
| AI 助手回答 | **提问者界面语言** | 说明、结论、建议用提问者语言；生成的 SQL、字段名、事件名保持原样 |
| 运维 / 审计记录、应用日志 | 不翻译 | 排障与合规需要稳定原文 |
| 日期时间与数字格式 | 随语言 | 千分位、小数点、百分比、时长写法按语言习惯；**展示时区仍为 Asia/Shanghai**（见 §8） |

## 6. 翻什么、不翻什么

### 6.1 要翻译

界面文案（菜单 / 按钮 / 表单 / 表头 / 空态 / 提示 / 引导）、系统错误与校验提示、权限不足与登录失效提示、组件库自带文案、平台预置展示名（角色名、权限项说明、告警健康度、内置通知模板默认值）、接入指南与 SDK 文档。

### 6.2 不翻译

用户自建的资产名与内容（事件、属性、虚拟事件、看板、卡片、分群、标签、指标名、备注、SQL 文本）、应用日志与审计记录、上报协议字段、导出数据本身。

判据一句话：**用户自己起的名，永远不翻译；平台替你写的话，都要翻译。**

### 6.3 术语统一

同一概念在所有语言中只能有一种译法，交付时随附术语表（事件 event / 属性 property / 漏斗 funnel / 留存 retention / 看板 dashboard / 分群 cohort / 埋点 tracking plan / 指标 metric / 告警 alert 等），翻译评审按术语表逐条核对，术语表本身纳入验收物。

## 7. 验收标准（门禁要素②）

产品层可核对项（实现层对应项见 `docs/architecture/clklog-analytics-design-i18n-v1.md` §10）：

- [ ] **I18N-1**：语言选择器列出且只列出已完整交付的语言；语言名用该语言自身书写。
- [ ] **I18N-2**：未登录首次访问时，浏览器语言为英文的使用者看到英文界面；浏览器语言不在语言集内时看到简体中文。
- [ ] **I18N-3**：登录后在个人设置切换语言，界面即时变化，**不刷新整页且已填写的查询条件不丢失**。
- [ ] **I18N-4**：语言偏好随账号保存：换浏览器 / 换设备登录后仍是所选语言；退出登录后回到浏览器语言判定。
- [ ] **I18N-5**：英文界面下走查登录页、看板、事件分析、告警工作台四个页面，**无中文残留**（白名单仅用户数据与专有名词）。
- [ ] **I18N-6**：英文界面下，报错提示、权限不足、登录过期、服务不可用、查询超时提示均为英文，且技术细节不外泄的现有规则不回归。
- [ ] **I18N-7**：日期选择器、分页、表格空态、确认弹窗等组件自带文案随语言变化；标签页标题与页面语言标记同步更新。
- [ ] **I18N-8**：数字千分位、小数点、百分比、时长、日期时间在中文 / 英文下各自符合语言习惯（中文的「万 / 亿」写法只在中文下出现）。
- [ ] **I18N-9**：切换语言后，用户自建的事件名、看板名、备注、SQL 文本**保持原字面**不被翻译（含看板详情与卡片标题）。
- [ ] **I18N-10**：告警通知按接收者语言发送——英文偏好用户收到英文飞书 / 邮件；用户自定义模板原样发送；无账号联系人的告警按项目 / 平台默认语言。
- [ ] **I18N-11**：按操作者语言导出的表格 / 图表，表头与工作表名为目标语言；数据内容不变；文件名稳定。
- [ ] **I18N-12**：接入指南 / SDK 文档在目标语言未完成时，页面顶部有明确「部分内容为中文」的标注，不出现空白或伪翻译。
- [ ] **I18N-13**：存量中文用户无感知：默认语言下界面文案、日期与数字格式与改动前逐字一致（自动化回归证据）。
- [ ] **I18N-14**：新增一门语言（以繁体中文为验证样本）只需提供语言内容，不需要为新语言改动交互或接口约定。
- [ ] **I18N-15**：术语表随交付提供，且抽样核对无同一术语多种译法。
- [ ] **I18N-16**：生产环境实测通过（切换语言走查 + 一条测试告警确认通知语言），证据写入 phase 验收记录。

## 8. 非目标（门禁要素③）

1. **不改 ClkLog 社区版**：社区版自带界面不在本次范围；不为社区版做多语言，也不改官方镜像 / 模板（红线 1）。
2. **不做时区本地化**：只本地化「格式」，展示时区仍固定 `Asia/Shanghai`；「时区随用户走」是独立课题（看板时间口径、告警窗口都受影响），不在本次范围。
3. **不翻译用户数据**：系统性地不做资产级翻译（事件名 / 属性名 / 看板名的多语言显示名属后续课题）。
4. **不做从右到左（RTL）语言**：本次语言集不含阿拉伯语 / 希伯来语。
5. **不做 AI 工作区指令文档的多语言**：AI 工作区的指令与工具说明保持中文单版，只要求助手**回答语言**跟随提问者。
6. **不做项目级默认语言**（个人级为主）：项目默认语言仅作为「通知收件人无账号」时的兜底，不引入「项目锁语言」的协作规则。
7. **不做机器翻译实时接口**：翻译内容随版本发布进入产品，不接在线翻译服务（离线私有化环境不可用）。
8. **不翻译内部记录**：日志、审计、运维明细保持原文。

## 10. 待确认（有默认值，不阻塞开工）

| 事项 | 默认决定（未反对即按此执行） |
|---|---|
| 首发是否除英文外再带繁体中文 | 带。繁中与简中同源，成本低、区域覆盖明显 |
| 日文 / 韩文何时上 | 英文稳定后按需求激活（第二梯队），不与首发同批 |
| 未完成语言是否可灰给用户 | 不可以。选择器只列完整语言（§3 门槛） |
| 登录页语言选择器位置 | 页面右下角，不做成弹窗打断登录 |
| 是否允许临时 URL 参数改语言 | 允许，且不写偏好（供支持与验收使用） |
| 项目级默认语言是否做 | 只做通知兜底，不做项目锁语言 |
