## 1. 阶段目标与范围

做出可复用的**用户分群**资产：先按规则或名单圈人并预计算成员，再在事件 / 漏斗 / 留存的**全局筛选**和**分组项**里选用。

对标数数用户分群（条件配置器是一句话规则，不是另做一张复杂表单）。分析选择器里数数同时有「用户分群」和「用户标签」；**本期只做分群，标签整项不做。**

本期包含：

1. **分群列表**：搜索分群名/显示名；列含分群名、显示名、类型、创建人、计算方式、最后计算时间、人数、操作（刷新 / 编辑 / 更多）。
2. **条件分群**：分析主体固定为现有「用户」口径。条件配置器三种：做过/没做过事件、依次/没依次做过事件、用户属性满足。可开「定时计算」（每日重算）或只手动刷新。
3. **ID 分群**：UTF-8 CSV 上传，对用户 ID；对不上的行丢弃。无定时。
4. **结果分群**：从事件 / 漏斗 / 留存结果里「人数」类格子保存当前用户集合。自定义 SQL 分析不能存结果分群。
5. **分析使用**：三个分析的全局筛选、分组项属性选择器增加分类 **用户分群**。筛选：属于 / 不属于某个已计算成功的分群。分组：按属于 / 不属于拆开。查询用**上次算好的成员**，不即席重圈。

导航：在「分析」下增加「用户分群」。不为此期加「用户」顶栏，也不做分析主体管理页。

## 2. 验收标准

- [ ] US-1：分析 → 用户分群能列出本项目分群；可按分群名/显示名搜索。创建入口先选类型：条件分群、ID 分群（结果分群不在此卡）。
- [ ] US-2：条件分群配置器默认句为 `做过` + 事件 + `的次数` + 比较符 + 整数 + 时间窗（含「过去 N 天」）。「+ 添加分群条件」仅三种。多条条件之间为「且」。保存后立刻计算一次；失败在列表分群名旁可感知（如叹号），分析选择器不出现失败分群。
- [ ] US-3：做过/没做过：事件可选上报事件、虚拟事件、任意事件。没做过 = 时间窗内次数为 0。依次/没依次：≥2 个有序事件 + 同一时间窗；步骤同时发生不算依次。用户属性：运算符与现网用户属性筛选一致。
- [ ] US-4：定时开则每日按规则重算；关则仅创建/编辑/手动刷新时算。列表「计算方式」为定时或手动。ID / 结果分群无定时。
- [ ] US-5：ID 分群可下载模板、上传 CSV；成员按现有用户键匹配。结果分群从三个分析的人数结果保存快照，只填显示名/分群名/备注。
- [ ] US-6：事件 / 漏斗 / 留存的全局筛选与分组项选择器有「用户分群」分类（可与事件属性、用户属性并列；**无「用户标签」分类**）。筛选属于/不属于；分组结果只有「属于」「不属于」两档。未计算成功的分群不可选。
- [ ] US-7：点人数可看成员列表（有界，默认最多 1000 行）。圈人与分析查询均有 `project_name` + 时间或 LIMIT/超时。成员只落分析域库，不改社区版表。
- [ ] US-8：分群名小写字母开头、字母数字下划线、≤80，项目内唯一。显示名必填。单测覆盖条件句校验、筛选/分组用预计算成员而非即席圈人。棘轮通过。

## 3. 非目标

- **用户标签**整项不做（选择器不出现该分类）。后续：`prd-clklog-analytics-user-segment-followups.md` phase `clklog-analytics-user-tag-v1`。
- 不做 SQL 分群、分析主体管理/切换、分群套分群、多时区结算。后续 SQL 分群 / 分析主体见同一 followups 文档。
- 不做运营推送、血缘、实时分群、标签体系、RFM。
- 不做自定义 SQL 分析、看板卡片上的分群筛选/分组。后续：followups phase `clklog-analytics-cohort-sql-dashboard-v1`。
- 不做列表列显隐拖拽、收藏/只看认证。
- 条件配置器本期不做：事件上再套属性筛选、「次数」以外的量（天数等）、依次做过的关联属性与步骤间「未做过」。
- 结果分群不支持再刷新（改名单只能新建）。

---

## 4. 体验

- 条件配置器保持一句话，控件 nowrap，装不下就换行整句，不拆成竖字。
- 选择器里分群用显示名，旁注分群名；与事件属性、用户属性分区，避免和属性重名混淆。
- 分析查询时间窗**不**重算分群；人数以最后计算时间为准，可在选择器或列表看到该时间。
- 删除分群：已被保存卡片引用时先提示影响，确认后再删；查询里失效分群当空集并提示。
