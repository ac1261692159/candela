# 调研：数数（ThinkingData）「行为序列」怎么做的，与我们已上线的对比

- `phase: clklog-analytics-user-timeline-v1`（**调研阶段**，改版提案；不改已上线行为）
- 帽子：产品（调研结论；改版实现方案另出 PRD/架构）

- 来源：数数科技官方文档 `docs-v2.thinkingdata.cn`（AE 使用指南 6.1）
  - 导航结构：站点左侧「分析」组（页面 URL：`?code=README` 深链）

## 1. 结论摘要（先说该改什么）

我们做的是「**按用户查原始事件**」——一张和 Debug 几乎一样的表；数数做的是「**一个人的行为画像 + 行为概览 + 行为明细**」三段式页面。
差别不在配色或排版，而在**信息组织的第一屏**：我们第一屏是「查询表单 + 原始行」，他们第一屏是**用户是谁（属性/标签）+ 他这段时间的行为概览（趋势/占比）**，明细是第三层。

**四条最该补的（按性价比排序）**：

| 优先级 | 改什么 | 为什么 |
|---|---|---|
| P0 | **概览先行**：分析时段内「每日事件量趋势」+「事件次数占比饼图」 | 这是「行为分析」的第一问（他活跃吗、主要做什么），我们现在只有一行「命中 N 条」 |
| P0 | **外显属性**：让用户挑几个属性（如 `$os`/模块/关卡）**直接作为列显示**，不必逐行展开 properties | 行为序列的价值在「属性随时间的演变」，我们只有一列 properties 预览 |
| P1 | **用户画像面板**：左侧展示该用户的用户属性 + 标签最新值（可搜索/按类型过滤） | 「从微观解释为什么」需要知道这个人是谁；我们页面完全没有用户维度信息 |
| P1 | **切换用户 + 从列表/分群进入**：按序查看一批用户的行为序列，而不是每次手填 ID | 数数的入口是「用户列表 → 行为序列」，逐个切人看是真实用法 |

另有两条他们做、我们暂不做（登记为非目标）：**「查看前后行为」**（以某事件为锚看前后 N 条）与**明细内属性筛选/快速定位**。

## 2. 数数「行为序列」的实现（文档事实）

### 2.1 入口与导航

- 位置：**「分析」组**，紧接「用户列表」；URL 语义 `code=user_streams`。
- 进入方式：**从「用户列表」进入**，并在页面内用「**切换用户**」按顺序查看符合某条件的一批用户；
- **自定义分析主体**同样支持：例如以「游戏账号」为主体，看该账号下的标签情况与**账号下所有角色**的行为数据，得到更全面的账号画像。
  （即：行为序列是「按主体展开」的，不限定 user id。）

> ⚠️ **对我方此前文档的纠错**：我在 `prd-clklog-analytics-user-timeline-v1.md` §0 曾写「数数在『用户 → 用户详情』下提供行为序列」——**这是错的**。
> 数数把「行为序列」放在**分析**组（与事件/漏斗/留存/路径并列），「用户」组里放的是**用户标签 / 用户分群 / 用户细查**。
> 我方现在把入口放在「用户」菜单下，与该事实不一致（见 §4 决策项）。

### 2.2 页面三段结构

| 区域 | 内容 |
|---|---|
| **左上：用户属性** | 该用户的用户属性；除元属性外**最多可选 30 个**虚拟属性或维度表属性；默认按用户在「用户列表」里配置的展示字段 |
| **左下：标签** | 该用户**所有标签的最新版本标签值**；支持搜索与按标签类型过滤 |
| **上：行为事件总量** | 分析时段内**每天元事件数量趋势**；可调整分析时段与事件范围；可把时段拉长后按**周/月**聚合；也可切**饼图**看事件总次数分布（各项核心行为占比，用来和全体平均对比） |
| **下：行为明细** | 快速浏览用户所有行为；**点击展开**看事件详情（含元属性、虚拟属性、维度表属性）；可把关注的事件属性设为「**外显属性**」——无需展开即可观察它随时间/事件的变化；支持**添加筛选条件**快速定位某事件；支持「**查看前后行为**」（该事件发生前后用户分别触发了哪些事件，看前因后果） |

### 2.3 权限（原文表）

| 大类 | 具体内容 | 公司超管 | 管理员 | 分析师 | 普通成员 |
|---|---|---|---|---|---|
| 用户行为序列 | 查看、新增、编辑 | ● 必有 | ● 必有 | ▲ 默认有可去掉 | △ 默认没有可有 |

> 与我们的差异：我们是「新增/编辑」不适用（只读查询），角色面与之相近（analyst / analysis_admin / owner，超管经项目角色），
> 普通成员我们**默认没有**（数数是默认没有但可开）。

## 3. 逐项对比（数数 vs 我们已上线）

| 维度 | 数数 | 我们（`/analysis/user-timeline`，v1） | 差距性质 |
|---|---|---|---|
| 菜单位置 | 分析组（紧接用户列表） | **用户**组 | 归属差异（见 §4） |
| 进入方式 | 用户列表 → 行为序列 → 切换用户 | 手填用户标识 | **差**（缺「列表/切换」链路；我方暂无用户列表页） |
| 主体支持 | 元事件 + 自定义主体（如游戏账号→其下所有角色） | ✅ 复用平台分析主体（含属性主体） | 持平 |
| 第一屏 | 用户画像（属性 + 标签）+ 行为概览（趋势/饼图） | 查询表单 + 原始事件表 | **根本差异** |
| 用户维度信息 | 属性面板（最多 30 个虚拟/维度表属性）+ 标签最新值 | 无 | **缺** |
| 概览 | 每日事件量趋势；按周/月聚合；事件占比饼图 | 一行汇总（命中数/种类数/首末时间） | **缺可视化** |
| 明细 | 事件卡片/行 + 展开详情 + **外显属性**（自定义列） | 行 + 展开 properties（固定列） | **缺外显属性** |
| 明细内筛选 | 加筛选条件定位事件 | 只有查询前的「事件名多选」 | 弱 |
| 前因后果 | 「查看前后行为」 | 无 | 缺（登记） |
| 异步/大数据量 | 未在文档中描述（其页面按天聚合，明细按需加载） | 两段式异步 + 单次 5000 行上限 + 截断标注 | **我方更强**（这点是优势，保留） |
| 多语言 | 文档站有中/英 | ✅ 13 语言（键集一致，i18n 门禁） | 持平/略强 |

## 4. 决策项与改版提案

### 4.1 决策项（要用户拍板）

1. **归属**：数数在**分析**组；我方现在在**用户**组。
   建议**对齐数数**：把菜单项移到「分析」组（1 行改动），并在 PRD 里把「从分群成员下钻」作为后续入口。
   备选：保持「用户」组（我方用户组的语义是「用户维度资产」：分群/标签/主体，行为序列确实也是用户维度）。
2. **是否引入「用户列表」页**：数数的链路是列表 → 切人。我方目前没有用户列表（最接近的是分群成员）。
   建议：本阶段**不做用户列表**，改为在行为序列页提供「**上一个/下一个用户**」于「同一批条件」内切换（例如从分群成员列表带入一批 ID）——把成本压在行为序列页内。

### 4.2 改版提案（P0/P1/P2，供下一个 phase 用）

| 优先级 | 提案 | 复用/依赖 |
|---|---|---|
| P0 | 明细视图「行为化」：**外显属性**（可多选属性作为列，选完记忆在本地）+ 事件行改为**可展开的事件卡**（元属性/虚拟属性/维度表属性分组呈现） | 我方已有属性字典（`MetaEventProperty`/虚拟属性/维度表）；前端改表格列 |
| P0 | **概览先行**：明细之上加「每日事件量趋势 + 事件次数占比饼图」，与查询同一次扫描取数或单独聚合（可用既有 `stat_date` 裁剪） | 复用平台图表组件（cards/explore-charts 已有趋势与饼图实现） |
| P1 | **用户画像侧栏**：用户属性（可配展示字段）+ 标签最新值（搜索/按类型过滤） | 依赖 `sa_user_profiles`（已有）与标签计算（`tag` 模块已有） |
| P1 | **切换用户**：从分群/标签成员带入一批用户，页面内上一个/下一个 | 复用分群成员接口（`cohort` 模块已有） |
| P2 | **查看前后行为**：以某事件为锚，查该用户该事件前后各 N 条 | 我们的 SQL 很轻（同一主体，时间往前/后各取 N），主要是交互与界面 |
| P2 | 明细内属性筛选（在不重跑全量的前提下过滤当前结果集，或服务端加条件） | 复用筛选器组件（`FilterEditor`） |
| 非目标 | 会话切分/会话回放/路径图 | 数数把这些放在相邻模块（会话回放、路径分析）；我方登记为后续独立 phase |

## 5. 我们该保留的（不要被「像数数」改掉）

1. **不搬原始事件流的隐私与权限口径**：我方是「原始事件 + 项目隔离 + `timeline.view`」，数数页面是聚合+明细混排；我方保持既有口径（PRD O-2 已定「同口径」）。
2. **两段式异步 + 截断标注**：数数文档未描述大数据量下的行为；我方已实测 2 小时区间即超 5s 预算并自动转后台、单次上限 5000 行且如实标注——这是我们的优势。
3. **13 语言一致性**：新增的可视化标题/图例等文案仍要走 i18n 门禁（键集 + 覆盖率棘轮）。
