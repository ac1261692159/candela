# PRD：看板默认可见范围与成员组授权（phase: clklog-analytics-rbac-v5）

> phase: clklog-analytics-rbac-v5
> 上游：`docs/product/prd-clklog-analytics-rbac-v2.md` §7（资产可见性）、§8（文件夹与资产保护）、`prd-clklog-analytics-rbac-v3.md`、`prd-clklog-analytics-rbac-v4.md`
> 下游：`docs/architecture/clklog-analytics-design-rbac-v5.md`
> 触发：验收实测——除外部人员外所有角色默认可见全部看板，与「私有化团队默认全开放」的早期口径已不匹配。

---

## 1. 背景与产品决定

v2 把看板可见性定为「私有化团队默认：分析师/普通成员看项目内全部看板，外部人员只看点名分享」。验收中确认这条不再合适：看板里越来越多是给特定团队/特定客户看的内容，默认全开放导致「谁能看什么」无法治理。经确认的口径：

| 决策点 | 结论 |
|---|---|
| 默认可见全部看板的角色 | **仅 owner 与分析管理员** |
| 分析师 / 普通成员 / 外部人员 | **默认看不到任何看板**，靠授权开放 |
| 自己创建的看板 | **创建者始终可见自己建的**（否则建完就看不见，无法工作） |
| 授权对象 | **成员组**为主（也支持单个成员） |
| 授权粒度 | **支持文件夹级**：给文件夹授权即覆盖其内全部看板（含之后新建的） |
| 看板筛选器报错 | 普通成员进看板时的 `cohorts?status=ready` 403 一并修复 |

---

## 2. 阶段目标与范围

1. **收回默认可见**：`dashboard.view_all` 只留给 owner 与分析管理员；分析师 / 普通成员 / 外部人员从「默认全可见」变为「默认不可见」。
2. **创建者例外**：看板创建者始终能看见并打开自己创建的看板，不需要授权。
3. **文件夹级授权**：给文件夹授「可查看」后，其内看板（含子文件夹内的、以及之后新建的）对该主体可见；单个看板仍可单独授权。
4. **授权对象放开**：看板的「可查看」可以授给任意成员组或单个成员（现状只列「角色=分析师」的人与组，导致外部人员与普通成员根本无法被授权）。
5. **修复普通成员看板页报错**：看板级分群筛选器不再对没有 `cohort.view` 的角色发起请求。

---

## 3. 验收标准

- [ ] **RB5-1 默认不可见**：分析师 / 普通成员 / 外部人员账号打开「报表 → 看板」，在没有任何授权时列表为空（有明确空态文案），且直连某个未授权看板的详情接口返回 403。
- [ ] **RB5-2 管理员不受影响**：owner 与分析管理员仍能看到全部看板，`dashboard.view_all` 对这两个角色为真，对其他三个角色为假。
- [ ] **RB5-3 创建者例外**：分析师新建一块看板后立即能在列表中看到并打开；该例外不影响其他未授权看板。
- [ ] **RB5-4 成员组授权即可见**：管理员把某个成员组授为该看板的「可查看」后，该组成员（如普通成员）刷新列表即可看到并打开；撤销后立即不可见。
- [ ] **RB5-5 文件夹级授权**：给某文件夹授「可查看」后，其内已有看板与授权后新建的看板对该组可见；文件夹内子文件夹的看板同样可见。
- [ ] **RB5-6 授权对象完整**：授权弹层的「可查看」候选包含项目内全部成员组与全部成员（不再只列分析师）；「可编辑」候选仍只列分析师（口径不变）。
- [ ] **RB5-7 看板页无 403**：普通成员打开有分群筛选的看板，控制台不再出现 `cohorts` 403；该筛选器在无 `cohort.view` 的角色下不渲染，其余筛选与卡片渲染正常。
- [ ] **RB5-8 文案与门禁**：新增文案 13 门语言齐备；`arch_ratchet` / `i18n_check` / `i18n_scan --check` / 后端 jest / 前端 vitest / 两端 `tsc` 全绿。

---

## 4. 非目标

1. **不改看板的写权限**：`dashboard.edit` 与 AssetPolicy（锁定、编辑授权、创建者可改）维持 v2 口径；本期只改「谁能看见」。
2. **不做卡片级可见性**：卡片跟随其所在看板；不给卡片单独配「可查看」。
3. **不做文件夹名的隐藏**：无授权的成员仍能在列表里看到文件夹结构（只有名字、里面没有可见看板）。是否需要连文件夹名一起隐藏，属下一期。
4. **不改公开分享链接**（v2 已声明不做）。
5. **不批量迁移历史可见性**：不做「自动把某某组授给全部看板」的一次性脚本；未授权即不可见，由管理员按团队授权。
6. **不改外部人员的其它约束**（仍只见被分享的看板、不能改筛选）。

---

## 5. 界面影响

| 界面 | 分析师 / 普通成员 / 外部人员 | owner / 分析管理员 |
|---|---|---|
| 看板列表 | 默认空；被授权后只看到被授权的看板 + 自己创建的 | 不变（全部看板） |
| 看板详情 | 未授权直连 403 | 不变 |
| 看板分群筛选器 | 无 `cohort.view` 时不渲染（消除 403） | 不变 |
| 资产授权弹层 | —— | 「可查看」候选＝全部成员组 + 全部成员；文件夹也可授「可查看」 |

---

## 6. 风险

- **上线即失明**：收回 `view_all` 后，现网分析师与普通成员立刻看不到任何看板，直到管理员授权。线上 `saAssetAcl` 目前为空，等于从零开始；成员组（普通成员组 / 外部人员组 / 分析师组）已存在，可按组批量授权，但看板多时仍需逐块（或按文件夹）操作。发布说明必须写清这件事，并建议管理员先把官方看板放进文件夹再按文件夹授权。
- **创建者例外的边界**：创建者改不了「别人建的未授权看板」的可见性；若创建者被移出项目，其看板回到「仅授权可见」。
- **文件夹授权面较宽**：一个文件夹授权等于其内全部看板可见（含未来的），管理员需要理解这层继承；弹层文案要写明。
- **外部人员的可用性**：本次同时修好了「外部人员无法被授权」的旧缺陷，属于顺带放开的能力，发布说明要提一句。

---

## 7. 发布说明

- 看板默认不再对全员可见：除 owner 与分析管理员外，所有人都需要被授权（按成员组或按文件夹）。
- 自己创建的看板始终可见。
- 授权入口在看板列表的行内「授权」，弹层里「可查看」可以选成员组或成员；对文件夹授权即覆盖其内全部看板。
- 无数据迁移、无需重新登录。
