# PRD：让 AI 助手读写事件分析的图表配置（v1）

- phase: `clklog-ai-event-chart-v1`
- 帽子：产品（`docs/product/`）
- 对应实现方案：`docs/architecture/clklog-ai-analytics-design-event-chart-v1.md`
- 上游：`docs/product/prd-clklog-ai-sql-chart-v1.md`（SQL 侧的同类能力）、`docs/product/prd-clklog-analytics-event-chart-binding-v1.md`（事件图表字段绑定本体）
- 状态：待评审

---

## 1. 背景

事件分析已经有了字段级显示控制（X 轴 / 拆分系列 / 指标 / 每指标单位 / 轴归属 / 列角色），配置存在卡片的 `dsl.chart_config`。

但 AI 助手（DeepSeek Harness）对这套配置**全盲**。诊断结论（证据见实现方案 §4）：

| | AI 现状 |
|---|---|
| 读 | 事件页只发布 `{ dsl, form, loading, result }`。`_view` 的 5 个字段与 `chart_config` 的 `chart_type/roles/bindings/options` **一个都不在快照里** |
| 写 | 唯一能写图表配置的 Page Bridge action 被服务端硬门禁锁在 SQL 页（`bridge.snapshot.page !== 'sql'` 直接 409）；事件侧物化器不存在 |

于是出现这样的割裂：用户问「这个图为什么看不出付费率的变化」，AI 能看到结果数据、能看到列角色，**却看不到用户当前把哪个指标放在了右轴**，也就给不出针对当前视图的建议。反过来，AI 想帮用户把量级差异大的指标拆到右轴，只能靠用户自己点界面上的建议条。

`clklog_get_card` 能读到**已保存卡片**里的配置，但那是历史资产——读不到用户此刻工作台上未保存的调整，更不能改。

---

## 2. 目标

1. **读**：AI 能读到当前工作台的图表配置（图表类型、X 轴、拆分系列、指标、每指标单位、轴归属、列角色、展示方式）与结果列元数据（列 key + 角色）。
2. **写**：AI 能把一份图表配置提案送到事件结果区，**经用户确认后**生效。
3. 读写都必须**不写库、不触发后端重查**——AI 改的是展示层，卡片要等用户自己保存。
4. 与 SQL 侧共用同一份 `ChartConfigV1` 契约与同一套校验，不造第二套。

---

## 3. 需求条目

### R1 AI 能读到当前图表配置

`clklog_page_read` 返回的事件页快照里，`analysis` 增加：

- `chart_config`：当前工作台生效的配置（含用户未保存的调整）
- `view`：`chart_config` 覆盖不到的展示态（展示方式、时长展示）
- `result_columns`：结果列元数据，含列 key、角色（时间/维度/指标）、标题、单位

**验收**：在事件分析页让 AI 读页面，它能在回答里准确说出「当前 X 轴是 X、指标 A 在左轴、指标 B 在右轴、单位是什么」。

### R2 配置变化会刷新 AI 看到的版本

用户改完图表配置后，AI 再读页面必须拿到新值；AI 基于旧版本发出的提案要被明确拒绝，而不是悄悄写到一个已经变了的视图上。

**验收**：改配置 → AI 再读，`revision` 变化且 `chart_config` 是新值；用旧 `revision` 提案会被拒并给出可读原因。

### R3 AI 能提案图表配置

新增工具，让 AI 能提出一份图表配置：图表类型 + X 轴 + 拆分系列 + 指标 + 每指标单位 + 轴归属，并附上「为什么这么配」。

**验收**：AI 能被要求「把量级差异大的指标拆到右轴」，并产出可用的提案。

### R4 提案必须经用户确认才生效

**这是与 SQL 侧有意的差异**：SQL 侧的图表提案是自动写入结果区的；事件侧**不自动应用**。

理由：SQL 那次改的是「还没出图的配置」，事件这次改的是**用户眼前正在读的图**。AI 自作主张把用户正在看的曲线挪走，比不帮忙更糟。

**验收**：AI 提案后，事件页出现一条可见的提案（含 AI 给的理由）；用户不点「应用」，图表**一个像素都不变**；点「应用」才生效；不点直接忽略则提案消失且无副作用。

### R5 提案不写库、不重查

应用提案只改本地展示状态。卡片要等用户自己点「覆盖保存」才入库。

**验收**：应用提案后，页面无 `/sa/api/query/` 请求，且卡片 `dsl` 与 `updated_at` 不变。

### R6 非法提案被拒绝且原因可读

AI 引用不存在的列、用事件侧不支持的图型（如漏斗）、指标数超上限、轴值非法时，服务端拒绝并给出用户能看懂的原因。

**验收**：四类非法提案各自返回 400 + 明确 errorCode；页面上不出现半应用的配置。

### R7 事件侧支持的配置范围

AI 能配置的：图表类型（9 种，不含漏斗）、X 轴、拆分系列、指标、每指标单位、轴归属。
AI 不能配置的：列角色（`roles`）、列角色忽略（`ignored`）、标签策略（`x_label`）——这些是排障手段，不该由 AI 改。

**验收**：AI 提案里的 `roles` / `x_label` 被服务端忽略或拒绝（按实现方案定的策略），不进入生效配置。

## 4. 交互

AI 给出图表提案后，结果区图表上方出现一条提案条（与既有的「指标量级差异 8508×，建议把 付费率 拆到右轴」同款样式，用户已经认识这个交互）：

```
┌─────────────────────────────────────────────────────────────┐
│ ⓘ AI 建议把「付费人数」「付费率」拆到右轴，避免被 DAU 压平   │
│                                        [应用]  [忽略]        │
└─────────────────────────────────────────────────────────────┘
```

要点：

- **理由必须显示**（来自 AI 的 `reason`），用户要能判断该不该点。
- 提案条是**非模态**的，不打断用户读图。
- 一次只保留最新一条提案；新提案覆盖旧提案。
- 用户改动图表配置后，未应用的提案自动作废（已过时）。

---

## 5. 非目标

1. **不自动应用**（R4）——与 SQL 侧的有意差异，理由见 R4。
2. **不允许 AI 保存卡片**。AI 只能改当前视图，`覆盖保存` / `另存为卡片` 永远由用户点。
3. **不做漏斗 / 留存的图表配置读写**。漏斗有自己的图形与绑定语义（步骤、行选择），单独排期。
4. **不允许 AI 改查询**。这一期只动展示层；改查询仍走既有的表单提案（`clklog_propose_analysis`）+ 用户点「计算」。
5. **不放开事件表单的键白名单**。`chart_config` / `_view` 混进 `clklog_propose_analysis` 的 `dsl` 仍然被拒（现在是抛错 + reject），图表配置只走图表提案通道。
6. **不改成"AI 直接操作界面"**。仍只允许 React 状态写入，不做 DOM 操作或键鼠模拟。
7. **不做自动图表推荐**。AI 不主动分析完结果就推一份配置，只在用户要求或明确需要时提案。

---

## 6. 术语

| 术语 | 含义 |
|---|---|
| 图表配置 | `ChartConfigV1`：图表类型 + 列角色 + 绑定（X 轴/系列/指标）+ 选项（单位/轴归属/标签策略） |
| 展示态 | `dsl._view`：展示方式（图表+表格/图表/表格）、时长展示等，`ChartConfigV1` 覆盖不到的部分 |
| 提案 | AI 产出的图表配置 + 理由，等待用户确认 |
| revision | 页面可编辑状态的版本号；AI 提案须带上它读到的版本，防止写到已经变了的视图上 |
