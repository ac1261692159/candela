> phase: clklog-analytics-rbac-v2
> 上游：`docs/product/research-clklog-analytics-rbac.md`、`docs/product/prd-clklog-analytics-user-rbac-v1.md`（P1 登录与用户表保留）
> 下游：`docs/architecture/clklog-analytics-design-rbac-v2.md`
> 对标差异：`docs/product/gap-clklog-analytics-vs-thinkingdata.md` §10
> 本文是产品层权威：谁能进项目、角色能干什么、数据怎么收窄、管理页长什么样。权限码、表结构、API 以架构文档为准。

## 1. 阶段目标与范围

把 P1「全局三角色 + 资产私有」升级成神策式**项目空间权限**。登录身份仍用现有用户表；权限改挂在「人 × 项目」上。

本期做：

1. **成员管理**：把已有登录用户加入/移出当前项目，指定项目角色；每项目恰好 1 个 owner。
2. **成员组**：项目内命名的人集合；组绑定一个非 owner 角色和一条数据权限策略；组员继承。
3. **角色管理**：预置五角色 + 平台超管说明；页面用「功能 / 操作权限 / 功能明细」把每个角色讲清楚（与神策角色管理同构）。
4. **数据权限**：按成员或组限制可见事件、可见属性、可选行过滤；查询与看板刷新按**查看者**收窄。
5. **菜单与接口按权限裁剪**：无权限的入口不出现，直链返回 403。
6. **看板文件夹**：看板列表顶部可切换「文件夹显示 / 列表显示」，不设左侧文件夹栏；可新建文件夹；看板与文件夹均可转移路径；看板设置可改所属文件夹（最多两层）。
7. **资产锁定与编辑授权**：官方资产可锁成管理员可写；未锁时可点名分析师维护。锁定与授权互斥。卡片、分群、标签走同一套写策略；分析主体和指标不走锁定。
8. **项目设置**：超管可新建分析项目（登记 `project_name` + 指定 owner），并按项目分别指定/替换 owner。不在 ClickHouse 建库，只登记分析空间名。

本期把超管的运维入口收口（现有 API Key、AI Workspace），**不交付**新的运维管理台；权限目录为后续运维管理留位。

## 2. 验收标准

- [ ] **RB-1**：`SaUser` 不再用全局 `analyst/viewer` 决定项目能力。超管是平台帽子；进项目靠成员关系。未加入项目的用户切换到该项目时看不到业务菜单，接口 403。
- [ ] **RB-2**：每个 `project_name` 至多 1 个项目 owner。指定/替换 owner **仅超管**可做。超管可以同时是某项目 owner。
- [ ] **RB-3**：项目 owner 拥有除运维外的全部项目空间权限（见 §6 表）。分析管理员功能与 owner 对齐，但：可添加/删除分析管理员；不能指定 owner；不能改「分析管理员」角色的授权定义（仅 owner 可改该定义）。
- [ ] **RB-4**：分析师能做全部分析查询、保存卡片、编辑**自己未锁定**的看板/卡片/分群/标签，使用「用户」模块；侧栏无「埋点管理」，对应写接口 403。他人资产默认只读，除非持有编辑授权。
- [ ] **RB-5**：普通成员侧栏只留可访问的看板；不能进分析 / 用户 / 埋点。外部人员只能打开明确分享给他的看板（无分享则空列表），不能改筛选条件。
- [ ] **RB-6**：成员组可建、可加人、可绑角色（非 owner）与数据权限。同一人直接角色 + 多个组：功能取最宽，数据权限取最严。组不能产生 owner。
- [ ] **RB-7**：数据权限策略可挂到成员或组。事件分析 / 漏斗 / 留存 / SQL / 看板刷新均按查看者过滤；owner 与超管不受数据权限限制。无权限的事件不出现在选择器。
- [ ] **RB-8**：角色管理页与神策同构：左角色列表（预置标签、搜索）、右三列表（功能 / 操作权限 / 功能明细）；owner 角色顶部有「每项目最多 1 位 owner，仅超管指定」说明条。明细文案与 §6 一致，不是权限码。
- [ ] **RB-9**：P1 现网唯一 admin 迁移为超管，并成为现有项目 `clklogapp` 的 owner；历史看板仍可见。交付前棘轮通过。
- [ ] **RB-10**：看板列表顶部切换文件夹显示 / 列表显示；可新建两层文件夹；看板与文件夹均可转移路径；看板设置可改所属文件夹；历史看板落在「未分组」。分析师不能建/删/改文件夹名。
- [ ] **RB-11**：管理员可锁定文件夹/看板/卡片/分群/标签。锁定后仅 owner 与分析管理员可改、可删。分析师不能删他人资产，不能删已锁定资产，**可以删自己未锁定的草稿**。编辑授权不附带删除。
- [ ] **RB-12**：未锁定时，管理员可把看板或卡片的编辑权授给分析师或「角色=分析师」的成员组。已锁定的对象不能授权（须先解锁）；有编辑授权的对象不能锁定（须先撤授权）。文件夹上的锁/授权 inherited 到其内看板。锁看板**不**自动锁卡片；锁卡片前展示被几块看板引用。列表对锁定、已授权、当前用户可额外编辑分别打标。
- [ ] **RB-13**：设置里「项目设置」可新建项目（`project_name` 小写字母数字下划线）并指定 owner；列表里可对每个项目分别替换 owner。选择器只列出当前用户能进的项目（超管看全部）。

## 3. 非目标

- 不做客服式自定义角色（神策「+ 自定义角色」记入 gap，本期按钮不做）。
- 不交付运维管理台、项目接入向导、公开链接、看板协作空间、资产箱、SSO、邀请邮件。
- 新建项目只登记分析空间名与 owner，不在 ClickHouse 建库、不改社区版项目表。
- 不改社区版 ClkLog 用户体系。
- 不把神策有、我们没有的功能做成永远关闭的权限行（资产认证、时区、预警、探索、模板中心、汇率、多语言等只在 gap）。
- 不把锁定做成细到 Grafana 面板级；卡片是一等资产，锁的是整张卡的 DSL，不是看板上的一个块。
- 不给分析主体、已保存指标做锁定/授权（主体改口径、指标在埋点侧，仍走角色表）。
- 不把编辑授权授给普通成员或外部人员（会打穿「只看看板」）。
- 不做三层以上文件夹、个人私有文件夹树、跨项目移动看板。
- 不回收 P1 登录、改密、token；只替换授权模型。
- 看板可见性默认仍见 §7：分析师/普通成员看项目内看板；外部人员只见点名分享。

## 4. 两顶帽子

| 帽子 | 标识 | 谁授予 | 干什么 |
|------|------|--------|--------|
| 超级管理员 | 平台 `super_admin` | 部署初始化 / 现有超管互授（运维） | 运维：账号、指定项目 owner、API Key、AI Workspace、后续运维管理 |
| 项目角色 | 成员关系上的预置角色 | owner / 分析管理员拉人；owner 席位仅超管 | 本项目分析空间 |

同一个人可以同时是超管和某项目 owner。进「项目管理」看的是当前项目角色；进「设置 / 运维」看的是超管帽子。超管若不是该项目成员，不能做分析查询，只能做运维动作（指定 owner、看成员列表以便指派）。

现网 P1 的 `admin` = 两顶帽子焊在一个字段上。本期拆开。

## 5. 成员与成员组

### 5.1 成员

成员是「登录用户 × 项目」的一条关系，必有一个项目角色，可选一条数据权限策略。

| 动作 | 超管 | 项目 owner | 分析管理员 | 其他人 |
|------|------|------------|------------|--------|
| 查看本项目成员 | 可 | 可 | 可 | 否 |
| 添加/移除成员（分析师及以下） | 可 | 可 | 可 | 否 |
| 添加/移除分析管理员 | 可 | 可 | **可** | 否 |
| 指定/替换项目 owner | **可** | 否 | 否 | 否 |
| 禁用登录账号 | **可**（运维） | 否 | 否 | 否 |
| 新建登录账号 | **可**（运维） | 否 | 否 | 否 |

规则：

- 不能移除或改掉当前唯一 owner；要换人必须超管先指定新 owner。
- 不能把 owner 角色赋给成员组。
- 用户被禁用后，所有项目成员关系仍在，但无法登录。
- 添加成员时从已有登录用户里选（本期无邀请链接）。

### 5.2 成员组

| 字段 | 规则 |
|------|------|
| 范围 | 属于当前项目 |
| 名称 | 项目内唯一，给人看 |
| 角色 | 分析管理员 / 分析师 / 普通成员 / 外部人员，**不能是 owner** |
| 数据权限 | 可选一条策略 |
| 成员 | 已加入本项目的用户；未入项目的人不能只靠进组获得成员资格 |

一个人可以同时：直接角色一份 + 多个组成员身份。生效规则见架构文档；产品语义：

- **功能**：取最宽的那档（owner > 分析管理员 > 分析师 > 普通成员 > 外部人员）。
- **数据**：所有命中策略做交集。无策略 = 不限制。owner 席位或超管 → 忽略数据策略。

## 6. 预置角色与功能明细

下列表格是角色管理页要展示的内容，只覆盖**我们已有或本期要管的能力**。操作权限取值：`功能使用` / `查看` / `编辑` / `管理`。

「分析管理员和项目管理员一致」：我们不设单独的项目管理员。分析管理员 = 项目空间管理员。

### 6.1 超级管理员（平台，非项目预置角色）

角色列表不把它和五个项目角色混排。系统管理/设置里用独立说明页或页顶条：「超级管理员拥有运维权限，不自动等于项目 owner」。

| 功能 | 操作权限 | 功能明细 |
|------|----------|----------|
| 运维 · 账号 | 管理 | 新建、禁用、启用登录账号 |
| 运维 · 项目设置 | 管理 | 新建分析项目；为每个项目指定或替换唯一项目 owner；超管自己可被指定为 owner |
| 运维 · API Key | 管理 | 查看、创建、撤销外部只读查询 Key |
| 运维 · AI Workspace | 管理 | 维护 AI 初始化模板与同步任务 |
| 运维 · 后续运维管理 | 管理 | 占位：后续系统内运维台仅超管可入；本期无页面 |

超管**没有**「因为是超管所以能改埋点」——那是项目 owner / 分析管理员的权限。要做项目内的事，把自己加成该项目成员（或当 owner）。

### 6.2 项目 owner

页顶说明条（必做，文案可微调）：

> 每个项目最多 1 位项目 owner。仅超级管理员可指定或替换。项目 owner 拥有除运维外的全部项目空间权限。

| 功能 | 操作权限 | 功能明细 |
|------|----------|----------|
| 项目权限管理 | 查看 | 查看本项目成员、成员组、角色说明、数据权限策略 |
| 项目权限管理 | 编辑 | 添加/移除成员与成员组；分配除「指定 owner」外的项目角色；**编辑「分析管理员」角色的授权定义** |
| 分析主体 | 功能使用 | 查看并编辑本项目分析主体 |
| 用户分群管理 | 查看 | 查看分群列表与成员预览 |
| 用户分群管理 | 编辑 | 新增、编辑、删除任意分群（含他人的）；锁定/解锁分群 |
| 用户标签管理 | 查看 | 查看标签列表与成员预览 |
| 用户标签管理 | 编辑 | 新增、编辑、删除任意标签（含他人的）；锁定/解锁标签 |
| 埋点 / 元数据 | 查看 | 查看元事件、事件属性、用户属性、虚拟事件/属性、指标、Debug、数据质量 |
| 埋点 / 元数据 | 编辑 | 编辑上述对象的显示名与定义；确认/隐藏事件与属性；使用 Debug；查看数据质量 |
| 模型使用 | 功能使用 | 使用事件分析、漏斗、留存、自定义 SQL；保存卡片；下钻人数（若该分析已提供） |
| 看板使用 | 查看 | 查看本项目全部看板及设置 |
| 看板使用 | 编辑 | 新建/编辑/删除任意看板与卡片；管理文件夹；锁定/解锁；授予或撤回编辑权 |
| 指标管理 | 查看 | 查看已保存指标 |
| 指标管理 | 编辑 | 新建、编辑、删除指标（含他人的） |
| 数据权限 | 管理 | 新建、编辑、删除数据权限策略，并赋给成员或组 |

### 6.3 分析管理员

默认授权与 owner 的项目空间功能相同，**但下面三行不同**。owner 可改本角色授权定义；改完后本表按新定义展示，并标注「已相对预置调整」。

| 相对 owner 的差异 | 操作权限 | 功能明细 |
|-------------------|----------|----------|
| 项目权限管理 | 编辑 | 可添加/删除分析管理员及其他成员；**不能**指定/替换 owner；**不能**编辑「分析管理员」或 owner 的授权定义 |
| 运维 | — | 无任何运维权限 |
| 其余行 | 同 §6.2 | 埋点、模型、看板、用户、主体、指标、数据权限策略 — 默认与 owner 相同 |

### 6.4 分析师

| 功能 | 操作权限 | 功能明细 |
|------|----------|----------|
| 用户分群管理 | 查看 | 查看分群列表与成员预览 |
| 用户分群管理 | 编辑 | 新增、编辑**自己未锁定**的分群；删除仅限自己未锁定的草稿；不能删他人的或已锁定的 |
| 用户标签管理 | 查看 | 查看标签列表 |
| 用户标签管理 | 编辑 | 新增、编辑自己未锁定的标签；删除仅限自己未锁定的草稿 |
| 分析主体 | 查看 | 在分析里切换已有主体；不进入主体管理编辑；主体不可锁定、不可点名授权 |
| 模型使用 | 功能使用 | 事件分析、漏斗、留存、自定义 SQL；保存卡片；维护自己未锁定的卡片；有卡片编辑授权时可改该卡 DSL，仍不能删 |
| 看板使用 | 查看 | 查看本项目看板及设置；临时调整看板筛选 |
| 看板使用 | 编辑 | 新建看板（落到当前文件夹或未分组）；编辑**自己未锁定**的看板；有看板/文件夹编辑授权时可改布局，仍不能删；不能建文件夹、不能锁定、不能给别人授权 |
| 指标管理 | 查看 | 查看指标 |
| 指标管理 | 编辑 | 新建、编辑、删除自己的指标（指标不走锁定） |
| 埋点 / 元数据 | — | **无**。侧栏不出现埋点管理。分析选择器仍能选用已启用的事件和属性（查询，不是治理） |
| 项目权限管理 | 查看 | **（rbac-v4 修订）** 只读查看本项目成员、成员组、角色说明与数据权限策略（含策略明细） |

### 6.5 普通成员

| 功能 | 操作权限 | 功能明细 |
|------|----------|----------|
| 看板使用 | 查看 | 查看已对项目成员开放的看板及设置；可临时调整筛选（只影响自己的本次查看，不写回）；进入演示/全屏若已有该能力 |

无分析、无用户、无埋点、无保存卡片、无 SQL。**（rbac-v4 修订）** 项目权限 / 数据权限：只读可见。

### 6.6 外部人员

| 功能 | 操作权限 | 功能明细 |
|------|----------|----------|
| 看板使用 | 查看 | 仅查看明确分享给自己（或所在组）的看板；**不能**改筛选 |
| 模型使用 | 功能使用 | 仅当从该看板打开时允许导出/下载已呈现的数据（若界面已有导出）；不能进分析页新建查询 |

无其它模块。**（rbac-v4 修订）** 项目权限 / 数据权限：只读可见（看板可见性规则不变，仍只见分享给它的看板）。

## 7. 资产可见性（相对 P1 的产品变化）

P1：非 admin 只能看自己的看板。这会让「普通成员只看看板」无法成立。

本期默认：

| 角色 | 看板列表 |
|------|----------|
| owner / 分析管理员 | 本项目全部看板 |
| 分析师 | 本项目全部看板（私有化团队默认；不在本期做「仅自己的」） |
| 普通成员 | 本项目全部看板（只读） |
| 外部人员 | 仅 `shared_with` 包含自己或所在组的看板 |

卡片仍有创建人，用于「谁能改自己的草稿」和锁定例外，**不再**挡住分析师看别人的看板。

外部人员的「查看分享」与分析师的「编辑授权」共用一张资产授权表（`view` / `edit`），不要两套分享。没有 `view` 记录则外部人员看不到该看板。

## 8. 看板文件夹与资产保护

解决的问题：角色默认偏宽之后，官方看板/分群会被分析师改掉或删掉；看板变多之后平铺列表无法管理。不用第二套「像 Grafana」的空话，下面规则必须能直接判 403。

### 8.1 文件夹

| 规则 | 判定 |
|------|------|
| 归属 | 一块看板恰好在一个文件夹，或 `folder_id` 空（列表里显示为「未分组」） |
| 深度 | 最多两层：根文件夹 → 子文件夹。子文件夹不能再有子文件夹 |
| 未分组 | 虚拟桶，不是真实文件夹；不能锁定、不能在其上授权、不能删除 |
| 谁能建/改名/删文件夹 | 仅项目 owner、分析管理员 |
| 删文件夹 | 必须先把里面的看板移走；有子文件夹须先删空。不能「连看板一起删」 |
| 谁能移动看板 | 管理员可移动任意看板（列表「转移路径」或看板设置「所属文件夹」）。分析师只能把自己**未锁定**且自己创建的看板，移到自己有写权限的文件夹 |
| 谁能移动文件夹 | 仅管理员。根文件夹可改为另一根下的子文件夹（自身无子文件夹时）；子文件夹可改挂到根或另一根。不能移入自己，不能超过两层 |
| 新建看板 | 创建时可选手动所属文件夹；未选则进未分组 |

列表不设左侧文件夹栏。顶栏切换「文件夹显示 / 列表显示」，并提供「新建文件夹」。文件夹显示按下文件夹分组展开看板；列表显示为平铺看板表。两视图的看板行、文件夹显示里的文件夹行都有「转移路径」。

### 8.2 可保护的资产

| 资产 | 锁定 | 编辑授权 | 入口 |
|------|:----:|:--------:|------|
| 文件夹 | ✓（只影响其内**看板布局**） | ✓（继承到其内看板） | 看板列表文件夹行 |
| 看板 | ✓（布局、筛选、加减卡、设置） | ✓ | 看板列表行 |
| 卡片 | ✓（DSL / 图表配置） | ✓ | 分析卡片列表行 |
| 分群 | ✓ | 否 | 用户分群列表 |
| 标签 | ✓ | 否 | 用户标签列表 |
| 分析主体 | 否 | 否 | 仍只走角色 `subject.edit` |
| 指标 | 否 | 否 | 仍只走角色 `metric.edit_*` |

官方报表要真正冻住：文件夹或看板锁定 **加上** 相关卡片锁定。只锁看板时，分析师仍能从卡片列表改 DSL，看板上的数会变——这是有意拆开，锁定弹层必须写明，并提供「同时锁定本看板引用的卡片」可选勾选。若某卡还挂在别的看板上，列出引用数，确认后仍锁整张卡（不是只锁这一块看板里的那一格）。

### 8.3 锁定 vs 编辑授权（互斥，锁定优先）

**锁定**：该对象写权限抬到「项目 owner + 分析管理员」。分析师、普通成员、外部人员只读。owner / 分析管理员**不能**被锁在门外。

**编辑授权**：仅看板、卡片、文件夹。对象只能是本项目**分析师**，或角色为分析师的成员组。不能授给普通成员、外部人员、管理员（管理员本来就能改）。授权 = 可改，**不可删、不可再转授、不可解锁**。

互斥（接口 409，文案给人看）：

1. 对象已锁定 → 不能再加编辑授权；须先解锁。
2. 对象上仍有编辑授权 → 不能锁定；须先撤光授权。
3. 文件夹要锁定 → 自己和子孙看板/子文件夹上也不能残留编辑授权。
4. 子看板锁定 **可以** 发生在「父文件夹已有编辑授权」时：文件夹授权不打穿子看板的锁。张三有文件夹授权，仍改不了其中已锁定的那一块。

同一对象不要同时亮「已锁定」和「已授权」。

### 8.4 谁能改、谁能删（写路径唯一表）

`admin` 下表 = 项目 owner 或分析管理员。

| 动作 | admin | 分析师（创建人） | 分析师（有编辑授权） | 其他人 |
|------|:-----:|:----------------:|:--------------------:|:------:|
| 改未锁定资产 | ✓ | ✓ | ✓ | 否 |
| 改已锁定资产 | ✓ | 否 | 否（锁优先） | 否 |
| 删未锁定、自己的 | ✓ | ✓ | 否 | 否 |
| 删未锁定、他人的 | ✓ | 否 | 否 | 否 |
| 删已锁定的 | ✓（二次确认） | 否 | 否 | 否 |
| 锁定 / 授权 | ✓ | 否 | 否 | 否 |

卡片、看板、分群、标签都用这张表。分析师默认**不能**改别人的未锁定看板——官方未锁时也不会被全员乱改；要让指定分析师维护，走编辑授权。这比「分析师默认可改项目内所有看板，再靠锁保护」更能解决问题。

查看仍按 §7：未授权的分析师仍能**看**别人的看板，只是不能改。

### 8.5 列表印记

三种印记，不混成一个「特殊权限」：

| 印记 | 谁看见 | 含义 |
|------|--------|------|
| 已锁定 | 所有能看见该行的人 | 仅管理员可写 |
| 已授权 | 管理员 | 有点名编辑人（可点开看名单） |
| 可编辑 | 被授权的分析师 | 你能改但不能删 |

文件夹锁定时，其内看板行可弱提示「随文件夹锁定」，避免每块看板再重复锁图标到看不清。

### 8.6 授权入口

- 看板列表、分析卡片列表：行内「授权」仅管理员可见；未锁定才可点。
- 弹层：已授权的分析师/组；添加时只能搜到本项目分析师。外部人员的「可查看」仍在同一弹层另一个页签，避免两套入口。
- 分群/标签只有锁定，没有授权入口。

## 9. 数据权限

与角色并列，入口在项目管理 → 数据权限。

### 9.1 策略里有什么

一条策略有名称，以及：

1. **事件**：全部 / 白名单（元事件 key + 虚拟事件 id）。
2. **事件属性、用户属性**：全部 / 白名单。
3. **行过滤**（可选）：一组用户属性条件，语法与现有分析筛选的用户属性条件相同（且）。命中的分析主体才计入查询。

空策略或不挂策略 = 本项目数据全可见（仍受 `project_name` 隔离）。

### 9.2 谁受限

- 超管、项目 owner：不受策略限制。
- 其他人：直接策略 ∩ 所在各组策略。白名单取交集；行过滤全部 AND。
- 选择器不展示无权限的事件/属性。查询若仍带上无权限字段 → 403，不静默丢掉让数变少却不说明。

看板刷新、SQL 卡、分群计算预览，凡是读 `sa_events` / `sa_user_profiles` 的路径，都按查看者收窄。分群**物化计算**仍用创建者权限还是系统权限：本期规定 **用创建者当时的数据权限**；owner 创建的分群覆盖全量。分析师创建的分群只圈自己能看见的人，并在分群详情标明「受数据权限约束」。

### 9.3 管理页

列表：策略名、已赋给的成员/组数、更新时间。编辑页三段：事件、属性、行过滤。保存后对已登录用户**下次查询**生效（不必强制踢下线）。

## 10. 界面

壳层仍是现有左菜单，不改成神策顶栏。项目管理作为新分组进入左菜单，仅对「能查看项目权限」的角色出现。

### 10.1 左菜单裁剪

| 分组 | 超管非成员 | owner / 分析管理员 | 分析师 | 普通成员 | 外部人员 |
|------|------------|-------------------|--------|----------|----------|
| 报表 / 看板 | 无 | 有 | 有 | 有 | 仅有分享时有 |
| 分析 | 无 | 有 | 有 | 无 | 无 |
| 用户 | 无 | 有 | 有 | 无 | 无 |
| 埋点管理 | 无 | 有 | 无 | 无 | 无 |
| 项目管理 | 仅成员/owner 指定（运维） | 有 | 有（rbac-v4：只读） | 有（rbac-v4：只读） | 有（rbac-v4：只读） |
| 设置 · 个人 | 有 | 有 | 有 | 有 | 有 |
| 设置 · 项目设置 | 有（超管） | 无 | 无 | 无 | 无 |
| 设置 · API Key / AI | 有 | 无 | 无 | 无 | 无 |

项目管理子项：成员管理、成员组、角色管理、数据权限。超管在设置下有「项目设置」：新建项目、按项目分别指定/替换唯一 owner。

### 10.2 角色管理页（必须像神策）

内容区两栏（项目管理子项已在壳层）：

```
┌─────────────┬──────────────────────────────────────────┐
│ + 不提供自定义│  项目 owner        [预置角色]              │
│ 搜索        │  蓝说明条：每项目最多 1 位 owner…            │
│ 项目 owner  │  ┌────────┬──────────┬──────────────────┐ │
│ 分析管理员  │  │ 功能   │ 操作权限 │ 功能明细         │ │
│ 分析师      │  │ …      │ 查看/编辑│ 完整句子         │ │
│ 普通成员    │  └────────┴──────────┴──────────────────┘ │
│ 外部人员    │  分析管理员：若 owner 改过授权，角标「已调整」│
└─────────────┴──────────────────────────────────────────┘
```

- 预置角色左侧不可删。选中项有明确选中态（条或底色）。
- 表：功能列按模块合并单元格；操作权限列短标签；功能明细列完整中文句子，与 §6 同源（前端渲染目录，不手写另一份）。
- owner 看分析管理员时可「编辑角色定义」（勾选功能明细行）；保存后只影响本项目的分析管理员。不能改 owner / 分析师 / 普通成员 / 外部人员的预置定义（避免五个角色失去含义）。
- 分析管理员打开本页：全部只读，含自己这档；无「编辑角色定义」。
- 窄窗：角色列表改左侧抽屉或上列表下明细；表头不竖字，明细可换行。

### 10.3 成员管理

表：用户名、显示名、项目角色、成员组、数据权限、状态、操作。主按钮「添加成员」。添加：选用户 + 角色（列表不含 owner，owner 在超管页指定）。改角色、挂策略、移出项目。当前 owner 行角色只读，旁注「由超管指定」。

### 10.4 成员组

表：组名、角色、人数、数据权限、操作。详情：组信息 + 组成员。不能选 owner。

### 10.5 无权限

隐藏入口。直链：页内说明「无权访问」+ 回看板或登录后首页，接口 403，文案「无权访问该资源」。数据权限导致事件不可见：选择器里没有该项，不弹系统级错误。

### 10.6 看板列表（文件夹）

`/report/dashboards` 不设左侧文件夹栏：

- 顶栏：显示切换（文件夹显示 / 列表显示）、「新建文件夹」（管理员）、「新建看板」。
- 文件夹显示：未分组与各文件夹可展开看其下看板；文件夹行可转移路径、重命名、锁定/授权/删除。
- 列表显示：全部看板平铺；行内「转移路径」改所属文件夹。
- 看板设置含「所属文件夹」，可把看板转移到文件夹或未分组。
- 分析师看到锁定的文件夹仍可展开浏览（只读）；行内无锁定/授权/新建文件夹。

分析卡片列表、分群列表、标签列表保持平铺，只加锁定印记（卡片另加授权）。不给卡片做文件夹。

角色管理里「编辑分析管理员的授权定义」和资产行上的「授权」不是同一件事，按钮文案分别用「编辑角色定义」「编辑权限」。

## 11. 初始与迁移（产品）

- 现网 `admin` → 超管。
- 现有项目（至少 `clklogapp`）指定该用户为 owner。
- 若库里还有 P1 `analyst` / `viewer`：分别变成对 `default_project` 或 `clklogapp` 的分析师 / 普通成员。
- 历史看板 `folder_id` 为空，出现在「未分组」；无锁定、无授权。
- 用户打开角色管理，能读懂自己这档为什么看不见埋点。
- 分析师将不能再改别人未授权的看板（相对「谁都能改所有看板」是收紧）。发布说明写清：官方看板请管理员放进文件夹并锁定。

## 12. 风险

- 查询路径多，数据权限漏挂会导致「页面藏了、API 还能查」。验收必须覆盖事件/漏斗/留存/SQL/看板刷新五条。
- 分析师能看见全项目看板，但不能改别人的——和 P1「只能看自己的」以及「默认可改所有看板」都不同，发布说明必须写清。
- 只锁看板不锁卡片时，DSL 仍能被改。锁定弹层不写清楚，用户会以为官方报表已经冻住。
- owner 改分析管理员**角色定义**后，两个项目的「分析管理员」可能不一样；列表用「已调整」避免以为全站预置被改。
- 文件夹继承锁/授权后，子看板单独锁定必须按 §8.3 第 4 条求值，单测覆盖「文件夹已授权 + 子看板已锁定 → 被授权人不能改」。
