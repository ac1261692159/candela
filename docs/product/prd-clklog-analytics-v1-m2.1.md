# PRD：ClkLog 分析平台 v1 — M2.1 埋点管理增强

> phase: clklog-analytics-v1
> 子阶段：M2.1
> 版本：v1.1（2026-07-28）｜ 上游：`docs/product/prd-clklog-analytics-v1.md` §4.1
> 本文档负责回答：M2.1 要无歧义地交付什么？

---

## 1. 阶段目标与范围（门禁要素①）

在 M2 MVP 已实现的「元事件 / 事件属性 / 用户属性 / 虚拟事件 / 事件分析」基础上，补齐埋点管理的产品可用性短板，使数据分析师和埋点研发能高效治理元数据。

M2.1 只聚焦两块：

1. **元事件管理增强**：让事件列表具备运营治理所需的完整字段与批量操作。
2. **虚拟属性**：允许在元数据层定义由已有属性计算得出的新属性，并在事件分析中像普通属性一样使用。

---

## 2. 验收标准（门禁要素②）

| 编号 | 验收项 | 判定标准 |
|------|--------|---------|
| M2.1-A1 | 事件列表增强 | 元事件表格展示：事件名、显示名、事件类型（上报/虚拟/预置）、昨日事件量、近7天量、实时可用状态、数据状态、连接状态、负责人、最后更新时间 |
| M2.1-A2 | 事件状态影响分析选择器 | `status=hidden` 的事件不出现在事件分析/漏斗/留存的事件选择器中；`status=visible` 优先置顶展示 |
| M2.1-A3 | 批量操作 | 支持批量隐藏/显示/删除元事件；删除仅标记 `is_deleted`，不物理删除历史数据 |
| M2.1-A4 | 虚拟属性 CRUD | 可在事件属性页面创建虚拟属性：填写表达式、数据类型、显示名；表达式支持引用其他属性与常量运算 |
| M2.1-A5 | 虚拟属性在分析中可用 | 创建虚拟属性后，事件分析的筛选/分组/指标中可直接选用该属性，SQL 生成器自动把表达式展开 |
| M2.1-A6 | 虚拟属性不破坏红线 | 虚拟属性只存表达式在 MySQL 元数据，不改 ClickHouse `sa_events` 表结构，不预计算列 |

---

## 3. 非目标（门禁要素③）

- 不做维度表（数据表）上传与关联。
- 不做用户分群。
- 不做属性物化（M8）的自动调度，只保留 M2 已有的手动「一键物化」入口。
- 不做事件属性的自动采样策略增强（保持 M2 的自动发现逻辑不变）。
- 不改 ClkLog 社区版代码与表结构。

## 4. 功能需求

### 4.1 元事件管理增强

| # | 功能 | 需求描述 | 优先级 |
|---|------|---------|--------|
| M2.1-01 | 事件类型 | 每条事件区分 `report`（上报事件）、`virtual`（虚拟事件）、`preset`（预置事件）；虚拟事件与预置事件在列表中显式标识 | P0 |
| M2.1-02 | 昨日事件量 | 在元事件列表展示昨日（T-1）事件量；由定时任务从 ClickHouse 刷新到 `meta_event.yesterday_count` | P0 |
| M2.1-03 | 实时可用状态 | 基于 `status` 与数据存在性计算：`available`（有数据且可见）、`no_data`（近7天无数据）、`hidden`（已隐藏）、`deprecated`（已废弃） | P0 |
| M2.1-04 | 数据状态 | 显示事件是否有近 7 天数据；用于快速发现埋点断流 | P1 |
| M2.1-05 | 连接状态 | 对虚拟事件显示「已连接」来源事件；对上报事件显示「自动接入」 | P1 |
| M2.1-06 | 批量操作 | 列表支持多选：批量隐藏、批量显示、批量标记废弃；批量删除仅做软删除 | P0 |
| M2.1-07 | 排序与筛选 | 按昨日量/近7天量/最后更新时间排序；按事件类型/状态/数据状态筛选 | P1 |

### 4.2 虚拟属性

| # | 功能 | 需求描述 | 优先级 |
|---|------|---------|--------|
| M2.1-08 | 虚拟属性定义 | 在事件属性页面新增「虚拟属性」类型；字段：prop_key、display_name、data_type、expression、description | P0 |
| M2.1-09 | 表达式语法 | 支持引用事件属性（`$prop_key`）和常量，支持四则运算、`concat`、`if`、常见函数；示例：`$amount * $quantity`、`if($is_vip, 'VIP', '普通')` | P0 |
| M2.1-10 | 虚拟属性作用范围 | 默认作用于全部事件；可选绑定到指定事件（如只让 `Purchase` 有 `order_amount` 虚拟属性） | P1 |
| M2.1-11 | 虚拟属性在分析中使用 | 事件分析的筛选、分组、agg 指标中可直接选择虚拟属性；SQL 生成器把表达式内联到 WHERE/GROUP BY/SELECT | P0 |
| M2.1-12 | 虚拟属性可用状态 | 表达式引用的基础属性被隐藏或删除时，虚拟属性标记为「异常」并提示 | P1 |
| M2.1-13 | 虚拟属性校验 | 保存时校验表达式语法、引用的属性存在、数据类型可推导 | P0 |

## 5. 用户界面

### 5.1 元事件列表页

- 顶部：事件类型筛选、状态筛选、数据状态筛选、关键词搜索、批量操作按钮。
- 表格列：事件名（可点击）、事件显示名、事件类型标签、昨日事件量、近7天量、实时可用状态、数据状态、连接状态、负责人、最后更新时间、操作（编辑/更多）。
- 行支持多选复选框；点击行进入事件详情抽屉。

### 5.2 事件详情抽屉

- 基本信息：事件名、显示名、事件类型（只读）、状态、负责人、描述。
- 数据信息：昨日量、近7天量、首见时间、最后出现时间。
- 属性页签：事件属性列表，区分真实属性与虚拟属性；虚拟属性可点击编辑表达式。

### 5.3 虚拟属性编辑器

- 字段：属性名（`vp_` 前缀，后端校验）、显示名、数据类型、作用事件（默认全部）、表达式输入框、实时预览/校验按钮。
- 表达式下方展示「引用属性」列表，方便用户确认依赖。

## 6. 依赖与风险

| 依赖 | 状态 | 说明 |
|------|------|------|
| M2 事件分析引擎 | 已完成 | 虚拟属性需要扩展 `attribute-resolver.service.ts` |
| ClickHouse 查询性能 | 待观察 | 复杂虚拟属性表达式可能降低查询性能，需设置执行超时 |
| 表达式解析器 | 新增 | 需要引入或自研一个安全的表达式 AST 解析器，禁止函数调用注入 |

| 风险 | 影响 | 对策 |
|------|------|------|
| 虚拟属性表达式复杂导致 SQL 性能差 | 分析变慢 | 限制表达式长度与函数白名单；复杂场景引导用户走物化列（M8） |
| 批量删除误操作 | 数据治理混乱 | 仅软删除，保留历史数据；删除需二次确认 |
| 事件类型与虚拟事件概念混淆 | 用户理解成本 | 界面用标签+tooltip 明确区分；文档补充示例 |

---

## 7. 后续衔接

M2.1 完成后，M3 漏斗 / M4 留存可继续使用增强后的事件与属性元数据。用户分群与维度表继续放到 M4 之后单独规划（v1.2 或 v2）。
