## 0. 评审结论与产品裁决

### 0.1 结论

原 v1 方案方向正确，准确命中了 SQL 图表不可用的真实问题，“自动推荐 + 手动切换 + 不重新查询”也是正确的主交互。但原稿更接近图表能力清单，字段语义、推荐冲突、漏斗多行口径、保存复现、异常边界和无障碍没有闭环。

本次修订作出以下裁决：

1. **可信优先于图表数量**：无法可靠判断字段语义时回退表格，不生成“看起来合理”的猜测图。
2. **图表配置必须可沉淀**：用户选择的图形、字段绑定、排序、TopN、单位和漏斗行选择，保存、重开和看板展示时必须一致复现。
3. **v1 收敛为高频核心图形**：表格、透视表、指标卡、折线图、柱状图、条形图、饼/环形图，以及具有严格数据形状约束的 SQL 漏斗图。
4. **复杂通用图形后置**：堆叠柱、通用热力、散点/气泡进入增强阶段；留存矩阵跟随结构化留存能力；桑基、直方和箱线进入 v2。
5. **禁止静默语义变换**：TopN、“其他”、百分比换算、字段忽略、行选择和任何聚合均须可见；v1 不对自由 SQL 结果做隐式再聚合。

### 0.2 设计健康度基线

本评分针对原 v1 规格的可用性定义，不等同于已上线页面质量。实现验收后应重新评分。

| # | 启发式 | 基线 | 主要缺口 | 本文解决位置 |
|---|---|---:|---|---|
| 1 | 系统状态可见性 | 2/4 | 推荐原因和数据变换不可见 | §5.4、§7.2、§10 |
| 2 | 符合分析师认知 | 3/4 | 主要术语已贴近分析任务 | §3、§6 |
| 3 | 用户控制与自由 | 2/4 | 不能修正字段绑定 | §7.3 |
| 4 | 一致性与标准 | 2/4 | SQL 页、事件分析和看板模型不一致 | §7、§9 |
| 5 | 错误预防 | 1/4 | 推荐冲突、不兼容选择无拦截 | §5.5、§6 |
| 6 | 识别优于记忆 | 2/4 | 依赖别名协议 | §5.2、§8 |
| 7 | 灵活与高效 | 2/4 | 缺专家字段映射和复用 | §7.3、§9 |
| 8 | 美观与极简 | 3/4 | 九种图形未按兼容性过滤 | §7.2 |

### 0.3 原评审问题

| 优先级 | 问题 | 风险 | 裁决 |
|---|---|---|---|
| P1 | 字段角色按列名和值静默猜测 | 数字 ID、日期样式字符串、比率被误判 | 引入分层证据、置信度、可见绑定和表格 fallback |
| P1 | 漏斗示例返回多行但要求一张漏斗 | 取首行任意，累加 UV 会重复计数 | 多行必须选择一行，禁止隐式聚合 |
| P1 | 推荐规则重叠，复杂图缺绑定 | 同一结果命中多种默认，无法确定实现 | 建立唯一、有序决策表和兼容矩阵 |
| P1 | 图表配置未进入保存与看板闭环 | 重开或看板展示丢失用户结论 | 配置随 SQL 卡片保存并由看板只读复现 |
| P1 | v1 范围与验收不匹配 | 留存未实现，多类图没有验收 | 收敛 v1，其余明确进入后续阶段 |

## 1. 背景与当前基线

### 1.1 当前问题

自定义 SQL 结果区已经具备明细表和特定结构下的透视表，但“图表”视图固定为折线图。共享 `ChartRenderer` 仍依赖事件分析 DSL 产生的 `g_` / `m_` 列前缀，自由 SQL 返回的列没有这些前缀，因此 SQL 图表实际不可用。

用户已经通过 SQL 产出大量分组聚合结果，典型任务包括：

| 分析任务 | 当前体验 | v1 目标 |
|---|---|---|
| 近 7 天事件量/UV 趋势 | 只能看表 | 自动折线，可修正字段 |
| 场景、房间、商品排名 | 只能看表 | 自动柱/条，明确 TopN |
| OS、渠道构成 | 只能看表 | 可切饼/环形，明确“其他” |
| 单行汇总指标 | 图表空白或错误 | 指标卡 |
| 自定义 SQL 漏斗 | 只能看表 | 合法形状下出漏斗，多行先选分组 |
| 保存后进入卡片/看板 | SQL 卡固定显示表格 | 复现已保存图表配置 |

### 1.2 可复用基础

- 前端已使用 React、Ant Design、ECharts 和 `echarts-for-react`。
- SQL 执行结果已经返回列名、ClickHouse 类型、行、截断状态和扫描统计。
- SQL 卡片已经是全局分析资产，现有存储可携带 `chart_config`，无需新建数据库表。
- 生产已有 45 张 SQL 卡，可作为真实数据形状回归样本。
- 查询安全边界已经存在；本阶段不增加查询请求，不改变 SQL、项目、时间和资源限制。

## 2. 阶段目标与范围（程序门禁要素①）

### 2.1 阶段目标

让分析师对 SQL/Builder 查询结果获得一张**语义可信、可解释、可纠正、可保存并可复现**的图表。用户不需要修改 SQL 别名来迁就渲染器；系统无法可靠识别时应明确说明并保留表格，而不是静默猜测。

### 2.2 v1 范围

1. 统一 SQL 结果的列角色识别、数据规范化、图表兼容判断和默认推荐。
2. 支持以下结果视图：
   - 明细表
   - 透视表（沿用现有合法形状）
   - 指标卡
   - 折线图
   - 柱状图
   - 条形图（柱状图的横向形态）
   - 饼图 / 环形图（同一数据语义，两种外观）
   - SQL 漏斗图（仅限 §8 定义的数据形状）
3. 图表类型自动推荐，用户可手动切换兼容图形。
4. 用户可查看并修改字段角色和图表字段绑定。
5. 图表切换、字段绑定和本地变换不重新请求后端。
6. 图表配置随 SQL 卡片保存、覆盖、重开，并在看板中只读复现。
7. 覆盖加载、空结果、推断失败、不兼容、截断、NULL、超量、配置失效和渲染错误状态。
8. 满足键盘、焦点、文本替代、非颜色依赖、窄屏和 200% 缩放要求。

### 2.3 非目标（程序门禁要素③）

- 不修改用户 SQL，不改变查询语义，不自动追加 `GROUP BY`、`ORDER BY` 或聚合函数。
- 不对自由 SQL 的返回行做隐式求和、去重、均值或二次聚合。
- 不做图表下钻、点击联动明细、跨图联动和刷选。
- 不做看板内图表编辑器；看板只复现分析页已保存配置。
- 不做自定义配色主题；沿用 Ant Design 与现有语义色。
- 不做双 y 轴、组合图、堆叠柱、通用热力、散点/气泡。
- 不做留存矩阵；当前留存查询和结果页不属于本 phase。
- 不做桑基、直方图、箱线图。
- 不修改 ClickHouse 查询、SQL 安全守卫、时间范围、项目隔离和资源上限。
- 不新增数据库表或 Prisma migration。

## 3. 用户与关键任务

### 3.1 主要用户

| 用户 | 典型状态 | 最重要需求 |
|---|---|---|
| 数据分析师 | 专注探索，需要迅速判断口径 | 看见系统如何解释字段，并能立即纠正 |
| 产品/运营 | 不熟悉 SQL，但会读取结果 | 默认图合理，文案直接，错误可恢复 |
| 研发 | 检查数据质量和边界 | 原始值、类型、截断和变换均可追溯 |
| 看板阅读者 | 不参与配置，只消费结论 | 看板与分析页结果一致，不因刷新改变语义 |

### 3.2 主任务流

1. 用户执行 SQL 或 Builder 查询。
2. 结果区立即展示行数、耗时、扫描量和截断状态。
3. 系统识别列角色，计算兼容图形并给出唯一推荐。
4. 如果推荐可靠，默认进入推荐视图；如果不可靠，默认表格并提示配置字段。
5. 用户可查看“为什么推荐”，也可展开字段设置修正绑定。
6. 用户切换图形、排序、TopN 或漏斗行，不触发查询。
7. 用户保存或覆盖 SQL 卡片，当前图表配置一并保存。
8. 用户重新打开卡片或在看板刷新，得到相同图表语义。

## 4. 产品原则

1. **证据先于推断**：显示列类型、角色、推荐原因和数据变换。
2. **不确定就退回表格**：表格是安全 fallback，不把不确定数据强行视觉化。
3. **自动化可逆**：任何自动选择都能被用户看见、修改并恢复为“自动”。
4. **不静默聚合**：尤其不累加 UV、去重人数、比率、均值和分位数。
5. **保存的是结论口径**：查询和图表配置共同构成一张 SQL 分析卡片。
6. **标准交互优先**：沿用 Ant Design 的分段选择、下拉、Popover/Drawer、Alert、Table 和 Tooltip，不创造陌生控件。
7. **表格始终可到达**：图表不能成为读取原始数据的唯一方式。

## 5. 列角色识别与推荐

### 5.1 列角色

每一列在图表工作区中只属于以下一种角色：

| 角色 | 含义 | 示例 |
|---|---|---|
| 时间维度 | 连续时间轴或时间桶 | `day`、`日期`、DateTime 列 |
| 类别维度 | 分组、名称、编码或标识 | `country`、`场景ID`、`os` |
| 指标 | 可用于数值比较的度量 | `event_count`、`UV`、`收入` |
| 忽略 | 不参与当前图表 | SQL 辅助排序列、说明列 |
| 待确认 | 证据冲突或不足 | 纯数字 ID、含混的 String 数值 |

### 5.2 识别证据优先级

优先级从高到低：

1. 用户当前显式字段绑定。
2. 已保存且仍能匹配结果列的字段绑定。
3. Builder 查询结构中的时间、分组和指标定义。
4. ClickHouse 返回的列类型。
5. 严格别名规则和严格样本检查。

不得仅以“值全部可转成数字”认定为指标，也不得使用宽松日期解析认定时间。

### 5.3 置信度与 fallback

| 置信度 | 条件 | 行为 |
|---|---|---|
| 确定 | 显式/已保存绑定、Builder 语义、ClickHouse 时间类型 | 可参与自动推荐 |
| 较高 | 类型与别名一致，样本无冲突 | 可参与自动推荐，并显示依据 |
| 待确认 | 类型与别名冲突，或数字列疑似 ID | 不自动出图，提示用户确认 |
| 无效 | 值无法满足图形要求 | 从兼容列表移除并说明原因 |

如果任何必需字段为“待确认”，默认显示表格，状态文案为：

> 无法可靠判断「{列名}」是维度还是指标。请配置字段后生成图表，原始表格不受影响。

### 5.4 推荐说明

结果工具栏始终显示当前模式：

- `自动：折线图`、`自动：柱状图` 等；
- hover/focus 可查看简短原因，例如“识别到 1 个日期列和 2 个数值指标”；
- 如果应用了 TopN、“其他”、百分比格式或漏斗行选择，以可关闭但不可隐藏的状态标签展示；
- 用户手动修改后显示 `手动：柱状图`，并提供“恢复自动”。

### 5.5 唯一推荐决策表

按表格自上而下匹配，命中第一条即停止；不得同时返回两个默认图。

| 优先级 | 结果结构 | 额外条件 | 默认视图 |
|---:|---|---|---|
| 1 | 空结果 | `rows=0` | 空状态 |
| 2 | 已保存配置 | 配置仍兼容当前列；自动配置的推荐版本未变化 | 恢复已保存图，不因刷新漂移 |
| 3 | 合法 SQL 漏斗形状 | 满足 §8 且行语义明确 | 漏斗图 |
| 4 | 无维度 + 1 行 + 1..8 指标 | 指标均有效 | 指标卡 |
| 5 | 1 时间维 + 1..5 指标 | 无类别维度 | 折线图 |
| 6 | 1 时间维 + 1 类别维 + 1 指标 | 类别值 2..5 | 多线折线图 |
| 7 | 1 时间维 + 1 类别维 + 1 指标 | 类别值 >5 | 透视表；提示可筛选后出图 |
| 8 | 无时间维 + 1 类别维 + 1 指标 | 指标可比较 | 柱状图；类别 >15 自动横向，>20 应用 Top20 |
| 9 | 无时间维 + 1 类别维 + 2..4 指标 | 指标单位兼容 | 分组柱状图 |
| 10 | 恰好 1 时间维 + 1 类别维 + 1 指标 | 满足既有透视规则且未命中更高项 | 透视表 |
| 11 | 其他 | 无唯一可靠图 | 明细表 |

饼/环形图不作为默认图。它是“1 类别维 + 1 个非负、可加指标、类别基数 ≤6”时的兼容手动选项，避免把排名问题默认解释为构成问题。

## 6. v1 图表兼容矩阵

| 图形 | 必需绑定 | 自动变换 | 不兼容条件 |
|---|---|---|---|
| 指标卡 | 1..8 指标，通常为单行 | 数字格式化，不求和 | 多行且未明确选行；非数值；混合单位无法分组 |
| 折线图 | 1 时间维 + 1..5 指标，或时间 + 1 系列维 + 1 指标 | 时间升序；NULL 保留为断点 | 无时间；重复时间键无法唯一表达；总点数超限 |
| 柱状图 | 1 类别维 + 1..4 指标 | 按主指标降序；类别 >15 时推荐横向 | 无类别；指标不可比较；类别值全空 |
| 条形图 | 同柱状图 | 类别 >20 应用 Top20；长名称保留 tooltip | 同柱状图 |
| 饼/环形图 | 1 类别维 + 1 非负可加指标 | ≤6 直接展示；>6 为 Top5+其他 | 负数、比率/均值/UV 等不可加指标、类别 >50、总和为 0 |
| 漏斗图 | §8 的合法步骤 + 指标族 + 明确行 | 保持步骤顺序；计算展示级转化/流失 | 步骤 <3 或 >8；多行未选；非数值；步骤重复 |
| 透视表 | 1 时间维 + 1 类别维 + 1 指标 | 时间升序，不填补缺失值 | 重复键冲突；类别过多 |
| 明细表 | 任意结果 | 用户排序只影响当前视图 | 无列时为空状态 |

图表不改变明细表原始行。TopN、“其他”和排序只作用于图表数据，并在界面中明确标记。

## 7. 结果区交互设计

### 7.1 信息层级

结果区从上到下分为：

1. **查询状态行**：行数、耗时、扫描行数/字节、是否截断。
2. **视图工具栏**：`透视`（兼容时出现）、`明细`、`图表`。
3. **图表工具栏**：当前推荐/手动图形、字段设置、恢复自动、变换标签。
4. **内容区**：图表或表格。
5. **必要提示**：推断失败、配置失效、超量或数据语义警告。

查询状态和数据警告不得塞入图表 tooltip，必须在 hover 之外可见。

### 7.2 图表类型选择

- 进入“图表”后显示一个图形下拉，不平铺全部按钮。
- 第一项为 `自动：{推荐图形}`。
- 第二组只列当前结果兼容的图形。
- 不兼容图形放在“不可用”组，禁用并提供原因；不得直接隐藏，避免用户不知道能力存在。
- 用户选择图形后不重新请求，并显示 `手动` 状态。
- “恢复自动”重新运行本地推荐，不重新请求。

### 7.3 字段设置

- 使用工具栏 Popover 或侧边 Drawer，不使用阻断式 Modal。
- 根据图形显示所需槽位：时间轴、类别轴、指标、系列、步骤、指标族、分组行、排序指标、TopN、单位。
- 字段选择项同时显示列名、ClickHouse 类型、当前角色和置信度。
- 不允许同一列同时承担互斥角色。
- 保存前若配置不完整，保持原图/表格并在字段旁显示可操作错误。
- 用户修改字段后可“应用配置”“恢复自动”；关闭未应用设置不改变当前图。

### 7.4 表格与结果尺寸

- 明细表不分页，展示本次接口实际返回的所有行；当前页面默认请求 1000 行，但接口和显式 SQL `LIMIT` 可能返回更多，不能把 1000 当成响应硬上限。
- 大于 200 行时使用虚拟滚动，避免一次挂载全部 DOM 行。
- 返回超过 10000 行时继续保留虚拟表格，但图表不做抽样或局部推断，回退表格并提示缩小 SQL/时间范围。
- 结果区默认高度 360px，可在 240px 至 70vh 范围内调整。
- 拖拽不得是唯一调整方式，提供“展开结果”“收起结果”按钮和键盘可操作分隔条。
- 图表随容器调整调用 resize，不出现外层 280px、内层 320px、图表 360px 的高度冲突。
- 窄于 960px 时结果区可进入全屏，字段设置使用全屏 Drawer。

## 8. SQL 漏斗产品契约

### 8.1 支持的数据形状

v1 支持两种来源：

1. **单行宽表**：至少 3 个按顺序编号的指标列，例如 `1.加载开始UV`、`2.加载成功UV`、`3.进入房间UV`。
2. **多行宽表 + 明确分组列**：每行代表一个场景/房间/商品，用户必须先在字段设置或图表上方选择一行，漏斗只展示该行。

长表 `step_order + step_name + value` 仅在架构实现已提供明确绑定时兼容；不得靠任意三列自动猜测。

### 8.2 步骤与指标族

- 步骤编号必须连续、唯一，按编号排序，ECharts 不得按数值重新排序。
- 列名中的 `UV`、`PV` 可形成两个指标族；默认优先 UV，有且仅有 PV 时使用 PV。
- 用户可切换 UV/PV，切换不重新请求。
- 手动配置允许选择 3..8 个指标列并拖动或用上移/下移按钮排序。
- 步骤名默认去掉数字前缀和 UV/PV 后缀，用户可在字段设置中修改展示名。

### 8.3 多行与聚合红线

- 多行结果不得取第一行作为默认漏斗。
- 多行结果不得跨行求和 UV、去重人数、比率、均值或分位数。
- 多行合法漏斗默认显示“选择 {分组列} 后查看漏斗”，并保留明细表。
- 如果业务需要总体漏斗，用户必须在 SQL 中直接计算总体行。

### 8.4 转化与异常

- 逐级转化率 = 当前步骤值 / 上一步值；总转化率 = 当前步骤值 / 第一步值。
- 分母为 0 时显示 `--`，不显示 0%。
- 数值出现负数时不兼容漏斗。
- 后一步大于前一步时仍保持业务步骤顺序，但显示警告：`该结果不是单调漏斗，请核对步骤口径。`
- tooltip 和可见标签同时展示原始值、逐级转化率；不得只通过 hover 提供关键数字。

## 9. 保存、重开与看板复现

### 9.1 保存行为

创建或覆盖 SQL 卡片时必须保存：

- 自动/手动模式；
- 图形类型；
- 字段角色与绑定；
- 系列和指标顺序；
- 排序、TopN、“其他”；
- 数字单位和百分比口径；
- 漏斗步骤、指标族和选中的分组行；
- 配置 schema 版本。

精确字段契约由架构文档定义。不得保存可执行函数、任意 ECharts option 或用户脚本。

### 9.2 未保存状态

- 用户改变图形或字段配置后，页面显示未保存状态。
- 切换卡片或离开页面前，沿用现有未保存确认模式。
- 单纯切换 `透视/明细/图表` 是否作为默认打开视图也应保存。

### 9.3 重开兼容

- 保存配置的列仍存在且类型兼容时，完整恢复。
- 已保存 `mode=auto` 的配置在推荐规则版本未变化时也按保存结果复现；刷新数据不得静默换图。用户点击“恢复自动”时才按当前规则重新推荐并形成新的未保存配置。
- 推荐规则版本变化时保留旧图并提示“有新的自动推荐可用”，用户确认后升级；不得用新规则静默改写已保存结论。
- 列缺失、改名或类型变化时，不渲染错误图；显示“图表配置已失效”，回退表格，并允许重新配置。
- 旧 SQL 卡没有图表配置时，继续以表格展示，用户主动选择“自动图表”并保存后才升级。
- 无效配置不得在未确认时自动覆盖原保存值。

### 9.4 看板行为

- 看板 SQL 卡执行原有 SQL refresh，使用同一只读渲染内核展示保存配置。
- 看板不提供字段编辑；提供“在 SQL 分析中编辑”入口。
- 看板空间不足时优先保持数据可读，图例折叠、标签省略并提供 tooltip；不能完整表达时显示表格 fallback 和原因。
- 分享/只读看板与拥有者看到相同图表口径。

## 10. 状态、提示与恢复

| 状态 | 用户看到什么 | 可执行恢复 |
|---|---|---|
| 未查询 | `执行 SQL 后查看表格和图表` | 执行查询 |
| 查询中 | 保留上次结果并覆盖轻量加载状态；首次使用骨架屏 | 等待或继续编辑，不显示空白闪烁 |
| 空结果 | `当前条件没有数据`，保留列信息时展示列头 | 修改时间/条件后重试 |
| 推断成功 | `自动：{图形}` + 推荐原因 | 切图或配置字段 |
| 推断不确定 | 表格 + 待确认列提示 | 打开字段设置 |
| 图形不兼容 | 禁用项 + 明确原因 | 修改绑定或选择兼容图 |
| 查询已截断 | 警告 `图表基于返回的前 {N} 行，不代表完整结果` | 缩小范围或修改 SQL |
| TopN/其他 | 图表上方显示变换标签 | 调整 TopN 或查看明细 |
| NULL/非数值 | 显示被保留/忽略的数量；NULL 不自动当 0 | 查看表格或修改绑定 |
| 配置失效 | 表格 + 缺失/变更字段列表 | 重新配置，不静默覆盖 |
| 返回行过多 | 表格 + `返回超过 10000 行，图表未抽样` | 缩小 SQL/时间范围 |
| 点数超限 | 表格 + `结果点数过多，缩小范围后出图` | 修改 SQL/时间范围 |
| 渲染异常 | `图表渲染失败，原始表格仍可用` | 重试渲染或切表格 |
| 漏斗多行未选 | `选择 {维度} 后查看漏斗` | 选择一个分组行 |
| 漏斗非单调 | 可见 warning，不改变步骤顺序 | 核对 SQL 口径 |

所有错误必须保留查询结果和用户配置，不清空可恢复数据。

## 11. 数据边界、格式、响应式与无障碍

### 11.1 数据边界

- 折线图最多 5 个系列，单系列最多 1000 点，总点数最多 5000；超出不静默采样。
- 柱/条在类别 >15 时改为横向；类别 >20 时应用 Top20。TopN 按用户指定主指标排序，未指定时按第一个指标；NULL 排末尾，同值按原始行序稳定排序。
- 饼/环形最多 6 个扇区；超过时使用 Top5+“其他”，但仅适用于可加指标。
- 漏斗 3..8 步。
- 指标卡最多 8 个；超过时回退表格并提示选择指标。
- 时间数据按实际时间升序；缺失时间桶保持缺口，不补 0。
- NULL 保持 NULL；只有原始值明确为 0 才绘制 0。
- 超过 JavaScript 安全整数范围的数值不直接转成 Number 绘图，提示用户在 SQL 中缩放或转换。

### 11.2 单位与坐标轴

- 柱状图数值轴必须包含 0 作为基线；存在负数时轴域同时覆盖负值，不把负值裁掉。
- 折线图不强制从 0 起，但必须显示刻度范围，禁止截断造成夸大；比率、货币和时长按单位设置格式化。
- `_ %`、`percent` 等明确百分数按 0..100 展示；0..1 比率与 0..100 百分数不得仅凭“率”字自动互换。
- 用户确认的单位随图表配置保存。
- 混合单位指标不得放在同一数值轴；v1 不提供双轴。

### 11.3 可访问性

- 图表开启 ECharts ARIA 描述，并提供可被读屏读取的图表摘要。
- 所有选择器、配置入口、恢复操作和结果分隔条可键盘操作，具有可见焦点。
- tooltip 不是读取值的唯一方式；关键数值在标签、摘要或表格中可获得。
- 系列不能只靠颜色区分，结合线型、标记、直接标签或图例文本。
- 文本和控件满足 WCAG AA 对比度；错误/警告不只依赖红黄颜色。
- 支持浏览器 200% 缩放；窄于 960px 时提供全屏结果模式。
- 尊重 `prefers-reduced-motion`，图表切换只使用状态过渡，不使用装饰动画。

## 12. 验收标准（程序门禁要素②）

### 12.1 核心识别与推荐

- [ ] **CHART-AC01**：自由 SQL 列不含 `g_`/`m_` 前缀时仍可识别并出图；现有事件分析图表不回归。
- [ ] **CHART-AC02**：Builder `按小时 × count()` 唯一推荐折线图，并显示推荐原因。
- [ ] **CHART-AC03**：`日期 + 1..5 指标` 推荐折线；日期严格按时间排序，NULL 为断点。
- [ ] **CHART-AC04**：`country + count()` 推荐柱状；类别 >15 自动横向，类别 >20 才应用并显示 Top20 标签；NULL 排末尾且同值排序稳定。
- [ ] **CHART-AC05**：`os + uniqExact(distinct_id)` 推荐柱状，饼图仅作为兼容手动选项；切换不重新请求。
- [ ] **CHART-AC06**：无维度单行 1..8 指标推荐指标卡，显示行内原值，不跨行求和。
- [ ] **CHART-AC07**：数字型 `room_id` / `error_code` 不得仅因类型为数值自动认定为指标。
- [ ] **CHART-AC08**：推荐规则每次只产生一个默认；无唯一结果时回退明细表。

### 12.2 用户控制与状态

- [ ] **CHART-AC09**：用户在两次操作内打开字段设置并修正 x 轴、指标或系列，不需要修改 SQL。
- [ ] **CHART-AC10**：图形下拉区分自动、兼容和不可用；不可用项可查看具体原因。
- [ ] **CHART-AC11**：图形、字段和 TopN 切换均不重新调用 execute API。
- [ ] **CHART-AC12**：空结果、待确认字段、NULL、混合单位、截断、点数超限、配置失效和渲染异常均按 §10 展示，且保留表格。
- [ ] **CHART-AC13**：截断结果明确写明“基于返回行”，不得显示成全量结论。
- [ ] **CHART-AC14**：TopN、其他、百分比格式和行选择均以可见状态标签披露。

### 12.3 漏斗

- [ ] **CHART-AC15**：单行 `1.加载开始UV` 至 `4.退出房间UV` 自动推荐四步漏斗，步骤顺序不按数值重排。
- [ ] **CHART-AC16**：同时存在 UV/PV 列时默认 UV，可本地切换 PV；分母为 0 显示 `--`。
- [ ] **CHART-AC17**：内部场景示例 SQL 返回最多 50 个场景时不取首行、不跨行累加；先要求选择场景，再展示该行漏斗。
- [ ] **CHART-AC18**：后一步大于前一步时保持顺序并显示非单调口径警告。
- [ ] **CHART-AC19**：手动漏斗支持选 3..8 个指标和键盘上移/下移排序。

### 12.4 保存与看板

- [ ] **CHART-AC20**：新建和覆盖 SQL 卡片均保存完整图表配置与 schema 版本。
- [ ] **CHART-AC21**：重开卡片恢复图形、绑定、排序、TopN、单位和漏斗行选择；保存的自动配置在推荐版本未变化时也不因刷新静默换图。
- [ ] **CHART-AC22**：保存配置字段缺失/变型时回退表格、列出原因、不覆盖原配置。
- [ ] **CHART-AC23**：旧 SQL 卡没有配置时继续显示表格，主动选择并保存后才升级。
- [ ] **CHART-AC24**：看板 SQL 卡刷新后使用同一只读渲染内核，结果与 SQL 分析页一致；看板没有图表编辑器。

### 12.5 性能、响应式与无障碍

- [ ] **CHART-AC25**：超过 200 行的结果表使用虚拟滚动；返回 >10000 行或图表总点数 >5000 时不渲染、不采样，提示缩小范围，原始表格仍可查看全部返回行。
- [ ] **CHART-AC26**：结果区可拖动和键盘调整，在 240px..70vh 内稳定 resize；960px 以下可全屏。
- [ ] **CHART-AC27**：200% 缩放下工具栏、字段设置、图例和错误信息可达且不遮挡主要操作。
- [ ] **CHART-AC28**：仅键盘可完成切视图、选图、改字段、恢复自动和选择漏斗行。
- [ ] **CHART-AC29**：读屏可获得图表标题、摘要、系列和关键值；颜色不是唯一编码。
- [ ] **CHART-AC30**：减少动态效果偏好下关闭非必要动画。

### 12.6 回归与工程门禁

- [ ] **CHART-AC31**：把生产 45 张 SQL 卡的数据形状脱敏固化为回归清单，每张记录期望默认视图、字段角色、警告和不得发生的聚合。
- [ ] **CHART-AC32**：前端为列分类、推荐、兼容、数据规范化、漏斗适配、配置恢复和结果状态提供独立测试。
- [ ] **CHART-AC33**：后端测试覆盖 chart_config 保存/覆盖/读取、旧卡 fallback 和非法配置拒绝。
- [ ] **CHART-AC34**：前后端 build、test、lint 通过。
- [ ] **CHART-AC35**：`python3 scripts/arch_ratchet.py` 通过；不得扩大既有 `common`、`shared`、`utils` 结构债。
- [ ] **CHART-AC36**：生产只读验收覆盖 SQL 分析页、保存重开、看板复现和内部场景多行漏斗；不修改 ClickHouse 查询与数据。

## 13. 成功标准

本 phase 完成需要同时满足：

1. CHART-AC01 至 CHART-AC36 全部通过并留有证据。
2. 重新进行 Nielsen 评审达到 ≥32/40，且没有 P0/P1。
3. 45 张生产 SQL 卡无错误图、无静默 UV/比率聚合、无页面崩溃。
4. 用户能在不改 SQL 的前提下纠正一次错误字段推断并保存复现。
5. 看板和 SQL 分析页对同一卡片给出一致图表语义。

## 14. 风险与依赖

| 风险/依赖 | 处理 |
|---|---|
| 自由 SQL 无法完整推断业务语义 | 显式字段设置 + 置信度 + 表格 fallback |
| UInt64/Decimal 以字符串返回 | 按 ClickHouse 类型严格规范化，超安全整数拒绝绘图 |
| 多行 UV 无法安全汇总 | v1 明确禁止隐式聚合，多行漏斗选择单行 |
| 图表配置与旧卡不兼容 | 版本化配置、旧卡保持表格、失效回退 |
| 结果区尺寸不足 | 可调整结果区 + ResizeObserver + 窄屏全屏 |
| Canvas 无障碍不足 | ECharts ARIA + 文本摘要 + 始终可达表格 |
| 生产 SQL 形状复杂 | 45 张现有卡脱敏回归，不靠少量理想样例 |
| 当前留存功能未实现 | 留存矩阵不纳入本 phase |
