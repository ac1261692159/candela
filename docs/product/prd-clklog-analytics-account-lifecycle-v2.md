# PRD：账号生命周期 v2（邮件通道：忘记密码 / 建号设密邮件 / 项目邀请）

> phase: clklog-analytics-account-lifecycle-v2
> 版本：v1.0（2026-09-17）｜ 上游：`research-clklog-analytics-member-lifecycle.md` §5 第二段、`prd-clklog-analytics-account-lifecycle-v1.md`
> 下游：`docs/architecture/clklog-analytics-design-account-lifecycle-v2.md`
> 本文档是「账号生命周期第二段」的**产品层**权威：SMTP 邮件通道加持下的自助密码找回、免代设密码建号、按邮箱邀请入项目。

---

## 1. 背景与问题

v1 交付后，管理员仍要当面/IM 转交密码（临时密码降级方案），用户忘密仍依赖管理员重置，项目加人仍要先建号再加成员两步走。调研结论（research §2.2）：私有化产品配好 SMTP 后，建号 / 找回 / 邀请全部邮件自助。本 phase 打通邮件通道，让这三件事闭环。

## 2. 阶段目标与范围（门禁要素①）

1. **邮件通道**：新增 `AUTH_SMTP_*` 独立配置组（复用告警 SMTP 的参数模式），服务端按**收件人语言**渲染邮件（13 门语言模板）；未配置时相关能力自动降级为 v1 行为（代设密码），不报错。
2. **忘记密码（自助找回）**：登录页入口 → 输入用户名或邮箱 → 若账号存在且绑定了邮箱，发送一次性重置链接（30 分钟有效，用后立刻失效并吊销全部会话）；无论账号存在与否，页面统一提示，防枚举。
3. **建号设密邮件**：用户管理创建账号时二选一——「发送设密邮件」（默认，管理员不见明文）或「直接代设密码」（v1 行为，强制首登改密）；设密链接 72 小时有效。
4. **项目邀请（按邮箱）**：项目成员管理支持直接输入邮箱邀请，带角色：
   - 邮箱已有账号 → 直接成为成员，收到通知邮件；
   - 邮箱未注册 → 发送邀请邮件（7 天有效）；受邀人点开链接注册新账号（用户名/显示名/密码），落地即自动入会；
   - 已登录且邮箱匹配的受邀者打开链接 → 一键接受入会；
   - 项目 owner/管理员可撤销未接受的邀请。

## 3. 验收标准（门禁要素②）

- [ ] **AM-1**：配置 `AUTH_SMTP_*` 后，`POST /auth/forgot-password` 提交存在账号的用户名/邮箱 → 收到重置邮件；过期/重复使用同一链接 → 页面提示失效；重置成功后旧会话全部失效，新密码受 v1 策略约束。
- [ ] **AM-2**：忘记密码对不存在的用户名/未绑邮箱的账号返回**相同文案**（枚举安全），不泄露账号是否存在。
- [ ] **AM-3**：同一收件邮箱 60 秒内重复请求重置/设密/邀请邮件 → 第二次起被拒并提示稍后再试。
- [ ] **AM-4**：创建用户选「发送设密邮件」：不填密码即可创建，目标邮箱收到设密链接；用户点击链接设密后可直接登录；链接 72 小时后失效；未配置 SMTP 时该选项隐藏，表单退回 v1 代设模式。
- [ ] **AM-5**：成员管理输入未注册邮箱 + 角色发出邀请 → 邮件到达；用链接注册后自动成为该项目该角色成员；链接 7 天后失效；撤销后链接不可用。
- [ ] **AM-6**：邮箱已有账号时邀请 → 不入邀请表直接成为成员；重复邀请已入会成员返回 409。
- [ ] **AM-7**：邀请接受页对「已登录但邮箱不匹配」的访问者提示账号不匹配，不允许接受。
- [ ] **AM-8**：邮件正文按收件人 `locale` 渲染（无则平台默认 zh-CN）；忘记密码/设密/邀请/邀请通知四类模板 13 门语言齐全。
- [ ] **AM-9**：发信、邀请创建/接受/撤销、重置成功均落审计（`auth_` 前缀沿用 v1 通道）。
- [ ] **AM-10**：`i18n_check` / `i18n_scan --check` / `arch_ratchet` 通过；新增单测覆盖令牌生命周期与枚举安全；未配置 SMTP 时全站无新增报错。

## 4. 非目标（门禁要素③）

- 不做成员有效期（`SaProjectMember.expires_at`）与休眠回收（第三段）。
- 不做显式「邮箱已验证」标记位（重置/设密/邀请链接到达即事实验证；独立验证留待第三段）。
- 不做短信通道、手机号、SSO/LDAP、自助注册、图形验证码。
- 不做邮件队列与后台重试：同步发送，失败返回明确错误并留审计；不做退信处理。
- 不改动告警 `ALERT_SMTP_*` 的配置语义与存量行为（两组配置独立）。
- 不做邀请邮件的富文本品牌模板（本期纯文本+链接即可）。

## 5. 产品规则

### 5.1 邮件通道与降级

| 条件 | 行为 |
|------|------|
| `AUTH_SMTP_HOST` 已配置 | 忘记密码 / 设密邮件 / 邀请邮件全量可用 |
| 未配置 | 忘记密码页提示「请联系管理员重置」；创建用户隐藏「发送设密邮件」；邀请仅限已有账号（按用户名选择，v1 行为） |

### 5.2 令牌规则（三类一律）

- 生成：`crypto.randomBytes(32)` hex；**仅存 SHA-256 哈希**，明文只在邮件链接里；
- 时效：密码重置 30 分钟、设密 72 小时、邀请 7 天；
- 一次性：消费成功即标记 `used_at`；同一用户同类新令牌签发后，旧同类令牌立即作废；
- 消费成功副作用：重置/设密 → 吊销全部会话、清强制改密与锁定；邀请 → 标记 `accepted_at`；
- 限流：同一收件邮箱任意类型邮件 60 秒一封（DB 最近一次签发时间判断）。

### 5.3 忘记密码交互

登录页「忘记密码」→ 输入框（用户名或邮箱）→ 提交后统一提示「如果账号存在且绑定了邮箱，重置邮件已发送」→ 邮件链接打开重置页（URL 带 token）→ 新密码表单（v1 策略）→ 成功跳登录页。

### 5.4 建号设密邮件

创建用户弹窗增加方式切换：**发送设密邮件**（要求填邮箱，无需密码）/ **直接代设密码**（沿用 v1：≥8 位 + 强制首登改密）。默认取前者（SMTP 可用时）。

### 5.5 项目邀请

- 成员管理「添加成员」输入框支持键入完整邮箱（正则识别）；已在簿账号照旧下拉选择（v1 行为不变）。
- 邀请列表区：展示待接受邀请（邮箱、角色、过期时间、撤销按钮）。
- 接受页（公开路由 `/sa/invite/<token>`）：按登录态分三态——未登录 → 注册表单（同时校验邮箱不可改）；已登录且邮箱匹配 → 「接受邀请」按钮；已登录但邮箱不匹配 → 只读提示并给出「换账号」出口。

### 5.6 审计事件（沿用 v1 `ops_action_log` 通道）

| action | 时机 |
|--------|------|
| `auth_reset_request` | 忘记密码请求（无论是否命中，detail 只记 hash 化输入，防枚举泄漏） |
| `auth_reset_complete` | 重置/设密完成 |
| `auth_setup_send` | 建号设密邮件签发 |
| `auth_invite_create` / `auth_invite_accept` / `auth_invite_revoke` | 邀请创建/接受/撤销 |
| `auth_mail_failed` | SMTP 发送失败（detail 含错误摘要） |

## 增补 v1.1（2026-09-18）：超管网页配置 SMTP（阶段目标⑦）

**动机**：env 配置要动服务器再重启，运维成本高。改为优先存库（凭证 AES-256-GCM 加密，复用 `ALERT_CONFIG_KEY` 主秘钥体系），env 保留作兜底与初次引导。

**规则**：
- 「设置 → 用户管理」页新增「邮件通道」区：超管可配置 host / port / secure / user / pass / from 与启用开关；**密码永不回显**（只报 has_password）。
- 生效优先级：库内已启用配置 > env `AUTH_SMTP_*`；库内未配置或未启用 → 按 v1.0 降级规则。
- 保存缺主密钥（`ALERT_CONFIG_KEY` 未注入）且要写入新密码 → 拒绝并提示（与告警通道同策略）。
- 一键「发送测试邮件」到指定邮箱，验证连通性；保存与测试动作均落审计（`auth_` 前缀），审计不含任何密钥材料。
- 运行时热生效：发送按 60 秒缓存读取生效配置，改库即生效不需重启。

**验收（追加）**：
- [ ] AM-11：超管在网页保存 SMTP（含密码）后立即生效，测试邮件可达；GET 接口与页面任何位置不出现明文密码。
- [ ] AM-12：库内配置与 env 同时存在时以库内为准；清空（禁用）库内配置后回落 env 行为。
- [ ] AM-13：主密钥缺失时保存带新密码的配置 → 400 提示；只改非密字段仍可保存。
