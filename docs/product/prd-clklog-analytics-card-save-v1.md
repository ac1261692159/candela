# PRD：分析卡片覆盖保存 / 另存为

> phase: clklog-analytics-card-save-v1
> 上游：`prd-clklog-analytics-workbench-v1.md` WB-8、`prd-clklog-dashboard-sql-cards-v1.md` PRD-DSC2/3
> 下游：`docs/architecture/clklog-analytics-design-card-save-v1.md`

---

## 1. 阶段目标与范围

从看板或卡片库打开已有卡片（URL 带 `?card=`）时，事件分析、漏斗分析、留存分析、自定义 SQL 都能**覆盖当前卡**，也能**另存一张新卡**。无 `?card=` 时仍只新建。

对标 Grafana / 神策：覆盖写回原资产，另存生成副本；同一层不把「保存」做成只能新建。

## 2. 验收标准

- [ ] CS-1：无 `?card=` 时，四个分析页主保存按钮文案为「保存为卡片」，走新建弹窗（名称必填；分析三类可选看板与图表类型；SQL 只填名称）。
- [ ] CS-2：有 `?card=` 时同时出现「覆盖保存」和「另存为卡片」。覆盖不改卡片 id / 名称 / 看板引用，只更新当前查询内容（分析三类含 `_form` 快照；SQL 含 sql/图表配置/时间范围）。
- [ ] CS-3：覆盖成功 toast 含卡片名；失败走现有错误提示。另存成功后 SQL 页切到新卡；分析三页保持当前卡，新卡进卡片库。
- [ ] CS-4：无查询 DSL / SQL 未就绪时保存按钮不可用或不可提交（与现网一致：分析页无结果区不展示保存；SQL 可在编辑后保存）。
- [ ] CS-5：单测覆盖 `CardSaveActions` 有卡/无卡按钮；`FunnelResult` 无卡仍显示「保存为卡片」；SQL 有卡可点「另存为卡片」并 `saveSqlReport`。

## 3. 非目标

- 不改卡片 id 规则、RBAC、看板布局。
- 不做保存前 diff、不做版本历史。
- 不在覆盖时弹出改名或改看板。
- 不强制刷新看板缓存（下次看板刷新或 TTL 到期后看到新 DSL）。

## 4. 体验

| 状态 | 主按钮 | 次按钮 |
|------|--------|--------|
| 未绑定卡片 | 保存为卡片（弹窗新建） | 无 |
| 已打开卡片 | 覆盖保存（立即写入） | 另存为卡片（弹窗新建） |

覆盖是高频动作，用主按钮。另存要填新名称，避免误把副本写进原卡。删除卡片仍独立、危险样式，不并进保存菜单。
