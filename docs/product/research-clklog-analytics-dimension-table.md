## 1. 它是什么

**给「键型属性」补一层查表能力。**

事件里通常只上报 `item_info=10001` 这种 ID；分析师想要「商品名 / 品质 / 资源」就得查一张业务表。数据表（数数叫法）/ 维度表（神策叫法）就是这张表：上传 Excel/CSV 建表 → 指定主键 → 把表绑到一个属性上 → 表里的非主键字段变成**可筛选、可分组、可当属性用**的新属性。

本质是 **事实表（事件/用户）× 维表 的 Join 建模**，两家的差别只在「生成物叫什么、在哪管」：

| | 关系建立在哪 | 生成物 | 命名 |
|---|---|---|---|
| 数数 | **数据表侧**（数据表 → 配置关联属性） | **维度表属性**，与事件属性/用户属性并列 | `#event_name@quantity` |
| 神策 | **元数据侧**（事件表/用户表 → 维度表） | 先建维度关联，再经**虚拟属性**引用 | `别名.字段名` |

和两件已有能力区分：**维度字典**（神策）只是「属性值 → 映射值」的值级替换，不引入新字段，比维度表轻得多；**物化列**是「把属性从 JSON 提成物理列」，解决性能不解决查表。

### 2.2 创建数据表（三步向导）

`1 上传数据表 → 2 确认表结构 → 3 数据预览 → 保存 → 数据表创建成功`。

**第 1 步 上传**

- 拖拽或点击上传，`支持 UTF-8 格式的 CSV 或 Excel`；解析成功后可「重新上传」。
- 提示原文：`你可以参考下面的维度表模板 或 前往 查看自动上传 API` —— 即**界面手动上传**与**API 自动上传**是两条并存入口（§3.5）。
- 页面示例表：`item_info`(主键) / `quantity` / `quality` / `resource`。
- 规则原文两条：① 以表头作为字段名，字段名只能以小写字母开头，包含小写字母、数字、下划线 `_`，长度最大 50 个字符；② **数据表会以第一列作为主键关联**。

**第 2 步 确认表结构**

- 数据表名称（`test1`）、备注（`test_excel`；右下角计数器 `10 / 120` → 备注上限 120 字，与手册一致）。
- 字段表格三列：**字段 / 数据类型 / 显示名**。首列 `item_info` 带「主键」标签且显示名为 `item_info`，其余显示名留空（`请输入`）→ 不填则等于字段名。
- 数据类型下拉四项：**数值 / 文本 / 时间 / 布尔**（截图展开态）。

**第 3 步 数据预览**

- 头部两个数字：`成功行数 3 行`、`丢弃行数 无`。
- 表格按字段展示解析结果；保存后弹「数据表创建成功」。

### 2.3 更新数据表

弹窗 `1 更新数据表 → 2 确认更新细节 → 3 数据预览`。

- 更新方式单选：**增量更新**（默认选中）/ **替换更新**。
- 增量更新规则原文三条：① 表头需要与下方预览数据的表头一致；② 表格首列将作为主键；③ 更新方式：新增主键及其数据，或更新已有主键的数据。
- 上传区提示：`支持 UTF-8 格式的 CSV 或 Excel`。

### 2.5 配置关联属性（本调研的核心屏）

弹窗标题 `配置关联属性（数据表: test1）`，顶部约束说明原文：

> 数据表 test1 的主键 `item_info` 为【文本】类型，仅可关联数据类型为【文本】【列表】【时间】的属性，作为其维度表

结构：

- **左侧**：`关联属性 1 / 关联属性 2 / 关联属性 3` 锚点 + `+ 属性`。截图三组都有内容，未见上限提示（手册写「一个数据表最多关联 5 个属性」，见 §9）。
- **每组**：`选择属性` 下拉（截图出现 `事件名称(#event_name)`、`事件时间(#event_time)`）+ 下方字段映射表。

字段映射表列：`字段 / 数据类型 / 维度表属性名 / 维度表属性数据类型 / 维度表属性显示名`。

| 字段 | 数据类型 | 维度表属性名 | 维度表属性显示名 |
|---|---|---|---|
| `item_info`（主键） | 文本 | `-`（**主键不生成属性**） | - |
| `quantity` | 文本 | `#event_name@quantity` | `quantity_事件名称`（可改） |
| `quality` | 文本 | `#event_name@quality` | `quality_事件名称` |
| `resource` | 文本 | `#event_name@resource` | `resource_事件名称` |

选中的是 **事件时间 `#event_time`** 时，`选择属性` 下方多出 **时间粒度** 下拉，六档：

`年（格式:2099）` / `月（2099-07）` / `日（2099-07-31）` / `小时（2099-07-31 09）` / `分钟（2099-07-31 09:16）` / `秒（2099-07-31 09:16:48）`；此时属性名形如 `#event_time@resource`，显示名 `resource_事件时间`。

要点：**改数据类型列在此屏只读**（跟着字段走），能改的只有显示名；生成规则是「关联属性名 `@` 字段名」，自动批量生成。

## 3. 数数手册补充（截图之外）

### 3.1 创建与字段

- 建表方式两种：手动上传表格、数据表 API（自动上传）。表结构 = 列名 + 数据类型 + 主键（首列）。
- 字段类型四种：数值 / 文本 / 时间 / 布尔。
- 文件：UTF-8 的 CSV 或 Excel；**单次上传 Excel ≤ 100M、CSV ≤ 500M**，超限改用多次增量导入。**未给行数上限**。
- 解析错误行可下载错误详情（创建页）。

### 3.2 主键与可关联范围

- 默认首列为主键；**主键值不可重复**，重复时自动去重、**取最小行号那条**。
- **主键数据类型创建后不可变更**。
- 主键类型决定能关联哪些属性：

| 属性数据类型 | 能否加维度表 / 主键要求 |
|---|---|
| 文本、数值、布尔 | 可加；**主键类型须与属性相同** |
| 时间 | 可加；**主键须为文本**，且需指定时间格式（粒度） |
| 列表 | 可加；**主键须为文本**；且**表内仅文本字段**才会生成维度表属性 |
| 对象、对象组 | **不可**加；对象的子属性可以 |

- 不可关联的对象：已加维度表的属性；创建规则中用了**维度表属性**的虚拟属性；创建规则中用了**用户属性**的**事件虚拟属性**。

### 3.3 更新与结构变更

| 场景 | 走哪种更新 |
|---|---|
| 只改数据内容 | 增量更新（按主键 upsert，未出现在文件里的主键不受影响）或替换更新 |
| 改字段**显示名** | 增量更新时改 |
| **增减列、改列数据类型**（主键除外） | 替换更新时改 |
| 表结构变更 | **需发布后生效**；列表「发布状态」提示「存在未发布更新」，发布时确认影响的资产 |

增量更新的硬约束：**上传文件与当前表结构须完全一致（列名 + 列顺序）**。

### 3.4 生命周期

- **删除不可恢复**，并级联删除由该表生成的维度表属性（与神策的"禁止删"策略相反，见 §4.2）。
- **版本还原**：在「数据表版本记录」还原，还原**表结构与数据**，**不含**表与属性的关联关系。
- 维度表属性有项目级上限（默认 **3000**，超出无法关联成功）。

### 3.5 Open API

数据表 API（`/open/datatable/*`，POST，鉴权 = query `token` + `projectId`）：

| 接口 | 用途 |
|---|---|
| `uploadFile` | 上传文件 → 返 `fileId` |
| `createDatatable` | 用 `fileId` + `datatableColumns[{columnName,dataType}]` 建表 |
| `updateDatatable` | `updateType=INCR_UPDATE \| REPL_UPDATE`；**仅支持内容更新，不支持字段增删/改类型** |
| `bindAssociatedProperty` | 绑定主属性（`associatedPropertyTableType=event\|user`，时间属性带 `timestampJoinFormat`） |
| `unbindAssociatedProperty` | 解绑，同时删除已生成的维度属性 |

出参摘要：创建返 `fileId`；绑定返 `dimensionProperties[{columnName,selectType}]`；更新返 `succeededRowCount` / `failedRowCount`。

旧版**维度表 API**（v3.8 之前的表用它更新）：`POST /open/dict-create`，`Content-Type: text/csv`，结构描述走 `createParam`（`mainColumn` + `columns`），首列不生成属性；**主键解析错误或重复的行自动丢弃，其他字段类型错误的行置空**；文件上限 200M。

页面未提供**查询**与**删除**接口（删除只在控制台 UI）。

### 3.6 定时更新（材料缺口）

列表有「定时更新」列、创建页有「查看自动上传 API」入口，但**手册正文没有定时更新的机制说明**，本页也没抓到「自动上传 API」的正文。截图那张表该列为 `-`（手动上传）。不臆测，计入 §9 待确认。

## 4. 神策对照

### 4.1 数据表管理（数据接入 › 通用数据接入 › 数据表管理）

纳管范围比数数数据表宽：用户表、事件表、标签表、分群表、自定义表一屏管理。

| 维度 | 神策 |
|---|---|
| 建表方式 | **直接创建**（表单填字段）、**SQL 创建**（物理表或视图表）、**上传文件**（Excel/CSV） |
| 表类型 | 主键表 / 非主键表 / 视图表；**非主键表必须设分区字段** |
| 主键 | 支持**联合主键**；上传建表时仅 String/Int/BigInt 可作主键，**最多 3 字段**；唯一键亦支持联合 |
| 字段类型 | **7 种**：Bool / Int / BigInt / Number / String / Timestamp / List |
| 命名 | 表名/字段名仅小写字母、数字、下划线且字母开头，**≤100 字符**；显示名 ≤100 且同库/同表内不重复 |
| 上传限制 | 单文件 **≤100M**，最多 **5 个文件 / 20 个 Sheet**，默认首行表头、默认逗号分隔，预览前 100 条 |
| 更新 | ① 数据同步模块（外部数据源定时导入）② 上传更新：**追加数据**（主键表按主键 upsert；非主键表直接追加）/ **替换数据**（先删后写）；仅不带分区的物理表可上传更新，需 SDH ≥ 1.3.1 |
| 删除 | **血缘判断**：被维度关联关系等资源引用时**不能删**；标签/分群产生的表须回原模块删 |
| 权限 | 功能权限「查看数据表 / 管理数据表（范围：全部 或 我创建的）」+ **表数据权限**（决定自定义查询能否查到该表、数据同步能否选它）；创建者永远有且不可取消 |

### 4.2 维度表关联（元数据管理 › 用户表 / 事件表 › 维度表 → 添加维度表）

1. **选择数据表**：只能用数据表管理里的**主键表**和**有唯一键的表**。
2. **关联表别名**：同一张表用不同关联条件多次关联时**必须起别名**；后续创建虚拟属性时按别名引用。
3. **关联条件**：两侧数据类型须一致；**表的主键/唯一键必须作为关联条件且不可删除**；右值可选「当前表属性」或**「固定值」**（即支持等值之外的常量约束）。
4. **生成属性**两条路：
   - **自动批量创建**（需 SDH ≥ 1.3.1）：把维表字段批量建成**虚拟属性**；
   - **手动创建虚拟属性**：引用语法 `维度表别名.字段名`。
5. 已创建虚拟属性的维度表**不能被删除**。

即：关联关系归属**元数据表**，生成物是虚拟属性；数数则是数据表直接绑属性、生成物叫维度表属性。

### 4.3 维度字典（比维度表轻的一条路）

对**已有属性**做值映射（`原值 → 映射值`），不引新字段、不需要 JOIN：

- 上传维度字典模板（UTF-8，逗号分隔，可选 `split` 指定分隔符），映射后**新建虚拟属性**；过滤/分组里带字典的属性会有字典标识。
- 仅**文本、数值**类型可上传字典；对某两类属性上传后，创建出的虚拟属性**类型自动变更**。
- 3.0+ 版本：普通属性已有字典可更新/删除，**删除后不允许再次上传**；虚拟属性可上传/更新/删除，删后可重传。
- 也有 API：`POST /api/property/dict/upload?project=&propertyName=&type=property&isIncrement=true&token=`（`isIncrement` 控制增量）。

### 4.4 虚拟属性（承接维度表的容器）

创建事件的虚拟属性时，可引用范围 = **当前表的普通属性 + 与当前表建立了维度关联的表里的属性**。这是神策把「维度表 → 分析可用属性」串起来的关键一环，也是数数不需要概念（数数直接把维度表属性并列暴露）。

## 5. 两家差异（速查）

| 维度 | 数数 | 神策 |
|---|---|---|
| 主界面 | 数据表（列表 + 三步向导） | 数据表管理（三种建表）+ 元数据侧维度表关联 |
| 关系配置在哪 | **数据表**侧，一张表直接选 N 个属性 | **元数据**侧，事件表/用户表加维度表，可多别名 |
| 生成物 | 维度表属性，命名 `#事件属性@字段` | 虚拟属性，引用 `别名.字段`（自动批量建，SDH≥1.3.1） |
| 关联右值 | 仅属性 | 当前表属性 **或固定值** |
| 键约束 | **首列即主键、单主键、类型不可改、重复值取最小行号** | 主键/唯一键可选，**联合主键 ≤3**，非主键表需分区字段 |
| 字段类型 | 4 种（数值/文本/时间/布尔） | 7 种（含 BigInt/List 细分），列名上限 100 字符 vs 数数 50 |
| 建表方式 | 上传 / 数据表 API | 表单 / SQL（含视图表）/ 上传 / 数据同步任务 |
| 更新 | 增量 / 替换；**结构变更需发布生效** | 追加 / 替换（数据同步或上传，需 SDH≥1.3.1） |
| 删除保护 | **级联删维度表属性** | **有依赖则禁止删**（血缘）+ 标签/分群表回原模块 |
| 轻量值映射 | 无对应物 | **维度字典**（文本/数值属性值级映射） |
| 权限 | 元数据查看/编辑按角色（数据表预览、导出、下载内容） | 功能权限（查看/管理，范围）**+ 表数据权限**（影响 SQL 与数据同步） |
| 版本还原 | 有（还原结构+数据，**不含关联关系**） | 未见同款说明 |

## 7. 差在哪 / 缺口排序

按「分析价值 ÷ 实现与红线代价」排：

1. **维度字典（值 → 值映射）**：神策有、我们无，且 `MetaPropertyDict` 位子已在。不需要上传建表、不需要 JOIN、不碰只读红线，能直接解决「渠道 ID → 渠道名」。**最该先补**。
2. **数据表 + 维度表属性（表级扩展）**：真需求（商品/道具/活动维度），但要新增「上传 → 建表 → 绑定属性 → 查询期 JOIN」整条链路，且必须处理写入权限与守卫白名单（§8）。
3. **更新与运维面**：增量/替换语义、结构变更发布、删除血缘/级联、版本还原。属 2 的配套，不用单独立项。
4. **自动化入口**：数据表 API / 自动上传（含数数未说清的「定时更新」、神策的数据同步任务）。私有化场景价值中等，可在 2 之后按需。
5. **权限**：数据表查看/管理 + 表数据权限（神策把「表数据权限」和 SQL 查询、数据同步绑在一起）。我们 RBAC v2 已规划数据权限，但尚未含「表级」粒度。
6. **不跟的**：SQL 建表/视图表、联合主键 ≤3、分区字段、业务方显示状态、指标平台显示隐藏 —— 属神策通用数据接入的广度，不是本次维度扩展的核心。

## 8. 与我们红线的冲突点（立项前必须先解）

| 红线 | 冲突 | 必须的前提 |
|---|---|---|
| ④ 分析查询必须有界 + 只读账号，禁 INSERT/ALTER/DROP/ATTACH | 上传表格必然要建表写数，走现有只读通道就是违规 | 写入必须由**服务侧独立路径**（新库/新表 + 新消费或同步任务），分析查询侧仍只读 |
| ④ 自定义 SQL 只用只读账号 | 维度表 JOIN 要放开白名单（现在只允许两张表） | 白名单扩展 + 仍强制 `project_name` + 时间范围 + LIMIT/超时 |
| ⑥ DDL 变更先在测试库演练、不可静默改写数据 | 表结构变更 / 替换更新 / 清空删除都要审计与备份 | 结构变更走「发布生效」类显式动作 + 审计记录 |
| ① 不侵入 ClkLog 社区版 | 维表应落在 `clklog_sa` 侧，不往 `clklog.log_analysis` 加列 | 新建表带 `project_name`，与社区版表无耦合 |
| ③ 不可把密钥写入仓库 | 若做数据表 API，token 走 Puppet 模板参数化 | 与现有 `env.epp` 一致 |
