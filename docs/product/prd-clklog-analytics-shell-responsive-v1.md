# PRD：分析平台壳层多分辨率适配 v1

> phase: clklog-analytics-shell-responsive-v1
> 版本：v1.0（2026-09-04）
> 上游：`PRODUCT.md`、`prd-clklog-analytics-workbench-v1.md`、`prd-clklog-ai-analytics-v1.md`
> 下游：`docs/architecture/clklog-analytics-design-shell-responsive-v1.md`
> 像素、档位阈值、槽位宽度以架构文档为 SSOT；本文写行为、优先级和验收。

---

## 1. 阶段目标与范围

浏览器窗口变窄时，壳层按**明确档位**改结构，而不是把三列一起压窄、让文字折成竖排。空间不够时先收菜单，再收 Harness；分析工作台（配置 + 结果）最后让路。

| 模块 | 本次做什么 |
|------|------------|
| 壳层档位 | 按视口宽度在 xl / lg / md / sm / xs 五档之间切换：菜单展开、图标、抽屉；Harness 停靠、收起、覆盖；工作台左右分栏或上下堆叠 |
| 折叠顺序 | 变窄：菜单 → Harness → 工作台分栏。变宽：反向恢复 |
| 最低显示宽度 | 我们自己的按钮、分段、步骤标题、菜单文字不得出现「一行一个字」的竖排；装不下就换档，不继续挤 |
| Harness 宿主 | 停靠态给官方 iframe 的宽度不得低于架构规定的停靠下限；低于下限则改为收起，禁止以 320px 侧栏硬塞官方设置弹层 |
| 工作台 | 分栏/堆叠由壳层档位决定，不再用「内容区 800px 容器查询」单独决策 |

本阶段覆盖登录后 `MainLayout`：左菜单、顶栏、内容区、分析页右侧 Harness。事件/漏斗/留存/SQL 共用同一套档位。

## 2. 验收标准

- [ ] **SH-1**：视口从 ≥1600px 连续缩到 375px，再拉回 1600px，档位变化符合架构 §4 表，无中间态三列同时被压到低于各自下限。
- [ ] **SH-2**：折叠优先级固定为分析工作台 > Harness 停靠 > 菜单文字。不允许出现「菜单仍展开、Harness 已收起」或「菜单仍展开、工作台已堆叠」的自动档位（用户手动展开抽屉除外）。
- [ ] **SH-3**：停靠 Harness 的分配宽度 < 停靠下限时，Harness 必须离开文档流（收起到可点的入口），会话不销毁。
- [ ] **SH-4**：我们壳层内可见中文控件（菜单项、且/或、时间快捷、步骤标题、查询按钮、AI 顶栏 Workspace 名）在所有档位都保持横向书写；禁止出现单列竖字。标题过长只允许单行省略号 + `title`/Tooltip。
- [ ] **SH-5**：分段控件（且/或、时间快捷、口径单选）空间不够时，**整颗芯片换行**，芯片内部文字仍横向；禁止把「跟随系统」「首日新用户」拆成一字一行。
- [ ] **SH-6**：xl（含 14 寸约 1512px）菜单展开 + Harness 停靠（默认 400px）+ 工作台左右分栏；lg/md 菜单收成图标，**底栏保留折叠/展开按钮**；折叠后悬停图标弹出子菜单，顶栏不再重复放汉堡。
- [ ] **SH-7**：仅当剩余宽度不够停靠下限 400 + 工作台堆叠下限时才收起 Harness；md 若仍够停靠则继续停靠（变窄，不先卸掉）。
- [ ] **SH-12**：SQL 页无结果时结果区收成工具条（约 88px），编辑器占满剩余高度；有结果后默认约 360px。Harness 可从默认 400 拖窄到 400、拖宽不超过 `min(560, 32vw)`。
- [ ] **SH-8**：sm/xs 点开 AI 为覆盖层（或全屏），不从工作台再抠一条窄侧栏。覆盖层宽度 ≥ 停靠下限；视口比下限还窄则 100% 宽，但不把官方设置弹层承诺为可用。
- [ ] **SH-9**：用户手动折叠/展开菜单、折叠/展开 AI 的选择在当前档位允许的形态内保留；档位升级后自动恢复「该档默认结构」，不把窄档的全屏 AI 带到 xl。
- [ ] **SH-10**：125% 浏览器缩放按 visual viewport 的 CSS 像素走同一套档位（缩放后的 1280 逻辑宽等于未缩放 1280）。
- [ ] **SH-11**：QA 至少截取并核对这些宽度：1920、1440、1280、1024、768、375（高度 800 与 900 各一档，确认查询按钮与 Harness 设置不被裁出视口）。
- [ ] **SH-13**：顶栏不再放项目选择器和用户菜单。当前项目、退出登录在侧栏「设置」下。xl/lg/md 不渲染空顶栏；仅 sm/xs 顶栏留汉堡打开菜单抽屉。

## 3. 非目标

- 不修改官方 Harness Web 源码、不注入 iframe 内 CSS、不重写官方设置/外观弹层。
- 不把 Harness 做成自制聊天条来规避宽度问题。
- 不把本阶段做成移动 App 或触控优先改版；xs 只保证分析工作台可操作，不保证官方设置弹层完整。
- 不改查询 API、DSL、卡片数据。
- 不引入第二套组件库。
- 不把菜单和 Harness 的收起做成互相抢宽度的自由拖拽竞技场；拖拽只在**已经停靠且宽度 ≥ 下限**时调整停靠宽度。

## 4. 空间优先级（产品规则）

用户在缩窄窗口时要继续配条件、看结果。因此：

1. **分析工作台**（配置轨 + 结果）是主任务，最后放弃左右分栏，永不放弃到「结果变成一条缝」。
2. **Harness** 是辅助，停靠需要足够宽才能用官方 UI；不够宽就收起，让用户点开覆盖层，而不是留一条废侧栏。
3. **菜单文字**最先放弃：先图标，再完全进抽屉。

当前实现的反面教材（必须改掉）：

- 视口 < 960px 才把 Harness 全屏，更宽时一直留窄侧栏，等于 **Harness 最后才让路**。
- 最小宽度 320px / 最大 42vw，官方设置里「浅色 / 深色 / 跟随系统」被压成竖字。
- 工作台用内容区 800px 容器查询，和整窗档位各判各的。

## 5. 档位行为（对用户）

名称与阈值见架构文档。这里只写用户看到什么。

| 档 | 用户看到 |
|----|----------|
| **xl** 宽桌面 / 14 寸笔记本 | 菜单带文字；配置在左、结果在右；AI 停靠约 400px，可拖窄到 400、拖宽不超过约三成视口。 |
| **lg** 更窄笔记本 | 菜单收成图标；底栏一颗按钮折叠/展开；收起后悬停图标弹出子项。顶栏不再放汉堡。AI 仍停靠。 |
| **md** 分屏 | 菜单图标栏 + 底栏折叠钮；悬停选子项。AI 若仍够 400px 下限则继续停靠。 |
| **sm** 平板宽 | 菜单抽屉；AI 默认收起，点开是覆盖层。 |
| **xs** 窄窗 | 同 sm，AI 点开铺满内容区；不承诺官方设置弹层完整。 |

顶栏不再放项目选择和用户头像。当前项目在侧栏「设置」里切换；退出登录同在设置末项。仅 sm/xs 显示一条瘦顶栏（汉堡）。xl/lg/md 顶栏不占高度，内容区直接接在菜单旁。

## 6. 文字与控件（硬性）

适用于我们渲染的 DOM，不含 iframe 内部。

| 允许 | 禁止 |
|------|------|
| 单行 + 省略号（标题、Workspace 名） | `word-break: break-all` / `overflow-wrap: anywhere` 用于导航、按钮、分段、步骤标题 |
| `flex-wrap` 让**整颗**芯片到下一行 | 把一个词或一句中文拆成竖列（一行一个字） |
| 换档、收起、抽屉、覆盖层 | 把容器宽度降到小于该控件的 `min-content` 后仍显示该控件 |
| 配置轨内部纵向滚动 | 查询按钮、步骤标题被裁到看不见且无法滚到 |

官方 Harness：我们不改它的字号与折行。唯一手段是 **不要把 iframe 放到低于停靠下限的宽度**。停靠下限必须高到外观三按钮在官方设置里仍横向（以架构常量为准）。若官方弹层在下限宽度仍损坏，产品选择是「该宽度不准停靠」，不是继续降到 320px。

## 7. 手动操作与记忆

- 用户可在 xl/lg **拖动**已停靠 AI 的宽度，下限 = 停靠下限，上限 = 在该档留下工作台下限之后的剩余。
- 用户可主动收起 AI（所有档）；收起后会话保持（现有 park 行为）。
- 用户在 xl/lg/md 用侧栏**底栏按钮**折叠或展开菜单；折叠后悬停图标弹出子菜单（不另开抽屉）。仅 sm/xs 顶栏汉堡打开抽屉，关掉后回到该档默认。
- 宽度偏好按登录用户保存，但 **不得覆盖档位强制结构**（例如 md 强制收起停靠时，不能因偏好 480px 而再次停靠一条低于下限的栏）。
