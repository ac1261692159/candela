# PRD：指标 v2 —— 与事件分析同深度的口径 + 查询时间 + 取值选择

- `phase: clklog-analytics-metric-v2`
- 关联：`docs/architecture/clklog-analytics-design-metric-v2.md`（实现契约）、`prd-clklog-analytics-metric-detail-v1.md`（上一期：查看与就地编辑）、`prd-clklog-analytics-alerting-v4.md`（指标告警）、`docs/product/guide-clklog-analytics-alert-channels-v1.md`
- 上一期已上线（17237）：指标的**查看**与**部分编辑**（显示名/格式/备注/事件/计算方法/属性），筛选条件保持只读

## 1. 背景与问题

指标现在只能存「事件 + 计算方法 + 属性」这一层，用户反馈三点（2026-09-16）：

1. **口径太薄**：事件分析页的指标卡有「事件 / 属性 / 计算方法（17 种，含分位数）/ 数值变换（乘系数、保留小数位）/ 阶段总和 / 条件组（事件属性、用户属性、分群、标签）」，而指标编辑器只有前三个字段；
2. **详细度不一致**：用户要求「和事件分析步骤一样详细」——同一套配置在两个入口能力不同，导致「分析里能做的口径，存不成指标」；
3. **缺少查询时间与取值选择**：指标没有自己的时间范围，时间范围由**告警规则**的窗口（今天 / 近 2 / 7 / 30 天）决定；也没有「窗口内怎么取一个数」（累计 / 日均 / 最大 / 最新一天…）的表达能力。

另外，上一期实现里有两处**保真缺陷**（实测确认，不是新需求）：

- 保存指标时后端按白名单重建定义，`transform`（数值变换）与 `stage_reduce`（阶段总和）**被静默丢弃**——分析页看到的数（乘过系数 / 按日均归并）与指标实际值可能不一致；
- 编辑事件指标时只覆盖三个字段，`filters` 保留在定义里但界面不可见、不可改。

结果：指标「看起来是一个可复用的度量」，实际只固化了口径的一小部分，且与告警窗口耦合在一起——同一条指标换规则就要重配时间范围。

## 2. 目标与范围

**要做（P0 / P1）**

| 优先级 | 内容 |
|---|---|
| P0 | 指标定义**保真**：分析页指标卡的全部字段（含数值变换、阶段总和、条件组、分位数、别名、分析主体）保存即保留、应用即还原，前后端 round-trip 一致 |
| P0 | 指标编辑器升级为**与事件分析同深度**的步骤化表单（见 §4.1），条件组可增删改（不再是只读） |
| P1 | 新增**查询时间**：指标自带相对时间范围（今天 / 昨天 / 近 N 天 / 本周 / 上周 / 本月 / 上月 / 自定义相对区间），上限 90 天 |
| P1 | 新增**取值选择**：把窗口内的日序列归并成一个值时用哪种口径（累计 / 日均 / 最大值 / 最小值 / 最新一天 / 首日 / 整段去重合计 / 加权平均） |
| P1 | **试算预览**：编辑器内可直接求值（当前值 + 最近一段日序列 + 归并说明 + 耗时），保存前先看见数 |
| P1 | 指标列表补「查询时间 · 取值」摘要；支持**直接新建**事件指标（不必先去分析页配一遍） |
| P1 | 告警联动：新建/编辑指标告警时明确显示「时间范围：跟随指标（近 7 天）」；规则仍可覆盖为自定义窗口 |

**P2（本期只留接口与字段，不做界面）**：留存指标的查询时间（队列范围）、看板卡片直接以指标为数据源。

## 3. 用户故事

- 作为分析同学，我把分析页配好的指标保存为「指标」后，希望它**完整保留**我设的筛选、数值变换与归并口径，别只留事件和计算方法。
- 作为运维同学，我想把「近 7 天日均下单金额」做成一个指标，让告警只判断「低于阈值」——时间范围和取值口径应该属于**指标**，不属于每一条规则。
- 作为指标维护者，我改了指标的筛选条件后，希望**告警和卡片自动跟着变**（同一口径），而不是各自维护。
- 作为指标维护者，我保存前想先**试算**看一眼当前值，避免保存完才发现事件选错。

## 4. 界面规格

### 4.1 指标详情 / 编辑抽屉（事件指标）

抽屉头部保留现状（指标名、类型、创建人、创建/更新时间、取消/保存）。编辑区按**事件分析同一顺序**分区，每区一行标题 + 一行主控件：

| 区 | 字段 | 控件与默认 | 说明 |
|---|---|---|---|
| ① 基本信息 | 显示名 / 格式 / 备注 | 现状不变（必填、number\|percent、200 字） | 指标名只读 |
| ② 分析主体 | 分析主体 | `SubjectSelect`，默认「跟随分析主体（用户）」 | 保真保存 `subject_id` |
| ③ 事件 | 事件 | 可搜索选择（与事件分析同一数据源，含虚拟事件） | 必填 |
| ④ 属性 | 属性 | 可搜索；方法不需要属性时置灰并提示「当前方法不需要属性」 | 选项按事件属性 + 用户属性分组，标注数据类型 |
| ⑤ 计算方法 | 计算方法 | 全量 17 种；选「分位数」时出现预设（P25/中位数/P75/P90/P99/自定义 0–100） | 选项按属性数据类型过滤（沿用 `methodsForDataType`） |
| ⑥ 数值变换 | 乘以系数 / 保留小数位 | 可空；两列并排 | 先乘系数，再保留小数位（与卡片一致） |
| ⑦ 取值选择 | 取值方式 | 默认「自动（按计算方法推荐）」；展开后可选具体值（见 §5） | 选具体值时旁边显示该方法的**推荐值**与「不可加方法」提示 |
| ⑧ 查询时间 | 时间范围 | 默认「近 7 天」；可选今天/昨天/近 N 天(1–90)/本周/上周/本月/上月/自定义相对区间(起止偏移 −366~0) | 只允许**相对**范围（指标要能每天循环求值） |
| ⑨ 条件组 | 事件属性 / 用户属性 / 分群 / 标签 | 复用 `FilterEditor`；AND/OR 可嵌套；最多 5 组 / 50 条 | 与事件分析卡片的「条件组」同语义 |
| ⑩ 试算 | （底部） | 「试算」按钮 → 显示当前值、单位/格式化的值、日序列迷你条、归并说明、耗时 | 保存前提示：未试算时保存给一次确认提示（不阻断） |

- 只读字段（指标名、类型）用与现在一致的灰底展示。
- 任何字段变更后**未保存**离开时二次确认。
- 校验错误就地红字（不弹 toast），错误文案见 §7。

### 4.2 指标列表

- 现有列：显示名 / 指标名 / 类型；新增**摘要素述**：`查询时间 · 取值`（例：`近 7 天 · 日均`），放在显示名下的小字行（与事件分析卡片摘要同一排版）。
- 行操作：查看 / 编辑 / **应用到分析** / 删除（现状）+ 顶部**新建指标**（仅事件指标，留存指标仍从留存分析保存）。

### 4.3 从事件分析保存为指标的保真规则

- 「保存为指标」保存当前卡片**完整字段**（见 §2 表），并记录保存时的分析主体与时间范围作为指标默认查询时间；
- 「应用到分析」把指标定义**原样**填回卡片，包括筛选、数值变换、取值（映射为卡片的「阶段总和」）、分析主体；若指标使用了卡片不支持的取值（首日/最新一天），提示「已按等价方式应用：仅影响告警/卡片展示，分析页按日序列展示」。Hmm，这句要简单：**提示该取值仅在指标求值时生效**。

### 4.4 告警联动

- 「新建指标告警」抽屉的「时间范围」默认显示为**跟随指标**（只读展示指标当前查询时间，如「近 7 天」），并提供「由本规则指定」单选以覆盖（保留现有 1/2/7/30 天选项）；
- 既有规则（2026-09-16 之前创建）行为**不变**：继续用规则自身窗口，编辑时才看到「跟随指标」新选项。

## 5. 取值选择（把窗口归并成一个值）

| 取值 | 语义 | 适用 | 备注 |
|---|---|---|---|
| 自动（推荐默认） | 按计算方法推导（下表） | 全部 | 现状行为，保证兼容 |
| 累计 | 窗口内各日值相加 | 可加方法（总次数、总和、为真/为假数…） | 与「阶段总和」同义 |
| 日均 | 各日值的算术平均 | 可加/均值类 | 告警更稳（不被窗口天数放大） |
| 最大值 / 最小值 | 各日极值 | 全部 | 常用于「峰值是否越线」 |
| 最新一天 | 窗口最后一天的值 | 全部 | 用于「今天到目前的绝对值」 |
| 首日 | 窗口第一天的值 | 全部 | 用于「窗口起点的水平」 |
| 整段去重合计 | 用整段时间**整体**求值（不是按日相加） | 触发用户数、去重数、列表去重 | 唯一正确取值，选别的会给出警告 |
| 加权平均 | 按分母加权（人均次数/人均值/均值） | 人均类、均值 | 唯一正确取值，同上 |

默认推导（沿用引擎既有规则）：触发用户数/去重类 → 整段去重合计；人均/均值 → 加权平均；最大 / 最小 → 对应极值；分位数/方差/标准差 → 日均；其余 → 累计。

## 6. 查询时间

- 选项：今天、昨天、近 N 天（N=1–90，默认 7）、本周、上周、本月、上月、自定义相对区间（`from_date_to_yesterday` / `custom_offsets`，偏移 0 ~ −366）。
- **只允许相对范围**：指标要能每天循环求值，绝对日期会让指标「过期」。
- 上限 90 天（与自定义 SQL 页同口径），超限保存报错；告警推荐的窗口（今天~近 30 天）仍在范围内。
- 与规则窗口的关系：指标的查询时间是**默认来源**；规则可覆盖（§4.4）。求值时以「规则覆盖 > 指标」为准，试算与告警使用同一份解析逻辑。

## 7. 验收标准

| # | 断言 |
|---|---|
| AC-1 | 分析页配置「事件 + 属性 + 求和 + 乘系数 0.01 + 保留 2 位 + 条件组 2 条 + 阶段总和=日均」→ 保存为指标 → 重新打开，**九个字段逐项一致**（含 transform 与取值） |
| AC-2 | 同一指标「应用到分析」后，卡片字段与原配置逐项一致（含 filters、transform、stage_reduce） |
| AC-3 | 指标编辑器可新增/修改/删除条件组（AND/OR 嵌套），保存后 `definition_json.metric.filters` 与界面一致 |
| AC-4 | 查询时间选「近 7 天」保存后，`GET /sa/api/meta/metrics/:id` 返回 `time_range.relative.kind=past_n, n=7`；选 91 天返回 400 且提示上限 90 |
| AC-5 | 取值选「最新一天」时试算值与「日序列最后一个非空值」一致；选「累计」时等于各日之和（用固定 fixture 断言） |
| AC-6 | 对「触发用户数」这类不可加方法选「累计」时，界面给警告，且求值仍用整段值（不出现「每日人数相加」的错误结果） |
| AC-7 | 试算接口返回 `{value, value_fmt, series[], reduce, elapsed_ms}`；同一指标、同一时间的试算值与告警 `probe` 值**完全一致**（交叉验证用例） |
| AC-8 | 编辑指标不出现「静默丢字段」：保存未修改的指标后 `definition_json` 与保存前**逐字节等价**（除 updated_at 相关） |
| AC-9 | 告警新建抽屉默认「跟随指标」，展示的窗口文案与指标查询时间一致；切到「由本规则指定」时保存 `window_days` 并照旧求值 |
| AC-10 | 既有规则（迁移前创建）不改任何字段时，告警值、触发/恢复行为与迁移前一致（回归用例 + 线上对拍一条规则） |
| AC-11 | 指标列表摘要显示「查询时间 · 取值」，与详情一致 |
| AC-12 | 指标定义变更写审计（`alert_metric_update`，含改动的字段），变更记录可见 |

## 8. 非目标

- 不做**公式指标**（`kind=formula`）的持久化与告警（公式仍只在分析页/卡片内使用）；
- 不做**分组维度指标**（指标仍是单一数值，不带维度拆分）；
- 不做留存指标编辑器的步骤化改造（本期仅保留其查询时间接口位，界面在 P2）；
- 不做指标的权限/共享/血缘图；
- 不改变指标的存储表结构（仍 `metasavedmetric.definition_json`），不改指标名/类型只读的既有约束；
- 不引入绝对时间范围的指标（见 §6）。
