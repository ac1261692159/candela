## 1. 阶段目标与范围（门禁要素①）

把「数据管理 → 接入指南」从**示例索引页**改为**自包含接入文档站**：用户在平台内即可读到完整的接入步骤、代码与验证方法，不需要去翻仓库目录。

范围：

1. **页面结构**：接入参数（项目名 / 上报地址 / token 说明）+ 三组 SDK 入口（客户端 / 服务端 / 其他接入），入口数量对齐同类产品（数数 ThinkingData 文档站的 SDK 列表量级）。
2. **文档自包含**：已实测的 SDK（PHP、Golang、Unity-C#）以及通用 HTTP 协议条目，在页面内直接写清楚：前置条件 → 依赖 → 初始化 → 上报事件 → 用户关联 → 批量与重试 → 验证方法 → 常见问题，**不出现 `examples/report-sdk/` 之类的仓库路径**。
3. **未开发条目**：尚未适配的 SDK 只保留入口，点击明确提示「暂未开发」，不展示任何伪代码或占位文档。
4. **协议真相引用**：上报地址、表单字段、编码规则以仓库《数据上报规范与流程》为准；页面只展示本项目当前可用的地址与参数，token 不在页面展示。

## 2. 验收标准（门禁要素②）

- [x] **O-1**：页面含三组入口（客户端 SDK / 服务端 SDK / 其他接入），客户端 ≥9 个、服务端 ≥9 个条目，全部渲染为可点击入口。
- [x] **O-2**：已实测条目（PHP、Golang、Unity-C#）与通用 HTTP 协议条目，点击后打开文档抽屉，含**不少于 5 个步骤**且**每份文档至少 2 段可复制代码**。
- [x] **O-3**：未开发条目点击后显示「暂未开发」，且**不展示**步骤、代码或指向仓库的路径。
- [x] **O-4**：全页面（含文档正文）**不含** `examples/`、`.env`、仓库文件路径引用；有自动化断言防止回归。
- [x] **O-5**：文档正文包含编码要求（JSON 数组 → base64 → urlencode）、三要素字段（project/token/data）、时间戳单位（毫秒）、登录关联口径（`identities.user_key` + `$track_signup_original_id`）。
- [x] **O-6**：文档正文包含验证方法（平台内 Debug 查询 / 查库两种），并含常见问题（HTTP 200 但无数据、直接 POST JSON、单条事件也要数组）。
- [x] **O-7**：页面任何位置的 token 均不显示真实值（只说明获取方式）。
- [x] **O-8**：前端单测覆盖「已实测条目结构完整」「未开发条目无文档」「正文无仓库路径引用」三条断言，并纳入 CI。

## 3. 非目标（门禁要素③）

- 不实现任何新 SDK 采集端代码（本期只做文档与入口；Android/iOS/Java 等仍是「暂未开发」）。
- 不引入 markdown 渲染库或文档后台（内容为前端自带的结构化常量，随版本发布）。
- 不做多版本文档切换、搜索、国际化。
- 不改上报协议本身，也不改 receiver/nginx（红线 1）。
- 不在页面内展示项目 token（也不提供「一键获取 token」接口）。

## 4. 页面形态

```
数据管理 · 接入指南
├── 接入参数卡：项目名称 / App_ID(=项目名) / 上报地址（可复制）/ token 获取方式
├── 接入前置说明：协议三要素 + 编码要求（含编码示例）+ 最常见的坑
├── 客户端 SDK：Android iOS JavaScript/Web 微信小程序 Unity(C#)* Flutter React Native Cocos2d-x Unreal Engine
├── 服务端 SDK：Java Python PHP* Go* Node.js C# Ruby C Lua
└── 其他接入：HTTP / RESTful API（通用）* 批量回补（文件导入）
    * = 本期已实测，可打开完整文档
```

点击已实测条目 → 右侧抽屉（宽 ~760）文档；点击未开发条目 → 「暂未开发」提示（Modal 或 Alert），文案说明「该 SDK 尚未适配 ClkLog 上报协议，可先用通用 HTTP 协议接入」。

## 5. 文档要素（每份已实测文档必须满足）

| 段落 | 要求 |
|------|------|
| 适用场景 | 一句话说明该语言/引擎的典型用途与前置条件（运行时版本、依赖） |
| 接入参数 | 该语言下 endpoint / project / token 的注入方式（环境变量或配置），token 不写死 |
| 初始化 | 客户端类/函数的构造方式与参数含义 |
| 上报事件 | 行为事件字段表 + 代码块 |
| 用户关联 | 登录关联（track_signup）与身份口径 + 代码块 |
| 用户属性 | `user_set` 用法 + 代码块 |
| 批量与重试 | 批量大小、失败重试策略、退出前 flush |
| 验证 | 平台内查询（Debug）与查库校验，含预期结果 |
| 常见问题 | 至少 3 条，含「HTTP 200 无数据」「时间戳单位」「单条也要数组」 |

## 6. 与其它文档的关系

- 协议细节以《数据上报规范与流程》为 SSOT；本页文档是**面向接入者的精简版**，不含协议之外的新约定。
- 本 PRD 不改变「埋点管理」的资产模型，页面上出现的项目名来自当前项目上下文。
