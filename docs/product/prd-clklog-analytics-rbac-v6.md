# PRD：授权弹层可用性与成员视角的看板授权（phase: clklog-analytics-rbac-v6）

> phase: clklog-analytics-rbac-v6
> 上游：`prd-clklog-analytics-rbac-v5.md`（看板默认可见范围与成员组授权）
> 下游：`docs/architecture/clklog-analytics-design-rbac-v6.md`
> 触发：v5 验收反馈——授权弹层两个选择器语义不对等、选项是平铺枚举难以查找；更关键的是**只能从看板侧授权**，要查「某个成员/组能看到哪些看板」必须把每块看板逐个打开。

---

## 1. 背景与问题（2026-09-18 验收实测）

1. **第一个授权栏目没有说明**：弹层里「可编辑」选择器只有一句 placeholder（选择本项目分析师或分析师组），没有像「可查看（成员组或成员）」那样的标签；使用者看不出这一栏是什么。
2. **选项是平铺枚举**：成员与成员组混在一个长列表里，没有分组、不能筛选、选中态是行尾的 ✓ 而不是复选框；选项多时下拉被内容撑长。
3. **授权只能从资产侧发起**（v5 的口径）：`saAssetAcl` 是「资产 × 主体」的行，管理界面却只有看板/文件夹侧的入口。要回答「胡正坤能看哪些看板」「普通成员组被授过哪些看板」这类问题，只能把每块看板逐个打开看——看板一多就不可操作。

---

## 2. 阶段目标与范围

1. **授权弹层可用性**：两个授权栏都带标签；每栏改为**左右双栏**（左「未添加」/ 右「已添加」），左栏顶部用**标签页**切换「成员组 / 成员」两个类别；两栏各自支持按名字筛选、**固定高度内部滚动**；点左栏项加入、点右栏项移出；弹层尺寸固定，不随成员数量变化。（2026-09-19 验收追加：多选下拉在成员上百时无法核对，改为双栏。）
2. **成员视角的看板授权**：成员管理、成员组的行内新增「看板授权」入口（仅 `asset.grant` 持有者可见，即项目 owner 与分析管理员），弹层内按「文件夹 / 看板」列出全部资产，勾选即授「可查看」，支持筛选与批量（勾文件夹 = 覆盖其内全部看板）。
3. **编辑授权蕴含可见**：v5 收回分析师的 `dashboard.view_all` 后，只被授「可编辑」的资产在看板列表里不可见（`view` 与 `edit` 是两条独立 ACL 行）。本期起 `edit` 授权一律蕴含可见，保证「能改的就能看到」。

---

## 3. 验收标准

- [ ] **RB6-1 标签对等**：授权弹层两个选择器都有明确标签——「可编辑（分析师或分析师组）」「可查看（成员组或成员）」，placeholder 不再承担唯一说明职责。
- [ ] **RB6-2 双栏与标签页**：每个授权栏为左右两栏——左「未添加」、右「已添加」，并各显示条数；左栏顶部有「成员组 / 成员」两个标签页，切换后只显示该类别。
- [ ] **RB6-3 点选移动**：点左栏项即加入右栏、点右栏项即移回左栏；初始已授权的对象出现在右栏。
- [ ] **RB6-4 固定尺寸与筛选**：两栏列表高度固定、超出滚动；两栏均可按名字筛选（组名、成员显示名/用户名）；弹层尺寸不随成员或选中数量变化。
- [ ] **RB6-5 成员视角授权**：成员管理与成员组的行内出现「看板授权」（owner / 分析管理员可见）；弹层列出项目全部文件夹与看板，可筛选、可勾选、可保存；保存后该成员/组立即能在看板列表看到被授权的看板。
- [ ] **RB6-6 反向可查**：打开某个成员的「看板授权」，能直接看到它当前被授过哪些文件夹/看板（含由他人从资产侧授予的），不需要再逐个看板翻查。
- [ ] **RB6-7 只授不撤他人**：在成员视角保存时，只增删该主体自己的 ACL 行，其他主体在同一资产上的授权不受影响。
- [ ] **RB6-8 文件夹批量**：勾选一个文件夹即覆盖其内全部看板（含子文件夹与之后新建的），看板列表里随之可见。
- [ ] **RB6-9 编辑蕴含可见**：只被授「可编辑」的分析师能在看板列表看到该看板（此前必须额外被授「可查看」）。
- [ ] **RB6-10 文案与门禁**：新增文案 13 门语言齐备；`arch_ratchet` / `i18n_check` / `i18n_scan` / jest / vitest / 两端 `tsc` 全绿。

---

## 4. 非目标

1. **不在成员视角做「可编辑」授权**：编辑授权与锁定/编辑权模型绑定（只能给分析师），仍在资产侧维护；成员视角里这类资产以「可编辑」只读标记呈现，不提供勾选。
2. **不做成员视角的批量重置/导出**（如「导出某成员的授权清单」）。
3. **不改 ACL 数据模型**：仍是「资产 × 主体 × perm」的行；成员视角只是同一批数据的另一个编辑面。
4. **不改 v5 的默认可见口径**（owner / 分析管理员全量，其余靠授权）。
5. **不改卡片 / 分群的授权模型**（本期只服务看板与文件夹）。

---

## 5. 界面影响

| 界面 | 变化 |
|---|---|
| 看板/文件夹授权弹层 | 两个授权栏加标签，改为「未添加 / 已添加」双栏 + 类别标签页 + 筛选 + 固定尺寸内部滚动 |
| 成员管理 · 行内 | 新增「看板授权」按钮（`asset.grant`） |
| 成员组 · 行内 | 新增「看板授权」按钮（`asset.grant`） |
| 成员视角授权弹层 | 新增：筛选框 + 固定高度滚动区（文件夹区 / 看板区）+ 保存 |

---

## 6. 风险

- **误删他人授权**：成员视角保存若按「整表覆盖」实现，会把其他主体在同一资产上的行删掉。对策：只对本主体做增删（RB6-7 用单测锁死）。
- **授权面扩大**：入口只对 `asset.grant` 持有者（owner / 分析管理员）出现；接口同样用该码把守，前端隐藏不作为安全边界。
- **「可编辑」与「可查看」的语义重叠**：本期约定 edit ⇒ 可见；成员视角对被授编辑权的资产只读展示，避免出现「勾掉可查看但还能看见」的困惑。
- **入口位置**：成员页与成员组页此前是纯成员管理，新增授权入口后要避免与「添加成员 / 移出」混淆——按钮文案统一叫「看板授权」，且只在有码时出现。

---

## 7. 发布说明

- 授权弹层更好用了：分组、可搜、复选框、尺寸固定。
- 新增反查入口：成员管理 / 成员组行内「看板授权」，可直接看到并调整该成员/组能看哪些看板（勾文件夹即批量）。
- 被授「可编辑」的分析师现在能直接在看板列表看到该看板（不必再单独授「可查看」）。
- 无数据迁移、无需重新登录。
