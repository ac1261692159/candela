## 2. 事件分析（已调研）

### 2.1 指标构成

数数：一条指标 = **事件** + **属性（可选）** + **计算方法**；或 **公式**（指标间四则运算）。截图里 `新用户任务.触发用户数` 即「事件.计算方法」；旁侧 Σ 为公式。

我们：一条指标 = **事件** + **type**（`count` / `uniq_user` / `agg` / `per_user`）+ 可选 `func`/`prop`。选择器把「人均次数」和「属性聚合」拆成独立 type，且 `per_user` 还会再要一个属性，和数数不一致。

实现锚点：`apps/analytics-web/src/components/MetricEditor.tsx`；DSL `MetricType` / `AggFunc` 在前后端 `dsl.types.ts`；SQL 在 `event-sql-generator.service.ts`。

### 2.2 不选属性时的预置方法

| 计算方法 | 口径 | 神策 | 数数 | 我们 |
|----------|------|:----:|:----:|------|
| 总次数 | `count()` | 有 | 有 | 有，文案「触发次数」 |
| 触发用户数 | 分析主体去重 | 有 | 有 | 有，文案「独立用户数」 |
| 人均次数 | 总次数 / 触发用户数 | 有 | 有 | SQL 能算；UI 仍走 `per_user` 且常要选属性 |
| 任意事件 | 不限制 event 名 | 有 | 有 | 无 |
| 预定义（过去 7/30 天、当月次数/人数） | 按事件日或查询窗滚动 | 有 | 少见 | 无 |

### 2.3 数值属性（时长落在这一层）

`$event_duration`（秒）在神策/数数是普通 Number。总时长 = 总和，次均时长 = 均值，人均时长 = **人均值**。

| 计算方法 | 口径 | 神策 | 数数 | 我们 |
|----------|------|:----:|:----:|------|
| 总和 | `sum(prop)` | 有 | 有 | 有（`agg`+`sum`） |
| 均值 | `sum/次数` | 有 | 有 | 有 |
| 最大值 / 最小值 | max / min | 有 | 有 | 有 |
| **人均值** | `sum(prop)/触发用户数` | 有（`uniqavg`） | 有 | **无**（人均时长缺口） |
| 去重数 | uniq(prop) | 有 | 有 | 有 |
| 中位数 | P50 | 有 | 有 | 有（`p50`） |
| P25 / P75 | 四分位 | 有 | 有 | 无 |
| P90 | | 有 | 有 | 有 |
| P99 / 其它分位（95/80/…） | | 神策 API 到 P90 | 数数分位很密 | 仅 P99 |
| 方差 / 标准差 | | 报表侧常见 | 事件分析内有 | 无 |

我们已采集 `$event_duration`（`docs/architecture/reporting-protocol.md`），分析侧没有时长专用入口，也没有把结果格式化成秒/分钟（`duration_sec` 只在 SQL 图）。

### 2.4 按属性类型的其它方法

| 类型 | 神策 | 数数 | 我们 |
|------|------|------|------|
| 任意类型 | 去重数 | 去重数 | 仅 `agg`+`uniq`，不按类型收窄选项 |
| 布尔 | 弱 | 为真数 / 为假数 / 为空数 / 不为空数 | 无 |
| 列表 | 弱 | 列表去重数 / 集合去重数 / 元素去重数 | 无 |
| 时间类型当**指标** | 计数或去重，不求和 | 同左 | 未按类型限制，选了 sum 会算错 |
| 时间类型当**分组** | 分/时/天/周/月；还可「按时段汇总」（每月几号、每小时几分） | 类似 | 只有时/天/周/月 |

### 2.5 公式、分析主体、指标个数

| 能力 | 神策 | 数数 | 我们 |
|------|:----:|:----:|------|
| Σ 公式（加减乘除、括号、常量） | 有 | 有 | 无 |
| 公式展示：百分比 / 小数位 | 有 | 有 | 无 |
| 切换分析主体（设备 / 账号等） | 有 | 有（影响人数、人均次数、人均值） | 无，固定 `if(user_key!='',user_key,distinct_id)` |
| 同时分析的指标个数 | 远大于 3 | 远大于 3 | 前端硬顶 **3**（`MAX_METRICS`） |

### 2.6 时间范围、粒度、对比

| 能力 | 神策 | 数数 | 我们 |
|------|------|------|------|
| 查询窗 | 静态/动态日期 | 有 | 静态/动态（数数口径：过去 N / 最近 N；见 phase `clklog-analytics-time-range-v1`） |
| 时间粒度 | 分/时/天/周/月（分有 1 天上限） | 合计、1/5/10 分、时、天、周、月、季、年 | 时/天/周/月；无「合计」、无分钟、无季/年 |
| 时间对比（上期 / 去年同期 / 自定义） | 有 | 有 | DSL 类型里留过口，M3 非目标，UI 未做 |
| 筛选「事件发生时间」按时段（0–23 时） | 有 | 常见 | 无 |

### 2.7 阶段汇总与结果展示

数数在粒度不是「合计」时，给每个指标做阶段汇总，可选：阶段总和、阶段均值、加权平均、最大、最小、**合计**（跨日再去重，贵）。

神策有快速总和 vs 精准合计。

我们：有时间分组时各桶各算；没有阶段汇总配置，合计行不是「人数跨日去重」。

图表：双方都有趋势/柱/表。数数还有累计图（只适合次数/总和）。我们有折线/柱/饼/数值卡/表，无累计图、无主次轴。

### 2.8 事件分析结论（改造输入）

靠拢数数，事件分析缺口按影响排序：

1. 人均值、人均次数选择器与口径  
2. 按属性类型展开计算方法（含布尔/列表）  
3. 任意事件  
4. 公式 Σ  
5. 指标个数上限  
6. 阶段汇总（尤其合计去重、加权平均）  
7. 分钟粒度与时间属性「按时段汇总」  
8. 分析主体  
9. 时长展示（`$event_duration` → 秒/分）  
10. 预定义滚动窗口指标、累计图、主次轴  

Session / 间隔 / 漏斗转化时长 **不是**事件分析计算方法，不进事件分析改造；等 §6–§7 调研。

## 10. 权限管理（已调研）

产品模型与我们怎么做见 `docs/product/research-clklog-analytics-rbac.md`、`docs/product/prd-clklog-analytics-rbac-v2.md`。本章只记对标事实。

主对标本模块改成 **神策**（用户提供了角色管理截图与五角色全表）。数数同构（超管 / 项目 owner / 管理员 / 分析师 / 成员 + 数据权限 + 成员组），公开手册粒度比神策这张表粗，不作为改造目标。

用户对我们分析师的基线比神策**更严**：整块埋点管理都没有（选择器仍能用已启用事件）。比神策**更宽**：有 SQL；分群不限于结果分群。

#### 普通成员（神策）

看板查看（含演示、临时筛选、导出 PDF）+ 探索。无分析模型、无用户、无元数据。

我们 P1 `viewer`：只读**自己的**资产，且菜单仍露出分析/埋点（后端查询类三角色均可）。和「只看看板」不一致。

#### 外部人员（神策）

模型：仅下载/导出模型数据。看板：查看与导出 PDF，**无**临时筛选。无探索。

我们：无此角色。

### 10.5 我们相对神策要补的（已写入 v2 方案，尚未实现）

1. 平台超管 / 项目角色拆开；每项目 1 owner。

## 11. 数据表 / 维度表（已调研）

产品模型与我们怎么做见 `docs/product/research-clklog-analytics-dimension-table.md`。本章只记对标事实。

两家同构：**上传 Excel/CSV 建表 → 定主键 → 绑到一个属性上 → 表内非主键字段变成可筛选/可分组的新属性**。差别在落地形态：

| 能力 | 神策 | 数数 | 我们 |
|------|:----:|:----:|:----:|
| 建表（上传/表单/SQL） | 三种，含视图表 | 上传 + 数据表 API | **无** |
| 主键 | 主键表/非主键表/视图表；联合主键 ≤3；非主键表需分区字段 | 首列即主键、单主键、类型不可改、重复值取最小行号 | 无 |
| 生成物 | **虚拟属性**（引用 `别名.字段`，自动批量建需 SDH≥1.3.1） | **维度表属性**（命名 `#事件属性@字段`） | 有虚拟属性，无维度表属性 |
| 轻量值映射（属性值→映射值） | **维度字典**（文本/数值属性，可 API 增量上传） | 无对应物 | 无（`MetaPropertyDict` 是空壳） |
| 关联条件 | 两侧类型一致；主键/唯一键必须参与且不可删；右值可为**固定值** | 主键类型决定可关联属性类型（文本→文本/列表/时间） | 无 |
| 更新 | 追加（主键 upsert）/替换；数据同步任务导入；上传更新需 SDH≥1.3.1 | 增量/替换；**结构变更需发布生效** | 无 |
| 删除 | **血缘判断，有依赖禁止删** | **级联删维表属性**；版本还原不含关联关系 | 无 |
| 表级权限 | 查看/管理数据表（范围）**+ 表数据权限**（影响自定义查询与数据同步） | 元数据查看/编辑按角色 | RBAC v2 无表级粒度 |
| 前端入口 | 数据表管理 + 元数据「维度表」 | 数据表列表 + 「配置关联属性」弹窗 | **无** |

我们现状：属性取数是「物化列优先 / 否则 `JSONExtract`」，已有一条用户属性标量子查询 JOIN；**没有任何上传建表、维表 JOIN 或 ClickHouse Dictionary**，且 SQL 守卫白名单只允许 `sa_events`/`sa_user_profiles`，外部表 JOIN 目前被安全策略主动挡住。缺口排序与红线冲突见专文 §7、§8（先补维度字典、再评估表级扩展）。
