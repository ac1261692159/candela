## 1. 阶段目标与范围

按顺序补三块，都落在分析工作台（事件 / 漏斗 / 留存）：

1. **任意事件**：留存初始/回访、漏斗每步可选「任意事件」（事件分析已有）。SQL 不写该步 `event =`，仍有项目与时间窗。
2. **创建指标**：把当前事件指标或留存切片存进项目指标库，之后可套用，不必每次重配。不是再存一张看板卡片。
3. **虚拟事件 / 虚拟属性**：三个分析的事件搜索能命中虚拟事件；选中虚拟事件后，筛选/分组/指标属性能用来源事件上的普通属性与虚拟属性。

## 2. 验收标准

- [ ] AC-1：留存初始、回访事件下拉里有「任意事件」；选中后提示可能较慢。查询 SQL 无对应 `event =`，仍有 `project_name` 与时间。两边都任意时不再 `event IN (...)`。
- [ ] AC-2：漏斗每步可选「任意事件」；该步条件不限制事件名；任一步为任意时漏斗扫描不再 `event IN`。
- [ ] AC-3：埋点管理有「指标」页。事件分析结果可「创建指标」（选一条非公式指标）。留存结果可「创建指标」（选 N + 留存率或留存人数）。标识小写字母开头、字母数字下划线、≤80。同项目标识唯一。
- [ ] AC-4：事件分析可「从指标添加」套用事件类指标。留存可「套用指标」填回初始/回访/口径/周期。时间范围不随指标冻结，用当前查询窗。
- [ ] AC-5：事件下拉合并可见虚拟事件，标签带「虚拟」。搜索打到显示名、`ve_` id、来源事件名。默认列表不被近 7 日次数挤掉。
- [ ] AC-6：选中虚拟事件后，属性下拉含来源事件属性并集 + 绑在这些事件或全局的虚拟属性（带「虚拟」）。
- [ ] AC-7：单测覆盖任意事件 SQL、指标标识校验、虚拟事件选项合并。棘轮通过。

## 3. 非目标

- 不做漏斗创建指标。
- 不做指标进公式跨查询引用、告警、神策预定义滚动窗口指标。
- 不改分析主体。
- 不把指标查询结果做成新的看板卡片类型（套用后仍可「保存为卡片」）。
- 不改虚拟事件定义 schema。

## 4. 体验

- 「任意事件」在下拉顶部。提示 nowrap。
- 「创建指标」在结果区工具条，弹层与现有保存卡片分开。
- 虚拟事件选项带「虚拟」，避免和上报事件混淆。
