## 绝对红线

1. **装不下就换结构，不继续挤。** 禁止靠压窄容器让导航、按钮、分段、步骤标题、**表格单元格**变成一字一列。禁止对这些元素使用 `word-break: break-all` / `overflow-wrap: anywhere`。
2. **一套宽度判决。** 壳层（导航 / 主任务 / 辅助侧栏 / 分栏或堆叠）必须由**一个纯函数**根据 visual viewport 算出；禁止各页面再写一套 `innerWidth < n`、`42vw`、内容区容器查询当主决策。
3. **第三方嵌入 UI 不改内部。** 不注入 iframe CSS、不 fork 官方前端、不自制简化壳冒充原会话。宿主宽度不够该产品的可用下限时，收起或改覆盖层，禁止画一条废侧栏硬塞。
4. **不引入第二套组件库或新字体**来「顺便重做视觉」。新控件先复用项目已有模式。
5. **规格不当事运行时 SSOT。** PRD 写用户看到什么；档位数字只改架构文档与解析器，并保持二者对齐。

触达壳层而没有自动检测时，PR 声明「门禁未自动检：[壳层档位 / 截图清单]」。

## 按需求类型：该怎么做

每条先写触发，再写必须遵循的做法。未满足时停止实现并报告，不得以「先挤一下」「第三方里面再修」绕过。

### 1. 窗口变窄，多栏同时在抢宽度

**碰到：** 同一屏有导航 + 主任务（配置/结果）+ 可选辅助栏（AI、检查器、预览）。

**遵循：**

- 先在架构文档写清**折叠顺序**（通常：先弃导航文字，再弃辅助栏停靠，最后才放弃主任务左右分栏）。解析器必须保证不会出现「主任务已降级、次要栏却仍展开」的自动档。
- 变宽时反向恢复。用户手动展开抽屉不算自动档，但不得让手动态在档位升级后污染更宽档的默认结构。
- 视口用 `visualViewport.width ?? innerWidth`（浏览器缩放按 CSS 像素，不另做一套）。
- 代表宽度做解析器快照测试；折叠顺序用断言锁住。

### 2. 辅助栏要「停靠」，但第三方 UI 有自己的最小宽度

**碰到：** 侧栏里嵌官方套件 / iframe，设置弹层、分段按钮会在过窄时竖排或不可用。

**遵循：**

- 架构里给停靠定**可用下限**。分配宽度 < 下限 → 离开文档流（收起到可点入口或改覆盖层），会话尽量不销毁。
- 夹紧函数输入低于下限时仍返回下限；**调用方必须 undock**，不得用返回值画出更窄的栏。
- persist 的宽度偏好写入前必须经过夹紧。当前档不允许停靠时，忽略「展开停靠」，只保留「用户是否想打开」（走覆盖层）。
- 覆盖层用 `position: fixed`，不占文档流宽度。视口比覆盖下限还窄则 100% 宽，且不承诺第三方弹层完整。
- iframe 在宿主内 `width/height: 100%`。拖拽条做在宿主槽上，不覆盖 iframe；按下并移动超过阈值才改宽度，`setPointerCapture`，避免悬停即拖。

### 3. 中文或短标签被压成竖字

**碰到：** 菜单项、分段芯片（且/或、快捷日期、三选项）、步骤标题、顶栏名称在窄容器里一行一个字。（表格单元格同类问题见第 7 条。）

**遵循：**

- 我们自己的 DOM：横向书写。标题过长 → 单行省略 + `title`/Tooltip。
- 分段空间不够 → **整颗芯片换行**，芯片内 `white-space: nowrap`，宽度随内容（`min-width: max-content` 或等价）。
- 第三方内部无法改字号时，唯一手段是**不要把宿主放到低于其 min-content 的宽度**。若官方弹层在下限仍损坏，产品选择是「该宽度不准停靠」，不是继续降下限。

### 4. 导航有多级子项，空间不够

**碰到：** 分组菜单；窄屏时既要占位又要能选到叶子页。

**遵循：**

- 文档流内的图标栏：**底部保留折叠/展开**，折叠只改变栏宽，不另开第二套入口。
- 折叠后：悬停（或项目约定的等价）弹出子菜单，弹出层挂到 `document.body`（或等价 portal），父级 `overflow` 不得裁切。
- 顶栏汉堡**只在导航完全离开文档流**（抽屉档）时出现。禁止图标栏与顶栏叠两套「打开菜单」。
- 抽屉内必须是带文字的展开菜单，不得把折叠态图标菜单塞进抽屉。

### 5. 「左边配条件、右边看结果」的工作台

**碰到：** 查询构建器、报表、漏斗、表单+预览等主任务。

**遵循：**

- 结果是主视觉。配置轨定宽（架构给默认与上限），结果列 `min-width: 0` 吃剩余。永不把结果压成一条缝。
- 左右分栏 vs 上下堆叠由**壳层档位**决定，禁止用内容区某一魔术宽度的容器查询单独决策。
- 堆叠时配置区限制最大高度并内部滚动，保证结果仍可见、主操作（查询/提交）可滚到。
- 空结果不要占掉半屏：收成工具条，把高度还给编辑器/主画布；有数据后再给结果区默认高度。高度数字在架构里，页面不另造。

### 6. 步骤、分区、列表编号、就地改名

**碰到：** 向导、漏斗步、多指标/多筛选、可命名卡片。

**遵循：**

- 序号只标**同级列表**（第 1 条、第 2 步）。分区标题（「筛选」「时间」「窗口」）不编号。
- 分区用边框/背景区分即可；禁止 Card 套 Card。
- 可折叠的步骤：折叠钮收起内容。名称默认是标题文字；**点击标题**才进入改名，失焦/回车提交，Esc 取消。禁止常驻输入框占一行。
- 筛选/条件行纵向排字段（范围、属性、运算、值），值输入占满行宽。

### 7. 表格 / 数据列表被挤成「每字一行」

**碰到：** 列表页列数多，窄屏下名称、描述、路径这类文本列被挤到一行一个字（中文按字内断行）。

**遵循：**

- 关键文本列**必须显式给宽度**作为最小保证；不设宽度的列会被弹性分配压到数像素宽，这是本问题的根因。
- 文本超长 → 单行截断 + Tooltip 看全文。禁止让单元格换行成竖字，也禁止用 `break-all` 折字。
- 单元格内是「文本 + 标签 / 按钮组」时：文本单独套截断，标签与按钮用**可换行容器**分组，保证窄列下操作与状态不丢失。
- 操作列给宽度并**固定到右侧**，横向滚动时仍可点。
- 整表给**横向滚动兜底**（按列宽总和）：容器装不下就出横滚，而不是继续压缩列宽。
- 已有「宽度 + 截断 + 横滚兜底」的表不重复处理；判断标准只有两条：列有没有宽度、表有没有兜底。
- 同类问题**全局排查**：先扫出所有表格，再按上述模式批量修；不只修报缺陷的那一张。

### 8. 下拉、日期、弹出层在滚动栏里被裁切

**碰到：** 侧栏、配置轨 `overflow: auto` 内的 Select / DatePicker / SubMenu。

**遵循：** 弹出层 portal 到 `document.body`（或页面约定的单一挂载点）。同一产品用同一辅助（如 `getPopupContainer`），禁止每个表单复制一套。

### 9. 用户刚手动改过布局，然后窗口又变了

**碰到：** 用户折叠过导航、拖过侧栏、打开过全屏辅助栏。

**遵循：** 手动选择只在**当前档允许的形态内**有效。档位升级/降级后恢复该档默认结构，不把窄档的全屏辅助栏带到宽档。

### 10. 嵌入页要保活，但不能永远不销毁

**碰到：** iframe / 重型编辑器，折叠或切路由后还想接着聊/接着编。

**遵循：** 离开可视或离开所属功能路由时，可移出视口但保留 DOM。仅在「上下文失效」时重建：切换租户/项目、切换工作区、用户显式重连、退出登录。不要每个路由变化都销毁。

### 11. 新增前端公共代码

**碰到：** 想抽 `utils` / `hooks` / `shared` / `common`。

**遵循：** 与 exec 相同：禁止扩大无领域杂项包。解析器放布局包，弹出层约定放窄模块，页面样式跟功能走。单文件行数上限与目录棘轮跟项目 `AGENTS.md` / exec，越线同一任务内拆分。

## 实现与验证

- 工作范围：`[前端源码目录]`。改壳层先改 `[布局解析器]` + 快照测试，再改消费方。
- 交付前：`[前端 typecheck]`、相关单元测试、项目结构棘轮。UI 必须在浏览器走一遍触发路径（变窄、折叠导航、停靠/覆盖、主任务分栏）；无浏览器时用组件测试并写明未检项。
- 新档位 = 新快照 + 折叠顺序断言仍成立。新的可折叠/可改名步骤 = 测试「折叠隐藏体」和「默认不是输入框」。
- 新增或改动表格 = 按第 7 条自检：关键文本列有宽度、超长有截断、操作列有宽度、整表有横向滚动兜底；同类问题要全局扫过再收尾。
