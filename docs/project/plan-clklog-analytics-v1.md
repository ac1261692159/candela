## 1. 阶段目标与范围（门禁要素①）

本 phase 交付 ClkLog 分析平台 v1，覆盖总体方案的 P0~P3：

| 范围 | 内容 | 对应 PRD |
|------|------|---------|
| P0 数据补齐 | 旁路消费 CKafka → `clklog_sa.sa_events` / `sa_user_profiles`；回灌历史数据 | PRD §2、§5.1 |
| P1 埋点管理 + 事件分析 | 元数据管理、事件分析 DSL 与图表 | PRD §4.1、§4.2、§5.2、§5.3 |
| P2 漏斗 + 留存 | 按人数漏斗、留存表与曲线 | PRD §4.3、§4.4、§5.4、§5.5 |
| P3 自定义报表 | 看板、卡片、自定义 SQL | PRD §4.5、§5.6 |

## 2. 验收标准（门禁要素②）

以 PRD §5 与架构设计 §2 为准：

- [x] P0：A1~A4 全部通过（`sa_events` 与 `log_analysis` 行数一致、自定义属性可查、user_set 生效、ingestor 支持回灌/续传）。
  - 验收时间：2026-07-28；`sa_events` 65 行 = `log_analysis` track 事件 65 行；`count() = count(DISTINCT crc)`。
- [x] P1：B1~B4、C1~C4 全部通过（埋点管理可用、事件分析指标/筛选/分组/性能达标）。
  - 验收时间：2026-07-28；详见 `docs/project/acceptance-clklog-analytics-v1-m2.md`。
- [x] P1.1：M2.1 埋点管理增强（事件类型/昨日量/状态/批量操作）+ 虚拟属性全部通过。
  - 目标日期：2026-08-11；详见 `docs/product/prd-clklog-analytics-v1-m2.1.md`。
- [x] P1.2：M2.2 埋点管理进阶（虚拟事件 OR/全局筛选、事件备注、事件属性面板）全部通过。
  - 目标日期：2026-08-18；详见 `docs/product/prd-clklog-analytics-v1-m2.2.md`。
- [x] P2：M3 事件分析增强 + 漏斗分析全部通过（漏斗语义与神策基准对拍，性能达标）。
  - 目标日期：2026-08-15；验收时间：2026-07-29；详见 `docs/product/prd-clklog-analytics-v1-m3.md` 与 `docs/project/acceptance-clklog-analytics-v1-m3.md`。
- [ ] P3：F1~F3 全部通过（看板卡片、自定义 SQL 安全限额）。
- [ ] 上线：通过 Puppet `puppet agent -t` 一键部署，nginx `/sa/` 路径可达。

## 3. 非目标（门禁要素③）

- 不做 P4 增强功能（按次数漏斗、属性关联、转化时长、分组留存、用户下钻、物化列管理）。
- 不做离线 ID-Mapping 刷数；v1 仅运行时归并。
- 不做留存分析（移到 M4 之后）。
- 不做用户分群、画像、标签、RFM、分布分析、归因分析、Session 分析等后续 phase 功能（放到 M4 之后单独规划）。
- 不做维度表（数据表）上传与关联（放到 M4 之后单独规划）。
- 不改 ClkLog 社区版代码与表结构（红线）。

## 7. 上线顺序与回滚

### 7.1 上线顺序

1. 建库建表（`clklog_sa`、`clklog_sa_meta`）。
2. 部署 ingestor，观察 24h 数据一致性（A1/A2）。
3. 部署 analytics-server + analytics-web，配置 nginx `/sa/`。
4. 埋点管理 + 事件分析灰度开放。
5. M2.1 埋点管理增强 + 虚拟属性灰度开放。
6. 漏斗 + 留存 + 自定义报表逐模块开放。

### 7.2 回滚

- 应用层：移除 `clklog-analytics` 容器与 nginx location 即可回滚。
- 数据层：保留 `clklog_sa` 数据，不删除；如需彻底回滚，手工 DROP（需审计记录）。
