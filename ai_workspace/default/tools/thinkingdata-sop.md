# 分析与数据质量 SOP（ClkLog 适配）

来源：thinkingdata/acquired/SQL_SOP.md 的需求、事件定位、输出与复现流程；tracking_quality_sop.md 的评估维度；p0_experience.md 的缺失与切换排查。迁入日期：2026-09-09。以下是改写后的方法，不继承原文执行指令、旧平台限制、统计结论或阈值。

## 1. 把问题转成可核验口径

先列出目标指标、分子/分母、分析主体、时间/时区、过滤、单位、分组和预期输出。事件名、币种、金额属性、模块属性没有得到当前字典或已核验资产支持时，先列候选再查询，不能凭英文名字确定含义。

例：统计「某活动的代币消耗」时，至少要确认货币种类、消耗流水事件、事件金额属性、活动归因条件。余额属性不是发生额；购买次数不是金额；免费领取不是付费消耗。来源冲突时输出冲突与待确认项，不选择看起来最合理的名字直接计算。

## 2. 事件定位与新旧切换

1. page_read 确认绑定页；capabilities 确认真实参数；先搜索卡片与当前 schema。
2. 历史 module-event-candidates.json 可提供新旧名字，但 `source_migration_status` 不是现网状态。
3. 分别查询新旧事件在同一有限窗口的次数与人数，再按允许的版本/渠道/环境属性定位覆盖；不能因“已改造=是”直接切换。
4. 新旧同名不表示 100% 接管；新旧并存不表示能相加。存在双报时先确认去重机制，不能简单 UNION ALL 或加总后称全量。
5. 新事件零数据、旧事件有数据，只能说明观察窗口内存在覆盖差异；还需区分部署、灰度、上报、环境和映射错误，不能直接断言唯一根因。
6. 前端/后端/原生标记仅供溯源，不决定哪个事件可以直接替代另一个。

## 3. 五项质量核验

| 维度 | 必须区分与记录 |
|---|---|
| 定义存在性 | 当前字典可见 / 字典不可见 / 无权限；字典不可见不自动等于系统没有事件 |
| 活跃性 | 有界日期逐日计数；零数据是窗口内事实，不是事件永远不存在 |
| 突变 | 同星期、发布/活动、数据迟到、版本与渠道变化；输出实际变化值，不迁旧工程固定告警阈值 |
| 新旧覆盖 | 新旧分别统计，核对同名与重复上报；低占比不能单凭阈值认定灰度 |
| 属性完整性 | 元数据定义与真实非空率分开；先确认目标事件属性关系，再查缺失/类型/枚举；JSON 缺键默认 0 不代表真实金额 0 |

质量检查只覆盖当前问题所需字段。不能从“元数据有属性”推出“每条事件都有值”；不需要输出用户身份明细。自动通知、定期全量查询、修改元数据都不在本流程内。

## 4. 选择执行路径

- 事件/漏斗/留存优先使用对应 run 工具；指标按 capabilities 的现代 analysis 字段表达。查询成功后再用同一 DSL 提案填表。
- 严格漏斗必须同主体、时序和窗口。逐事件独立人数称覆盖，不能叫转化漏斗。
- 留存说明 cohort 的真实实现及成熟期；回访观察要覆盖最大 N。现有 all 不是每日重复入组，first_day 不是注册新用户。
- 自定义 SQL 优先复用授权 SQL 卡；无卡时在 SQL 页提出编辑，再确认执行。用户确认编辑不构成执行授权。
- SQL 表/列/函数以 ClkLog 当前字典和只读守卫为准，不把 TA 视图、日期宏、维度表别名或旧 API 参数粘贴进来。
- scope=user 目前被 Harness 拒绝，不修改 scope 伪装支持。无法完整回填的 UI 选项明确说明，不能丢字段。

## 5. 输出与对拍

结果列使用清晰中文含义与已确认单位；率必须注明 0–1 还是百分数。按日人数不能直接累加为全期去重人数。输出结果总行数、裁剪和查询时间；不得把可见前 N 行当全量。

对拍必须对齐事件、时间边界、时区、过滤、主体、数据新鲜度、近似/精确算法。精确计数应一致；金额比较使用约定精度，不照搬旧“允许 5%”阈值。不同口径的数不能硬对齐。

先交付业务结论，再给来源和条件。结果未知、字段缺失、无权限、无数据、参数不支持分别说明。保存脱敏证据，记录 pending/verified/conflict 状态；失败不是零结果。

同参数错误依据契约修正一次后停止该路径；401 交给宿主恢复，不找 token、不循环发送、不重复执行。完整记录使用 evidence-template.md。
